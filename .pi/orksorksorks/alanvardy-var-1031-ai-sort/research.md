## Cross-Cutting Observations

- **`SortOption` is the only user-facing enum whose value changes reminder ordering**; it is `Sendable` and travels as a String `rawValue` across App-Group `UserDefaults` (key `"sortOption"`) and the WCSession applicationContext (payload key `"sortOption"` — `SkippedReminderSyncService.swift:352`) to the watch, which live-re-sorts (`WatchAppViewModel.swift:190-192`).
- **Every persisted value shared with the watch must round-trip through `AppGroup.defaults`** (the `UserDefaults(suiteName:)` suite) — the store types (`SortOptionStore`, `BoolPreferenceStore`) all default to it.
- **The app has no freeform text input UI.** The only freeform-in path is speech dictation → `ReminderDictationParser`; all other text (seeds, fixtures) arrives via launch args or hard-coded fixtures.
- **No on-device AI exists beyond the Speech dictation facility** (`requiresOnDeviceRecognition = true`, `ReminderDictation.swift:134`). No Foundation Models, SiriKit, Core ML, bundled models, or LLM clients anywhere in the repo or manifests.
- **Settings sheets hold no state of their own**: `SettingsBindings` is rebuilt per sheet open; UI state survives close/reopen only via persistence (App-Group store writes, or `@AppStorage` write-backs for standard keys). A "hidden, not lost" rule-text box has **no existing precedent** — the codebase design keeps every control unconditionally visible (documented at `BackgroundSettingsView.swift:5-13`).
- **No conditional control visibility** in the settings sheets; conditional UI exists only at the content level (`ContentView.swift:177`) and for accessibility/UI-test seams.
- Unit-harness shape for any store-level logic: construct `ReminderStore` with `InMemoryEventStore`, `loadsReminders: false`, and explicit reminder/skip/exclude inputs — the pattern every ordering test uses.
- Watch and widget consume ordering but have no sort picker UI; the watch receives the selected option over sync, the widget reads `SortOptionStore().load()` independently.
