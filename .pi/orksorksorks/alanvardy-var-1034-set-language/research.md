# Research Findings

## Q1: End-to-end flow of an Interface preference (appearanceMode / textSize)

### Findings
- Entry: gear button action `settingsBag = makeSettingsBag(); isShowingSettings = true` (`SingleThread/ContentView.swift:183-186`); `settingsSheetContent` renders `SettingsView` via `settingsSheetWritebacks(bag)` (`ContentView.swift:607-612`, macOS min-frame `:614-616`).
- `makeSettingsBag()` (`SingleThread/ContentView+Settings.swift:46-71`): iOS branch seeds `SettingsBindings(appearanceMode: appearanceMode, textSize: textSize, ...)` from the `@AppStorage` properties (`:48-60`); macOS branch passes the same plus `enableActionButtons`, `showMicrophoneButton`, `background*`, `showMenuBarExtra` (`:61-71`).
- `SettingsBindings` is `@Observable @MainActor` (`SingleThread/SettingsBindings.swift`); plain tracked fields `appearanceMode`/`textSize` default `.system` (`:28,30,57-58`); header doc `:1-10` — standard-suite values mirror `@AppStorage` defaults; seven App-Group keys (`showDate`, `sortOption`, `:96-183`) are computed store-backed properties that bypass `@AppStorage`.
- Write-back chain: `SettingsView` receives the bag; `.onChange(of: bag.appearanceMode) { _, new in appearanceMode = new }` and same for `textSize` (`ContentView+Settings.swift:11-21`; macOS adds `enableActionButtons`/`showMenuBarExtra` at `:28-31`).
- `@AppStorage("appearanceMode") var appearanceMode = AppearanceMode.system` (`ContentView.swift:71-72`), `textSize` (`:75-76`) — **standard suite**, not App-Group.
- `InterfaceSettingsView` takes `@Binding var appearanceMode` (`InterfaceSettingsView.swift:9`), `textSize` (`:10`); Appearance `Picker(selection: $appearanceMode)` over `AppearanceMode.allCases` with `.tag(mode)` (`:37-50`); Text Size `Picker` (`:58-75`). Each control carries `.accessibilityIdentifier(...)`.
- Application of value: `.onChange(of: appearanceMode)` → `viewModel.handleAppearanceMode(newValue)` (`ContentView.swift:294-295`) → iOS `AppDelegate.applyAppearance(mode)`, macOS `MacAppDelegate.applyAppearance(mode)` (`SingleThread/ContentViewModel.swift:155-161`). `TextSizeModifier` applies `content.dynamicTypeSize(size)` unless `.system` (`TextSizeModifier.swift:8-17`; applied `ContentView.swift:300`).
- Core store type: `AppearanceModePreference.swift:8-35` — `UserDefaults`-backed, `defaultsKey = "appearanceMode"` (`:19`, shared key used by `@AppStorage` and `AppearanceMode.load`), `rawValue` reads `defaults.object(forKey:) as? String`, missing/unrecognized → `"system"` (`:23-30`), `setRawValue` writes (`:32-33`). Init defaults `UserDefaults = .standard` (`:11`). `AppearanceMode` is an app-enum (`SingleThread/AppearanceMode.swift:15-17`) with platform mapping (`:26-51`), localized `title` (`:77-85`), `load(from:) reading the core store (`:86-88`).
- macOS: everything gated at compile time `#if os(iOS)` / `#elseif os(macOS)` (`InterfaceSettingsView.swift:10-12,18-24`; previews `:77-95`; `ContentView+Settings.swift:48/61`; `ContentViewModel.swift:155-161`; `ContentView.swift:78-80`). Separate macOS surface: `CommandMenu("Appearance")` with `Picker` bound to the **same** `@AppStorage("appearanceMode")` key (`SingleThreadApp.swift:53-58`; `SingleThreadApp+Commands.swift:45-54`) — reuse of the same storage key means the shared `.onChange → handleAppearanceMode` path applies; cross-observation between the two properties lives inside the `@AppStorage` macro (framework, not in repo).
- `SettingsViewModel.swift:11-24` — iOS-only `allowsLandscapeChanged` → `AppDelegate.applyLock` (`:13-15`); `showPreferenceChanged` → `WidgetCenter.shared.reloadAllTimelines()` on iOS/macOS (`:21-23`).
- Not findable: `@AppStorage` macro internals and `AppearanceMode`/`TextSize` enum Founation-side behavior (framework code, not in repo).

## Q2: Localization structure

### Findings
- Four string catalogs, all Xcode `.xcstrings` JSON (`sourceLanguage: "en"`): App `SingleThread/Resources/Localizable.xcstrings` (137 keys), Core `SingleThreadCore/Sources/SingleThreadCore/Resources/Localizable.xcstrings` (33 keys), Watch `SingleThreadWatch/Resources/Localizable.xcstrings` (7 keys), Widget `SingleThreadWidget/Resources/Localizable.xcstrings` (5 keys).
- Every key carries exactly six languages `en, zh-Hans, es, ja, de, fr` (pinned in `SingleThreadTests/LocalizationTests.swift:222`); plural `%lld` keys carry `variations.plural` — `one` for en/es/de/fr, `other`-only for zh-Hans/ja (`LocalizationTests.swift:208,210-220`).
- Build wiring: `LOCALIZATION_PREFERS_STRING_CATALOGS = YES` (`SingleThread.xcodeproj/project.pbxproj:670,727`), `GENERATE_INFOPLIST_FILE = YES` with `INFOPLIST_KEY_*` (`project.pbxproj:751-764,801-804`); catalogs live in synchronized folder groups (`LocalizationTests.swift:20-23`). Per-target `<target>/<lang>.lproj/InfoPlist.strings` for all six languages (18 files; keys verified at `LocalizationTests.swift:133-152,240-247`).
- Bundle selection: App compiles its table into the app bundle (`bundle: .main`), Core into the SPM package bundle (`bundle: .module`); tests resolve the core bundle via `Bundle.main.url(forResource: "SingleThreadCore_SingleThreadCore", ...)` (`LocalizationTestHelpers.swift:14-30`).
- `String(localized:)` call sites — **App (`bundle: .main`)**: `ContentView.swift:218,733,758`; `CreationFeedback.swift:29-30`; `SortOption+Presentation.swift:12-14`; `ContentViewModel.swift:105`; `MenuBarExtraOptions.swift:34`; `AppearanceMode.swift:71-73`; `TextSize.swift:42-46`; `SingleThreadApp+Commands.swift:17,23`; `ReminderDictation.swift:227,239`; `BackgroundSettingsView.swift:70`; `ReminderCardView.swift:128`. **Core (`bundle: .module`)**: `LocalizedString+Shared.swift:16-98` (20 `SharedStrings` accessors); `ReminderSkip.swift:42-44`; `ReminderRecurrenceFormatter.swift:17-30` (7 recurrence keys incl. plural). Outlier: `NotificationScheduler.swift:82` uses `bundle: .main`.
- `SharedStrings` typed-accessor layer (`SingleThreadCore/Sources/SingleThreadCore/LocalizedString+Shared.swift:11-99`): `public enum SharedStrings` with 20 members; doc `:3-10` — shared keys live here so app/watch/widget callers never repeat `table:`/`bundle:` args; keys shared across ≥2 targets are never duplicated in a target's own catalog (exception: "Medium" in both App and Core, `LocalizationTests.swift:266-267`). Every member delegates to `String(localized: <key>, table: "Localizable", bundle: .module)`.
- Watch/Widget consume **only** `SharedStrings.*` (`WatchReminderView.swift:51,134,138,149,153,178,197,212,219,226,229,258,262-263,331,348,353`; `NextThingWidget.swift:130,138,140,143,156,161,165,170,219,225`). Their own small catalogs are **unused by source** — the watch view renders hardcoded English literals (`WatchReminderView.swift:55,167,215,295,298,313,316`); catalogs are referenced only by `LocalizationTests.swift:236-237` paths.
- Pinned-locale seam: `String.en(_ key:bundle:table:)` = `String(localized: key, table: table, bundle: bundle, locale: Locale(identifier: "en"))` (`LocalizationTestHelpers.swift:7-13`) — Foundation's `String(localized:)` accepts a per-call `locale:` parameter. `LocalizationTests` forces no locale — it parses the raw catalog files (`#filePath` + `JSONSerialization`) and asserts languages/plurals/InfoPlist (`LocalizationTests.swift:13-160`).
- Residual unknowns: exact pbxproj folder-group → catalog mapping per target not located; full args of `ReminderIntentsTests.swift:17,29` not re-read.

## Q3: Shared preferences across the phone–watch boundary

### Findings
- Two patterns on the phone side: **plain bag values** (`enableActionButtons`) — `Toggle(isOn: $enableActionButtons)` (`InterfaceSettingsView.swift:88`) → `.onChange(of: bag.enableActionButtons)` write-back (`ContentView+Settings.swift:25` iOS / `:32` macOS) → `@AppStorage("enableActionButtons", store: AppGroup.defaults)` (`ContentView.swift:100`, default `true`). **Store-backed computed properties** (`showDate`, `sortOption` and five more) — no `@AppStorage`, no write-back handlers; `SettingsBindings` reads/writes `BoolPreferenceStore(key: BoolPreferenceKey.showDate.rawValue, fallback: true)` (`SettingsBindings.swift:104-114,179-183`; header `:6-11` notes the App-Group keys write straight through stores, which post `UserDefaults.didChangeNotification`).
- `AppGroup.defaults = UserDefaults(suiteName: "group.app.alanvardy.SingleThread") ?? .standard` (`SingleThreadCore/Sources/SingleThreadCore/AppGroup.swift:11-17`); `BoolPreferenceStore` defaults to it (`BoolPreferenceStore.swift:14`); `SortOption.declares defaultsKey = "sortOption"` (`SortOption.swift:18`, store `SortOptionStore`).
- Sync out: `SkippedReminderSyncService.swift:216-257` `pushAll()` builds **one combined application context** keyed by `PayloadKey` (`:344-361`):
  - unconditional: `skippedReminderIdentifiers`, `skipCounts`, `excludedListTitles`, `showUndatedReminders`, `sortOption` (via `sortStore.load().rawValue`, `:224`), `completionCount`;
  - `enableActionButtons` only if `enableActionButtonsStore.isSet` (`:229-231`; doc `:226-228` — never-set keys omitted so a fresh device keeps its own default);
  - `showDate`/recurrence/alarms/list/glow/`isEntitled` gated by `sends*` flags (`:232-257`).
  - Transport: `SkipSyncSession` protocol wrapping `WCSession.updateApplicationContext`/`sendMessage`/`queueUserInfo` (`:8-31`); push at `:252`; delivery chokepoint `deliver()` (`:371-387`).
- Phone-side triggers: store-change hooks → `service.pushAll()` (`SingleThread/AppViewModel.swift:424-426`); `store.onSortOptionChanged` → save + push (`:432-436`); `setupSyncObservation()` observes `UserDefaults.didChangeNotification` on `AppGroup.defaults` and diffs last-seen snapshots of showDate/recurrence/alarms/list/glow/enableActionButtons (`:438-479`). Service built at `:390-402` (`sendsShowDate`/`sendsEntitled` true).
- Receive: `apply(context:)` (`SkippedReminderSyncService.swift:423-441`) persists each key via its store, then fires a write-once hook (`onShowDateReceived` `:461-464`, `onEnableActionButtonsReceived` `:493-495`, `onSortOptionReceived` `:455-458`); `applyRemaining()` `:489-507`.
- Watch wiring: `WatchAppViewModel.swift:158-205` `setupSyncService()`; `:249-284` `wireStateReceiveHooks()` → `onShowDateReceived → showDateState?.apply(value)` (`:260-261`), `onEnableActionButtonsReceived → showEnableActionButtonsState?.apply(value)` (`:276-277`), `onSortOptionReceived → store?.setSortOption(option)` (via `makeSyncService` `:187-189`); `makeSyncService()` `:226-247` builds watch-side stores with `defaults: .standard`, `sendsShowDate: false` etc. (`:245-246`) — the watch never pushes settings back, only mutations (skip/complete/delete/reschedule) flow watch→phone (`wireStoreSyncHooks` `:207-224`).
- Watch state classes: `ShowDateState.swift:9-31` — `@Observable` holder replacing former `@AppStorage("showDate")` read-back; `init()` seeds from `BoolPreferenceStore(defaults: .standard, key: ..., fallback: true)` (`:29-31`); `apply()` persists then publishes (`:22-25`). Consumption: `WatchReminderView.swift:337` `if viewModel.showDateState.isEnabled, let due = display.dueDate { Text(due, style: .date) }`; `:82` gates action buttons.
- Over the wire vs shared suite: on watchOS no App Group is registered, so `AppGroup.defaults` falls back to `.standard` (`AppGroup.swift:16-17`); the wire is the *live-update* channel, `.standard` the persistence fallback/initial seed on the watch (`WatchAppViewModel.swift:29-34,234-244`). Generic mechanism: keyed `BoolPreferenceStore` + combined `pushAll()` + single receive decoder + per-key hooks; all stores default to `AppGroup.defaults`.

## Cross-Cutting Observations
- **Two preference plumbing patterns coexist** in the settings stack: (a) `@AppStorage`-backed bag fields with explicit `.onChange` write-backs (standard suite: `appearanceMode`, `textSize`; App-Group: `enableActionButtons`), and (b) store-backed computed properties on `SettingsBindings` that write straight through core `UserDefaults` store types (`showDate`, `sortOption`, ...) and post `didChangeNotification`. Enum-valued preferences have a precedent: `SortOption` (`defaultsKey`, `SortOptionStore`) and `AppearanceModePreference` (`UserDefaults`-backed with `load`/`setRawValue`).
- **The locale-pinning seam already exists in Foundation usage**: `String(localized:table:bundle:locale:)` with an explicit `Locale` is used by test helpers today — a per-call locale override of lookup. SwiftUI `Text(due, style: .date)` and `DatePicker` rendering instead follow the SwiftUI environment (no explicit `Locale` in prod code anywhere).
- **Localized-string consumption is split**: app `bundle: .main` direct calls + `SharedStrings` (`bundle: .module`) shared across app/watch/widget; watch/widget views consume only `SharedStrings`; ~47 hardcoded view literals bypass catalogs entirely; watch/widget catalogs contain keys no source uses.
- **Watch persistence model**: no App Group on watchOS — `AppGroup.defaults` falls back to `.standard`; live updates arrive over the WatchConnectivity context payload through per-key receive hooks (`onXReceived → ShowXState.apply`); initial seed is read directly from `.standard`.
- Gate-adjacent facts: unit tests are Swift Testing (names must not start with `test`); UI tests XCTest with accessibility audit; tests gate per-platform with `#if os(...)`.
