## Q3: In-flight loading state

### Findings
- **`ReminderStore` has no in-flight flag** (`@MainActor @Observable` `ReminderStore.swift:14-16`); grep for `isRefreshing/isLoading/isFetching/isReloading` = zero. `reload()` is **fully re-entrant** with no guard (:416). Only loading-adjacent state: `authorizationStatus` :72 (drives the launch gate) and results `reminders` :29-55 / `hasHidden` :69.
- **`ContentViewModel` has no in-flight flag** (`ContentViewModel.swift:9-11`); it forwards to the store (`reload(clearSkipped:)` :156-158). iOS/macOS refresh spinner is the **SwiftUI system `.refreshable` spinner** — no app-owned flag/progress/disable. No duplicate-reload gate.
- **`WatchReminderViewModel.isRefreshing` is the only reminder-loading flag in the codebase**: declared `var isRefreshing = false` `WatchReminderViewModel.swift:46`; set `true` :110 and `false` :119, both only inside `refresh(clearSkipped:)` :108-120: `guard !isRefreshing` :109, `isRefreshing = true` :110, `startedAt = Date()` :111, `await store.reload(clearSkipped:)` :112, minimum-display sleep :113-118, `isRefreshing = false` :119. No unit tests assert the toggling/hold.
- **`MinimumDisplayDuration`**: `public nonisolated enum` `SingleThreadCore/Sources/SingleThreadCore/MinimumDisplayDuration.swift:6` with sole API `remainingSleep(elapsed:minimum:) = max(0, minimum - elapsed)` :10-13. Only call site in the repo: watch refresh, `WatchReminderViewModel.swift:113-115`, constant `refreshMinimumDisplayDuration: TimeInterval = 1` :126 → spinner visible ≥ 1 s. Sleep is `try?`-swallowed :118 so the flag always resets on cancellation. Tests: `MinimumDisplayDurationTests.swift:11-22` (pure math floor over 4 cases).
- **Surfacing**: watch overlay `ProgressView()` top-aligned while `isRefreshing` `WatchReminderView.swift:90-94`; empty-state refresh button `.disabled(viewModel.isRefreshing)` :191; dialog Refresh button not disabled but VM-guarded :109 (:208-210). iOS/macOS launch spinner: `ContentView.swift:373-385` — `.notDetermined` → `ProgressView(SharedStrings.requestingAccess)` :376; denied/restricted → `ContentUnavailableView` :379-385. Watch launch gate `WatchReminderView.swift:47-52`.
- Closest iOS analog (wallpaper, not reminders): `BackgroundImageStore.isRefreshing` `BackgroundImageStore.swift:76` toggled in `forceRefresh()` :122-129 (guard :123, defer reset), surfaced by `BackgroundSettingsView.swift:62-70` (inline `ProgressView`, `.disabled(...)` :67, `.accessibilityValue("Refreshing")` :68-72, id `refreshWallpaperButton`). The only iOS/macOS manual-refresh-with-in-flight-state precedent.

- Action: both call sites fire `Task { await viewModel.refresh(clearSkipped: viewModel.store.allSkipped) }` (:189, :209) — argument dynamically `store.allSkipped` (un-hide when in All-Done state). View does not await the task.

## Cross-Cutting Observations
- **The watch refresh button is the only manual reminder-refresh control in the codebase.** Its full pattern (VM-owned `isRefreshing` + `guard`, action = `refresh(clearSkipped: store.allSkipped)`, `.disabled(isRefreshing)`, id `refreshButton`, 1 s minimum display) is the in-repo precedent; the wallpaper `refreshWallpaperButton` (`BackgroundSettingsView.swift:55-73`) is the only iOS/macOS manual-refresh-in-flight example.
- **Reload is centralized**: all refresh paths funnel into `ReminderStore.reload(clearSkipped:)` (`ReminderStore.swift:416`); `ContentViewModel.reload(clearSkipped:)` (`ContentViewModel.swift:156-158`) is a thin passthrough. Reflexive design: post-mutation reloads live inside the store, not at call sites.
- **`clearSkipped` semantics**: `true` only from user "un-hide" gestures (all-skipped pull-to-refresh, watch Refresh in all-done state); it clears the persisted skip set and pushes an empty skip set to the watch; the `skipGeneration` counter kills in-flight skip tasks on clear.
- Overlay styling is uniform: 56×56 `controlPlate()` circles with `.accessibilityLabel`/`Identifier`/`.isButton`; position via `.overlay(alignment:)` + `.padding(.top, 8).padding(.trailing/leading, 12)` — the macOS gear at top-trailing (`ContentView.swift:184-199`) is the direct styling template for any top-corner macOS control.
- Strings that must appear on both iPhone and Apple Watch (labels, empty-state copy, action names) come from the Core catalog so translation is shared; per-target catalogs hold platform-specific phrasing.
- Every persisted value shared with the watch round-trips through `AppGroup.defaults` per AGENTS.md; `--seed`/`--ui-testing` seams both write to the suite (`UITestingSeed.swift:62-98`, `AppViewModel.swift:342`).
- macOS testing is unit-only (`-only-testing:SingleThreadTests`) despite the UI-test bundle being macOS-capable; iOS audit tests carry a macOS `#else` branch that is never scheduled.
