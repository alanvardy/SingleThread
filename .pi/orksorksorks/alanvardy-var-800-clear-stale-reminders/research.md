# Research Findings

Branch: `alanvardy-var-800-clear-stale-reminders`. Line numbers verified against the working tree; the core file is `SingleThreadCore/Sources/SingleThreadCore/ReminderStore.swift` (cited as `ReminderStore.swift`).

## Q1: Flow that determines the "current" reminder — reload / visibleReminders / listContent, and how complete / delete / skip advance it

### Findings
- **`reload(clearSkipped:)` is the single fetch path** (`ReminderStore.swift:439-491`): `guard loadsReminders` (`:440`) → iOS/macOS `eventStore.refreshSourcesIfNecessary()` (`:442`) → date window (`:444-452`, 30-day `overdueCutoff()` → `endOfToday()` unless `showsUndatedReminders`; `ReminderDateFilter.swift:12-21,25-33,41-52`) → `predicateForIncompleteReminders(withDueDateStarting:ending:calendars: nil)` (`:453-456`, all lists) → `await fetchReminders(matching:)` (`:457`, async bridge at `:626-638` via `withCheckedContinuation` + `ResumptionGate.swift:19` + `resumeOnMainActor`).
- **`reload()` issues 1 or 2 EventKit fetches**: when undated reminders are hidden, a second broad fetch (`predicateForIncompleteReminders(nil…nil)`) computes `hasHidden` via `hasHiddenFor(shown:allIncomplete:)` (`:467-473, :92-99`); the undated-shown path re-filters the broad fetch client-side with `ReminderDateFilter.isInCurrentWindow` (`:458-460`).
- **Post-fetch pipeline**: `applyingPendingCompletionFilter(to:)` (`:478, :641-648` — loads/persists `pendingCompletions`, applies `PendingCompletionLogic.filtering` then `.removingCompleted` = "never show a completed card" invariant) → `reminders = shown` wholesale replacement (`:479`) → `availableLists` from `calendars(for: .reminder)` (`:481-485`) → `reconcileSkipState(clearSkipped:visibleShown:)` (`:487, :668-685`; `ReminderSkipLogic.resolve` prunes stale skip ids and persists, `ReminderSkip.swift:5-16`) → `prunePendingCompletions(fetched:)` (`:490, :650-664`; skipped when `fetched.isEmpty` to protect a transient empty fetch) → `onRemindersChanged?()` last (`:491`). **`reload()` does not sort** — sorting lives in the computed `visibleReminders`.
- **"Current" = `visibleReminders.first`**: computed property (`ReminderStore.swift:146-151`) filters `reminders` by `skippedIDs` and `excludedListTitles` then sorts via `ReminderSort.areInIncreasingOrder(using: sortOption)` (`ReminderSort.swift:14-45,56-67`; default `.priority` `:75`, persisted via `SortOptionStore` `SortOption.swift:34-60`). `listContent` (`:161-171`) resolves `allSkipped → .allDone` else `visibleReminders.first → .reminder(ReminderDisplay(...))` else `.empty(hasHidden:)`; never `.noAccess` (`ListContent.swift:1-26`). All stored properties are `@Observable` (`ReminderStore.swift:14-16`), so mutation re-derives the view.
- **Complete (iOS)** `completeReminder(identifier:)` (`ReminderStore.swift:239-258`): `guard canMutate` (`:221`, `canMutate` at `:175-179`) → `isCompleted = true` + `eventStore.save(commit: true)` (`:244-245`) → `completionCounter.increment()` / `undoStore.retain` / `resetSkipCount` (`:246-248`) → `await settle()` (200 ms) + `await reload()` (`:249-250`). The fresh incomplete fetch no longer contains it → next-highest sorted reminder becomes `visibleReminders.first`. `completeCurrentReminder()` (`:261-264`) captures first, then delegates.
- **Complete (watchOS)** (`:215-237`): EventKit read-only — removes from in-memory `reminders` (`:224`), records id in `PendingCompletionStore` (`:230-232`, 300 s expiry `PendingCompletionStore.swift:15,73-79`), fires `onCompleteReminder` relay (`:235`).
- **Delete (iOS)** (`:294-317`): `eventStore.remove(reminder, commit: true)` (`:305` — whole object incl. recurring series, `EventKitStoring.swift:33-35`) → settle + reload (`:307-308`). Watch branch removes locally + relays (`:298-301`).
- **Skip** `skipCurrentReminder()` (`:380-405`): guard → capture first → `incrementSkipCount` (`:385, :571-578`); on iOS/watchOS a **6th-skip nudge interrupt returns early** (`:387-389`, `SkipCountLogic.crossedThreshold` `SkipCountStore.swift:21-27`) so the reminder *stays current*; otherwise `updatedSkipSet(afterSkipping:)` (`:393, :561-566`) and an **unstructured `Task`** (`:395-402`) sleeps `settle()` → `applySkipSet(updated, generation:)` (`:613-623`) → `await reload()`; the `skipGeneration` gate (`:600-608, :615-617`) discards the apply if a clear-skipped raced ahead. `skipCurrentReminderImmediately()` (`:417-432`) is the synchronous widget variant (no settle — process may be suspended).
- **Advance mechanism is structural, not explicit**: a mutation removes the current candidate from EventKit's incomplete population (or from `reminders`/`skippedIDs`), `visibleReminders`/`listContent` re-derive, `reload()` replaces `reminders` (`:479`). `undoLastCompletion()` (`:268-292`) reverses it (re-save + reload → reminder re-enters at its sorted position). Cross-surface: every mutation eventually fires `onRemindersChanged` (`:411, :491, :501, :510, :621`) → `AppViewModel.swift:32-38` `WidgetCenter.shared.reloadAllTimelines()`.

## Q2: Freshness semantics of the EventKit read path; what is memoized/cached

### Findings
- **Every fetch is a fresh EventKit query**: `reload()` rebuilds the predicate and awaits 1-2 `eventStore.fetchReminders` calls per invocation — no TTL, no dirty flag, no fetch-time generation (`ReminderStore.swift:439-491`). `predicateForIncompleteReminders` returns only incomplete reminders, so a completion/deletion (even on another device, via OS Reminders sync) drops out of the result set by itself.
- **`refreshSourcesIfNecessary()`** is called once per `reload()` on iOS/macOS (`:442`; no-op in `InMemoryEventStore.swift:85`). The only explicit read-freshness timing guarantee in repo docs is the **200 ms `settle()`** before read-after-write (`ReminderStore.swift:10-12, :38-40, :537-540` — "Production waits 200 ms for EventKit to reflect an in-flight write"). SDK internals of `EKEventStore.fetchReminders`/`predicateForIncompleteReminders`/`refreshSourcesIfNecessary` live outside this tree and are not documented here; repo docs do not state whether a fetch physically re-reads the OS DB.
- **Fetch results are never memoized**; what persists *between* reloads in the store object: `reminders` (wholesale-replaced each reload, `:479`), `skippedIDs` (re-resolved from skip store each reload `:682`, mutated between by `applySkipSet`/`clearSkippedState` `:613-623/:600-608`), `excludedListTitles` (`:683`), `hasHidden` (recomputed `:462-473`), `availableLists` (`:481-485`), `pendingCompletions` (loaded inside `reload()` `:645-646`, pruned+persisted `:650-664`), in-memory `skipGeneration` (`:557-558`), `undoStore` (iOS-only, `#if !os(watchOS)` `:268`).
- **All persisted identifier sets reconcile against the new fetch inside `reload()`**: skip ids (`reconcileSkipState :668-685`), skip counts (`reconcileSkipCounts :590-596`), excluded titles (`:683`), pending completions (`prunePendingCompletions :650-664`). Persistence is UserDefaults-backed via `AppGroup.defaults` (`AppGroup.swift:9-22`, suite `group.app.alanvardy.SingleThread`): `SkippedReminderStore` key `"skippedReminderIdentifiers"` (`ReminderSkip.swift:112-130`), `SkipCountStore` `"skipCounts"`, `ExcludedListStore` `"excludedListTitles"`, `PendingCompletionStore` `"pendingCompletionIdentifiers"`.
- **The abstraction**: `EventKitStoring` protocol (`EventKitStoring.swift:4-36`, `@MainActor`), production conformance is the SDK class itself (`extension EKEventStore: EventKitStoring`, `:38-56`). `InMemoryEventStore` (`InMemoryEventStore.swift:13`) computes `allReminders.filter { !$0.isCompleted }` fresh on each fetch (`:60`, predicate stub inert `NSPredicate(value: true)` `:49-54`; `save` appends `:87-88`, `remove` filters `:91-92`; `authorizationStatus` always `.fullAccess` `:38-39`); it does **not** model a data source changing behind the store's back — cross-device freshness is modeled by seeding `isCompleted = true` before a fetch.
- **Cross-device assumption is asserted only indirectly in this tree**: `ReminderStoreTests.swift:283-312` ("completed on another device → dropped by refetch") and the pending-drain logic (`ReminderStore.swift:650-664`), which assumes a phone-side completion removes the reminder from the OS incomplete predicate.

## Q3: Every trigger that leads to `reload()` on iOS/macOS — which re-read completion state

### Findings
- **Headline**: the app notices external completion/deletion **only through explicit `reload()` calls**. Zero `EKEventStoreChanged` observers, zero `.onAppear`, zero `.onOpenURL`/incoming deep-link handling in the repo (verified by grep); scene-phase and `applicationDidBecomeActive` do **not** refetch. Every reload is a fresh EventKit fetch (Q1), so trigger Group I re-reads completion state; Group II re-renders local state only.
- **Group I — triggers that refetch (re-read completion state)**: (1) relaunch/first appearance `.task` (`ContentView.swift:249-255` → `ContentViewModel.task` `ContentViewModel.swift:118-121` → `store.start()` `ReminderStore.swift:191-199`; `AppViewModel` rebuilt per launch, `SingleThreadApp.swift:50`); (2) pull-to-refresh in all three list states (`.allDone` with `clearSkipped: true` `ContentView.swift:384-385`, `.empty` `:397-398`, `.reminder` `:479-480`, → `ContentViewModel.reload` `ContentViewModel.swift:175-177`); (3) macOS refresh button (`ContentView.swift:195-206` → `refreshManual` `ContentViewModel.swift:182-198` → `store.reload(clearSkipped: store.allSkipped)` `:187`); (4) show-undated preference change (`ContentView.swift:264-265` → `ContentViewModel.handleShowUndatedReminders` `:124-127`), triggered either from Settings (`FilterSortSettingsView.swift:31` → `SettingsBindings.swift:77-87` → `BoolPreferenceStore` write → `UserDefaults.didChangeNotification` → `PreferenceHolder.swift:14-21` observer → `.onChange`) or from a watch push persisting into the same AppGroup suite (`SkippedReminderSyncService.swift:400-405`); (5) watch messages wired in `AppViewModel.setupSyncService` (`AppViewModel.swift:376-393`): `onSkipCountsReceived → store?.reload()` (`:392`), `onCompleteReminderReceived → completeReminder` (`:377-379`), `onDeleteReminderReceived → deleteReminder` (`:381-383`), `onRescheduleReminderReceived → rescheduleReminder` (`:385-387`) — each ends in the phone executing the EK write then `reload()`; (6) every in-app mutation's post-write reload (complete/skip/delete/undo/reschedule/add, `ReminderStore.swift:250, :281, :308, :341, :371, :399-400`); (7) widget-extension processes: intents call `store.reload()` before mutating (`ReminderIntents.swift:21, :44`) and the timeline calls it per refresh (`NextThingWidget.swift:72`).
- **Not wired on the phone**: `onSkippedIdentifiersReceived` — a watch-pushed skip set persists (`SkippedReminderSyncService.swift:387-394`) but is not picked up until the next reload's `reconcileSkipState` (`ReminderStore.swift:668-685`).
- **Group II — re-render only**: sort change (`ContentView.swift:267-268` → `setSortOption` `ReminderStore.swift:408-412`, fires `onRemindersChanged?()` `:411`); excluded-list changes (`:496-502, :506-512`); widget-timeline hook `onRemindersChanged → WidgetCenter.shared.reloadAllTimelines()` (`AppViewModel.swift:32-38`); `PreferenceHolder` observers refresh preference values only (`PreferenceHolder.swift:14-21`).
- **Lifecycle surfaces that exist but do NOT reload**: `.onChange(of: scenePhase)` (`ContentView.swift:246-247, :603-621`) — `.background` schedules iOS notifications using **stale in-memory** `store.visibleReminders.count` (`AppViewModel.swift:177-180`), `.active` cancels notifications + refreshes dictation auth; nothing fetches. iOS/macOS `applicationDidBecomeActive` (`AppDelegate.swift:46-50, :92-95`) only re-apply appearance. No background refetch exists; a reminder completed/deleted in another app while SingleThread stays foregrounded is noticed only at the next Group-I trigger.

## Q4: How the watch obtains data; phone→watch pushes; consistency

### Findings
- **The watch reads its own local EventKit store**: `WatchAppViewModel` init (`SingleThreadWatch/WatchAppViewModel.swift:13-19`) builds `ReminderStore(loadsReminders: true)` (`:18`) unless `--ui-testing` (in-memory `uiTestingStore`, `:106-170`). `WatchReminderView.swift:59-61` `.task` → `WatchReminderViewModel.task()` (`:83`) → `store.start()` (`ReminderStore.swift:191-199`). Display = `viewModel.store.listContent` / `visibleReminders.first` (`WatchReminderView.swift:95-108`). **There is no reminder fetch over WatchConnectivity.**
- **Transport**: `SkippedReminderSyncService` (`#if os(iOS) || os(watchOS)`, `SkippedReminderSyncService.swift:3-4`) wraps `WCSession` behind `SkipSyncSession` (`:8-17`). Two channels: `updateApplicationContext` (combined snapshot, latest-wins, auto-delivered on (re)connect, `:21-22`) and fire-and-forget `sendMessage` (`:245-264`). No `transferUserInfo` anywhere.
- **Phone→watch push = one combined context per push** (`pushAll()`, `:200-243`): always-on keys `skippedReminderIdentifiers`, `skipCounts`, `excludedListTitles`, `showUndatedReminders`, `sortOption`, `completionCount`, `enableActionButtons` (`:205-211`); gated `showDate/showRecurrence/showAlarms/showList/showCompletionGlow/isEntitled` (`:213-233`). Keys centralized in `PayloadKey` (`:342-358`).
- **Push triggers (phone, `AppViewModel.swift`)**: `onSkipSetChanged`/`onShowUndatedRemindersChanged`/`onExcludedListsChanged → pushAll()` (`:395-397`); sort change (`:406-409`); `withObservationTracking` on `store.entitlementStore.isEntitled` (`:418-427`); `UserDefaults.didChangeNotification` observer on `AppGroup.defaults` → `handlePreferencesChanged` diffs show-*/enable flags and pushes on change (`:429-484`). **No initial push at launch** — the watch receives the last context on activation (latest-wins auto-delivery) and restores persisted values itself.
- **Watch receive wiring** (`WatchAppViewModel.setupSyncService`, `:172-214`): `onShowUndatedRemindersReceived → store.showsUndatedReminders + reload` (`:176-181`); `onSkippedIdentifiersReceived → store.reload()` (`:185`); `onSkipCountsReceived → store.reload()` (`:187-188`); `onSortOptionReceived → setSortOption` (`:190-192`); `onCompletionCountReceived → AppGroup.defaults "completionCount"` (feeds `canMutate`, `ReminderStore.swift:175-179`) (`:197-199`); `onExcludedListTitlesReceived → refreshExcludedListTitles` (`:202-204`); show-* values → `Show*State.apply` (`:254-286`). So phone-pushed context **does** trigger live reloads/re-sorts on the watch (verified by `SingleThreadWatchTests/WatchSyncPipelineTests.swift`).
- **Watch → phone**: local skip fires `pushAll()` from `store.onSkipSetChanged` (`:216-224`); complete/delete/reschedule are `sendMessage` relays (`:218-222`) executed by the phone (`AppViewModel.swift:385-388`) — **the phone is the only EventKit writer** (watchOS branches are read-only, `ReminderStore.swift:215-237, :298-301, :358-366`). Pending-completion store (`PendingCompletionStore.swift`, 300 s expiry) hides the relayed reminder from the watch until the phone's fetch drops it (`ReminderStore.swift:641-664`).
- **Sort / preference state on the watch**: `Show*State` holders read `BoolPreferenceStore(defaults: .standard, key:)` at init and `apply(_:)` persists + publishes (`ShowDateState.swift:14-28`, same in `ShowRecurrence/ShowAlarms/ShowList/ShowCompletionGlowState.swift:14-28`); `ShowEnableActionButtonsState.swift:11-13` reads `AppGroup.defaults` (falls back `.standard` — watch has no App Group, `AppGroup.swift:18-24`); `EntitlementState` is memory-only (`EntitlementState.swift:13,24-26`); sort restored from `SortOptionStore().load()` at launch (`WatchAppViewModel.swift:31`).

## Q5: Widget — timeline refresh model, ReminderStore lifetime, intents

### Findings
- **Timeline model**: `NextThingProvider` (`SingleThreadWidget/NextThingWidget.swift:20`) `getTimeline` builds **one entry** with `let refresh = Date().addingTimeInterval(15 * 60)` and `Timeline(entries: [entry], policy: .after(refresh))` (`:44-50`); `.placeholder`/`getSnapshot` return hardcoded entries (`:23-42`). Config: `StaticConfiguration(kind: "NextThing", provider:) { ... }`, families `.systemSmall/.systemMedium/.systemLarge` (`:94-111`). The extension registers only `NextThingWidget()` (`SingleThreadWidgetBundle.swift:7-11`).
- **ReminderStore lifetime: per-refresh construction**. `makeEntry()` (`@MainActor private static`, `:55-89`) reads display prefs via `BoolPreferenceStore` (`:57-64`), checks `EKEventStore.authorizationStatus(for: .reminder)` directly (`:65`), and on `.fullAccess` constructs a **brand-new** `ReminderStore(loadsReminders: true)` (`:67`), applies `showsUndatedReminders` (`:68-70`) and `setSortOption(SortOptionStore().load())` (`:71`), `await store.reload()` (`:72`), and builds the entry from `store.listContent` (`:73-79`). It never calls `start()` and never requests access — it relies on app-granted full access. Nothing retains a store between refreshes (the intents also construct fresh stores, `ReminderIntents.swift:19, :42`). Persisted state crosses instances via AppGroup stores (skip ids, counts, exclusions, completion count, pending completions, sort, bool prefs).
- **Intents** (`SingleThreadCore/Sources/SingleThreadCore/ReminderIntents.swift`): `CompleteReminderIntent.perform` (`:18-24`) = fresh store → `setSortOption` → `await store.reload()` → `await store.completeCurrentReminder()`; widget view buttons `Button(intent: CompleteReminderIntent())` / `SkipReminderIntent()` (`NextThingWidget.swift:149, :158`, rendered only for `.reminder(display)`). `SkipReminderIntent.perform` (`:41-51`) = fresh store → reload → `skipCurrentReminderImmediately()` (`:49`) — the sync variant with no settle sleep, documented as safe when WidgetKit may suspend the process (`ReminderStore.swift:416-432`).
- **Timeline reload after intents**: the freshly-built store's hooks (`onRemindersChanged`/`onSkipSetChanged`) are **nil in the widget process** — nothing in the extension wires them (`SingleThreadWidgetBundle.swift:7-11`); reload is WidgetKit's automatic timeline reload for an AppIntent run from the widget (`ReminderIntents.swift:4-6` doc, `ReminderStore.swift:416-420` doc).
- **External widget reloads = exactly two `WidgetCenter.shared.reloadAllTimelines()` sites**: `AppViewModel.swift:32-38` (`onRemindersChanged` — fires from `ReminderStore.swift:411, :491, :501, :510, :621`) and `SettingsViewModel.swift:20-23` (`showPreferenceChanged` on show-date/recurrence/alarms toggles). No `NotificationCenter.post`, no notification-userInfo reload path; `NotificationScheduler` schedules a plain `UNTimeIntervalNotificationTrigger` with no userInfo (`NotificationScheduler.swift:63-106, :96-110`).
- **Entitlements/access**: widget builds use `SingleThread/AppGroup.entitlements` (`project.pbxproj:1000, :1031` — app group `group.app.alanvardy.SingleThread`); reminders usage string via `INFOPLIST_KEY_NSRemindersFullAccessUsageDescription` (`project.pbxproj:1007, :1038`); app target uses the same App Group entitlements on iOS and `SingleThread.entitlements` (app sandbox + calendar personal-information + app group) on macOS (`project.pbxproj:740-742, :754`).

## Q6: Periodic/delayed-task patterns, lifecycle, concurrency constraints

### Findings
- **No `Task.sleep` loops anywhere** — every `Task.sleep` is a one-shot delay: ReminderStore settle 200 ms (`ReminderStore.swift:38-40`); deferred skip task (`:395-405`); `ContentViewModel.refreshManual` min-display `Task.sleep(for: .seconds(...))` (`ContentViewModel.swift:189-191`, `MinimumDisplayDuration.swift:6-13`); watch completion ghost-card delay (`WatchReminderViewModel.swift:103-116`); watch refresh min-display 1 s (`:121-133, :139`); `CompletionGlow` auto-dismiss (`CompletionGlow.swift:36-44`); dictation feedback 1 s (`DictationViewModel.swift:85`) and 5 s auto-stop timeout (`ReminderDictation.swift:200-208`); one `DispatchQueue.main.asyncAfter` UI-test seam (`WatchAppViewModel.swift:294`). Zero `Timer.publish`/Combine and zero `nilLiteralInterval` in live code.
- **`for await` streams only in `EntitlementStore`**: long-lived `Transaction.updates` loop kept alive by stored `observationTask` (`EntitlementStore.swift:19-21, :94`) and cancelled in `deinit` (`:43-45`); one-shot `Transaction.currentEntitlements` (`:104`). WatchConnectivity is callback-based (`SkippedReminderSyncService.swift:31, :328-393`).
- **NotificationScheduler**: cancel-then-reschedule every invocation, single non-repeating `UNTimeIntervalNotificationTrigger` (`NotificationScheduler.swift:63-106`); call sites: iOS scene phase background/active (`ContentView.swift:603-621`), iOS settings toggle (`ContentView+iOS.swift:38-46`), macOS via `onRemindersChanged → scheduleNotificationsForMacOS` (`AppViewModel.swift:33-39, :301-313`).
- **Scene phase**: iOS/macOS only — `.background`: schedule notifications; `.active`: cancel + dictation auth refresh (`ContentView.swift:246-247, :603-621`); **watch and widget have zero scenePhase handling** (grep). Start-of-lifetime work is in auto-cancelling `.task` modifiers (`ContentView.swift:249-257`, `WatchReminderView.swift:59-61`, `PurchaseSettingsView.swift:56-58`). **No `.task(id:)`/`.task(onChange:)` anywhere**; no `withTaskCancellationHandler`/`checkCancellation` in live code.
- **Lifecycle/teardown patterns**: long-lived `for await` is the only stored-task-with-deinit-cancel (`EntitlementStore.swift:19-21, :43-45, :91`); fire-and-forget unstructured `Task { [weak self] ... }` with no handles everywhere else (skip task `ReminderStore.swift:395-405`, ghost card `WatchReminderViewModel.swift:104-116`, dictation timeout `ReminderDictation.swift:200-208`); `PreferenceHolder` removes its NotificationCenter observer in `deinit` (`PreferenceHolder.swift:24-31`); dictation teardown is `defer` (`ReminderDictation.swift:145-153`); callback→MainActor bridges use `Task { @MainActor in ... }` at the wiring site (e.g. `AppViewModel.swift:36, :389, :392`, `WatchAppViewModel.swift:188, :191`).
- **Concurrency constraints**: `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` set on **only two targets** — SingleThread (`project.pbxproj:777, :827`) and SingleThreadWatch (`:961, :989`) — so app/watch types default MainActor; **not set** on SingleThreadWidget (`:997, :1028`), the test targets, or project level (`:617, :680`). `SingleThreadCore` declares no default isolation, so Core marks `@MainActor` explicitly: `ReminderStore.swift:14`, `NotificationScheduler.swift:6`, `CompletionGlow.swift:11`, `EntitlementStore.swift:10`, `EntitlementState.swift:8`, `UndoStore.swift:8`, `PreferenceHolder.swift:7`, protocols `EventKitStoring.swift:7`, `UserNotificationCentering.swift:5`, intent `perform()`s (`ReminderIntents.swift:17, :40`), widget `makeEntry` (`NextThingWidget.swift:54`). Nonisolated escape hatches: `SkippedReminderSyncService` is not MainActor with `nonisolated(unsafe)` hook vars (`SkippedReminderSyncService.swift:91-181`) + `MainActor.assumeIsolated` (`:73, :233`); `EntitlementStore.observationTask` (`EntitlementStore.swift:91`) and `PreferenceHolder.observer` (`PreferenceHolder.swift:31`) are `nonisolated(unsafe)`; `ResumptionGate` is `@unchecked Sendable` (`ResumptionGate.swift:10-37, :47-53`). `SWIFT_VERSION = 6.0`, `SWIFT_APPROACHABLE_CONCURRENCY = YES`, no `SWIFT_STRICT_CONCURRENCY` setting.

## Cross-Cutting Observations
- **One fetch funnel, three surfaces**: iOS/macOS app (long-lived store, `AppViewModel.swift:55`), watch (own local store), and widget (per-refresh store) all call the same `ReminderStore.reload()`; identity/skip/exclusion/pending state lives in AppGroup-backed UserDefaults stores so a fresh store converges to the same displayed set.
- **Structural advancement**: there is no "advance to next" code anywhere; the next reminder becomes current purely because mutations + reloads shrink the fetched incomplete set and `visibleReminders`/`listContent` re-derive from `@Observable` state. The only deliberate pause is the 6th-skip nudge interrupt (`ReminderStore.swift:387-389`).
- **Hook-based integration**: `ReminderStore` is hook-rich but Core never touches UserDefaults, WatchConnectivity, stores, or WidgetKit directly; app/watch layers wire `on*` hooks (`AppViewModel.swift:376-409`, `WatchAppViewModel.swift:172-286`). Widget/intent processes run with nil hooks and rely on WidgetKit's automatic timeline reload.
- **Pending-completion is the only cross-device staleness guard**: 300 s expiry + hide-until-phone-processes + prune-on-fetch (`PendingCompletionStore.swift:5-28`, `ReminderStore.swift:641-664`) — iOS never writes it, so it is watch-only in practice.
- **Read freshness is unobserved on purpose**: no EventKit change notifications, no scene-phase refetch, no foreground refetch; freshness is pull-driven (reload triggers in Q3-I) plus the 200 ms settle write guarantee.
- **Test style**: Swift Testing (`import Testing`, no `import XCTest` in `SingleThreadTests`; 72 files); `InMemoryEventStore` + `noopSettle` + continuation rendezvous are the standard determinism stack; UI tests (XCTest) are exceptions and use `--seed`/`--ui-testing-noop-settle` launch args.
