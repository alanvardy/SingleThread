## Q2: How do iOS/macOS-side preference changes reach the watch?

### Findings
- **Push is iOS-only**. `SkippedReminderSyncService` is built/armed inside `#if os(iOS)` in `AppViewModel.init` (`AppViewModel.swift:28-76`): session `WCSession.default`, skip/store/defaults-backed preference stores, `sendsShowDate: true, sendsEntitled: true` (`:39-40`); store hooks trigger pushes: `onSkipSetChanged`→pushAll `:60`, `onShowUndatedRemindersChanged`→pushAll `:61`, `onExcludedListsChanged`→pushAll `:62`, `onCompleteReminder`→requestCompleteReminder `:63`, `onDeleteReminder`→requestDeleteReminder `:68`, `onSortOptionChanged`→save+pushAll `:71-73`; widget timelines reload hook `:77-81`. macOS gets **only** the widget hook — no WatchConnectivity.
- **Defaults diff pipeline**: `setupSyncObservation()` `:418-431` → `handlePreferencesChanged()` `:432-449` diffs exactly five keys (showDate, showRecurrence, showAlarms, showList, showCompletionGlow) against last-seen cache `:453-457`, then `syncService?.pushAll()` `:448`. Never diffed here: sortOption, showUndatedReminders, skip IDs/counts, excluded lists, completionCount, entitlement (travel via store hooks or `setupEntitlementObservation` `:402-411`, which re-registers itself on change).
- **Transport**: `pushAll()` (`SingleThreadCore/Sources/SingleThreadCore/SkippedReminderSyncService.swift:176-213`) builds one snapshot context (always: skippedReminderIdentifiers, skipCounts, excludedListTitles, showUndatedReminders, sortOption, completionCount; conditional flags for showDate/Recurrence/Alarms/List/CompletionGlow/entitled) → `session.updateApplicationContext` (latest-wins, auto-delivered on reconnect, doc `:21-22, :171-175`). Interactive complete/delete use `sendMessage` (`:219-237`). **`PayloadKey` enum `:278-293`**: `showDate`…`showCompletionGlow`, `showUndatedReminders`, `sortOption`, `skippedReminderIdentifiers`, `skipCounts`, `excludedListTitles`, `completeReminderIdentifier`, `deleteReminderIdentifier`, `completionCount`, `entitled` (wire value `"isEntitled"`).
- **Receive side (watch)**: `session(_:didReceiveApplicationContext:)` `:241-245` → `apply(context:)` `:320-376` decodes each present key, persists into `.standard`-backed stores, fires `on*Received`. `applyRemaining` `:381-395`: skipCounts→save+hook, entitled→`onEntitlementReceived` (in-memory only — `EntitlementState.swift:8-21`), completionCount→hook.
- **WatchAppViewModel.setupSyncService** (`SingleThreadWatch/WatchAppViewModel.swift:160-216`): `guard WCSession.isSupported()` `:161` (standalone watch skips service); built with all `sends*: false` `:172-173` (one-way phone→watch) and `defaults: .standard` stores `:165-172`; handlers: showUndated→`store.showsUndatedReminders`+reload `:176-181`, skippedIDs→reload `:185-188`, skipCounts→reload `:190-192`, sortOption→`setSortOption` `:194-196`, completionCount→`AppGroup.defaults.set(count, "completionCount")` `:201-203`, exclusions→`refreshExcludedListTitles` `:206-208`; watch pushes only skip-set changes (`store.onSkipSetChanged = { _ in service.pushAll() }` `:210`); complete/delete relay `:213-214`. `wireStateReceiveHooks` `:222-248` hops `Task { @MainActor }` then `.apply(value)` on each `Show*State`.
- **`Show*State` holders** (ShowDateState.swift:1-31 and identical siblings for Recurrence/Alarms/List/CompletionGlow): `@Observable`, seed from `.standard` at init (`:14-20`), `apply(_:)` persists + publishes (`:24-29`, preference at `:29`). Replaces former `@AppStorage` read-back (doc in each file). Consumed at `WatchReminderView.swift:268` (date), `:273` (list), `:278` (recurrence), `:283` (alarms); glow gates `WatchReminderViewModel.swift:86-87`.
- **Watch-relevant preference inventory** (12): the five show-* + entitled + showUndatedReminders + sortOption + skippedReminderIdentifiers + skipCounts + completionCount + excludedListTitles (full list with refs in agent-q2 §4). **Not watch-relevant**: notifications pair, enableActionButtons, showSwipePrompt, showUndoButton, allowsLandscape, showMicrophoneButton, background trio (all `.standard`, `ContentView.swift:72-113`).
- **Launch-arg seams (watch, standalone)**: `--ui-testing` (`WatchAppViewModel.swift:14`, deterministic single-reminder store `:95-149`), `--ui-testing-gated` (`:21-27`, completes→freemiumCap so `canMutate` false → upgrade prompt), `--ui-testing-glow` / `--ui-testing-glow-disabled` (`:48-56`, `showCompletionGlowState.apply(true/false)` + glow duration 2.0s `:55-57`; phone-side duration at `AppViewModel.swift:243-246`), `--ui-testing-priority <n>` `:107-110`, `--ui-testing-skip-count <n>` `:118-121` (AppGroup skipCounts), `--ui-testing-excluded-list "<l>"` / `--ui-testing-live-excluded "<l>"` `:131-146, :252-263` (live WCSession context delivery 5s after launch). iOS family: `--ui-testing` (`AppViewModel.swift:281-312`), `--reset-glow-preference` `:285-286`, `--reset-swipe-preference` `:288-289`, `--ui-testing-glow` `:243-246` (used with `--seed`).

## Q4: What do the three state-change operations look like in `ReminderStore`, and what platform constraints apply?

### Findings
- **Class**: `@MainActor @Observable public final class ReminderStore` (`ReminderStore.swift:42-44`); injected stores + `settle` hook default 200 ms `Task.sleep` (`:47-99`, settle `:70-73`). All five mutations gate `guard canMutate` (`:167-172`: `entitlementStore.isEntitled || completionCounter.count < EntitlementStore.freemiumCap`; cap=100 `EntitlementStore.swift:52-57`). No auth-status checks inside mutations — auth resolves once in `start()`/`requestAccess()` (`:185-198, :443-453`).
- **`skipCurrentReminder()`** `:370-399`: sync entry → `guard canMutate` `:371` → `visibleReminders.first` `:372` → `incrementSkipCount` persists immediately (synchronous, `:561-568`) → nudge interrupt iOS/watchOS on first 5→6 crossing (`:374-381`, macOS `#else` increments without interrupting `:382-383`) → `updatedSkipSet` (`:552-555`, `ReminderSkipLogic.skipping` `ReminderSkip.swift:19-26`) → `Task { await settle(); if applySkipSet(updated, generation:) { await reload() } }` `:386-395`. `applySkipSet` `:604-614` discards on generation mismatch (clear race), persists, fires `onSkipSetChanged` + `onRemindersChanged`. `reload()` `:431-485` reconciles skip/excluded, prunes stale counts `:579-587`. Widget: `skipCurrentReminderImmediately()` `:411-425` (sync, no generation, still fires nudge hook but applies).
- **Skip-count store**: `SkipCountStore.swift` persists `[identifier: Int]` under key `"skipCounts"` in `AppGroup.defaults` (`:25-36`); thresholds in `SkipCountLogic` (`:9-21`); resets via `resetSkipCount` on complete (iOS `:236`, watch `:227`), delete (`:294, :302`), reschedule (`:361`), and prune-on-reload `:579-587`.
- **`rescheduleReminder(identifier:to:)`** `:344-367`: `@discardableResult … async -> Bool`; `guard canMutate` `:349`; **`#if os(watchOS) return false`** (`:350-352`, EventKit read-only on watch); else lookup, `reminder.dueDateComponents = due`, `try eventStore.save(reminder, commit: true)` (`:356-358`, via `EventKitStoring` `:472-479`), `resetSkipCount` `:361`, settle+reload `:362-363`; errors → logger + `false` `:365-366`. - **Nudge-sheet DatePicker flow (iOS)** `SingleThread/ContentView+iOS.swift` (file `#if os(iOS)`): sheet state `isShowingNudgeSheet` (`ContentView.swift:135-137`), `rescheduleDate = Date().addingTimeInterval(86400)` (`:139-141`), presented `.sheet(…onDismiss: dismissNudge)` `:275-278`; entry = card banner tap (`ContentView.swift:429-442`). `nudgeSheetContent` `ContentView+iOS.swift:59-86`: title `nudgeSheetTitle` `:64`, `DatePicker("Reschedule to", displayedComponents: nudgedReminderHasDueTime ? - **`deleteReminder(identifier:)`** `:285-307` (also `deleteCurrentReminder()` `:308-311`): `guard canMutate` `:291`; **watchOS branch** `:292-296`: local `reminders.removeAll`, `resetSkipCount`, fire-and-forget `onDeleteReminder?(identifier)` (hook `:105`; no pending set, no settle/reload); **iOS branch** `:297-307`: lookup, `eventStore.remove(reminder, commit: true)`, `resetSkipCount`, settle+reload; errors → logger + swallow `:306-307`.

## Q5: What multi-option action-presentation patterns exist today, and what are the platform constraints?

### Findings
- **`confirmationDialog` — watchOS only, 2 call sites**: card tap→Refresh/Delete (`WatchReminderView.swift:214-228`; ids `refreshButton` `:222`, `deleteButton` `:227`; flag `isShowingRefreshConfirmation` `WatchReminderViewModel.swift:47`, tap target `.accessibilityAddTraits(.isButton)` `:217`); nudge banner→Delete-only (`WatchReminderView.swift:230-243`, id `nudgeDeleteButton` `:242`, flag `:55`). No sheets/menus/pickers/alerts/swipe elsewhere in `SingleThreadWatch/`. Watch dialog actions are **addressed by label in XCUITests** — system suppresses SwiftUI ids inside the dialog (comments `SingleThreadWatchUITests/SingleThreadWatchUITests.swift:20-24`, `SingleThreadWatchUITestsFlows.swift:123-131, :144-150`).
- **`contextMenu` — iOS only, 1 site** `ContentView.swift:451-471`: View-in-Reminders (no id, matched by label) + Delete (id `deleteButton`, `.accessibilityLabel(deleteReminderAccessibility)`, styled `.tint(.red)` **not** `role: .destructive`) `:460-469`. Triggered by long-press in tests `SingleThreadUITestsFlows.swift:169,189`.
- **`swipeActions` — iOS rows**: leading Complete green `:472-479`, trailing Skip orange `:480-487`; no ids — tests match `app.buttons["Complete"]`/`["Skip"]` (`SkipNudgeUITests.swift:32-38`). Inert on macOS (shared `reminderList`).
- **Sheets — 3 (iOS + settings shared with macOS)**: settings `:267-268` (macOS `.frame(minWidth: 400, minHeight: 500)` `:602-605`), purchase `:270`, nudge sheet `:275-278` (`#if os(iOS)`). The nudge sheet is the repo's **only 3-action surface** (`ContentView+iOS.swift:59-86`).
- **`Picker`/`Menu`**: zero `Menu(` in all six targets; `Picker` only in settings sheets (`FilterSortSettingsView.swift:20`, `InterfaceSettingsView.swift:35,47`, `NotificationsSettingsView.swift:24-35` with `.pickerStyle(.menu)`, `BackgroundSettingsView.swift:31-41`). Headless pickers are tapped as **buttons** in tests (`app.buttons["appearancePicker"]` `SingleThreadUITestsAppearanceLaunchTests.swift:71`; options by label). `DatePicker` once: `ContentView+iOS.swift:66`.
- **macOS**: **no single-control multi-action affordance** — three always-visible bar buttons with keyboard shortcuts (`ContentView.swift:328-371`: Complete `c` `:330-344`, Skip `s` `:346-358`, Delete `:360-369`); only modal = settings sheet. An action menu would have no in-repo precedent.
- **Widget**: two plain `Button(intent:)`s in HStack (`NextThingWidget.swift:141-158`), `.buttonStyle(.bordered)`.
- **Destructive styling per platform**: watch dialogs use `role: .destructive` (`WatchReminderView.swift:224,239`); iOS nudge sheet `role: .destructive` (`ContentView+iOS.swift:145`); contextMenu can't use role → `.tint(.red)` (`ContentView.swift:469`); button rows `.tint(.red)` (`:364`).
- **Constraints for 2-3 actions from one control**: watch = `confirmationDialog` (sole modal; ids unreachable in dialogs → label matching); iOS = contextMenu (ids reachable) or sheet (ids reachable); macOS = no precedent; deployment targets modern (iOS 18.7/macOS 26.5/watchOS 26.5, `project.pbxproj:765,768,965`) — splits are deliberate `#if os()` conventions, not version limits.

## Cross-Cutting Observations
- **One mutation gate everywhere**: `canMutate` (entitlement OR count<100) guards all five store mutations (`ReminderStore.swift:215,291,349,371,412`); view layers additionally gate on `hasResolvedEntitlement`/`showsActionButtons`/`canDictate&&showMicrophoneButton` (iOS cluster) or `canMutate&&entitlementState` (watch).
- **AppGroup.defaults is the hub**: `@AppStorage(store:)`, typed preference structs, `UITestingSeed` persistence, watch `completionCount` sync, and the `didChangeNotification` observer all meet at the shared suite; `AppGroup.swift:20-22` fallback to `.standard` makes watchOS/simulator/preview behavior converge.
- **Both iOS test seams force `enableActionButtons = true`** (`AppViewModel.swift:291` `--ui-testing`, `:350` `--seed` after reset); watch has no such key (buttons gated only by `canMutate`).
- **Skip symbol/tint/id are invariant** across all five surfaces (`circle.slash`, `.orange`, `skipButton`); swipe + watch-dialog actions are matched **by label** in tests, everything else by identifier.
- **`calendarItemIdentifier` is the identity key** across skip counts, skip set, nudge, reschedule, delete relay, and sync payloads.
- **Nudge is a once-per-crossing interrupt** (5→6) that returns before advancing; resets ride on complete/delete/reschedule and prune-on-reload; widget skips still apply (no UI).
- **File-length discipline**: `ContentView.swift` at 716 lines is under the 650/800 budgets only via the extension split + disable header; same pattern in Core (`ReminderStore.swift` 677 lines, disable at `:8`).
