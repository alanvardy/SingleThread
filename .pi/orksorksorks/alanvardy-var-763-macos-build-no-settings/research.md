# Research Findings

Context: single app target for iOS + macOS (`SUPPORTED_PLATFORMS = "iphoneos iphonesimulator macosx"`, `project.pbxproj:772,822`), per-SDK entitlements, `#if os(...)` branches throughout. Settings is a sheet inside `ContentView`'s `NavigationStack`/`List`. Line numbers reference current source.

## Q1: Settings screen construction & presentation on both platforms

### Findings
- **Gear button** — `.overlay(alignment: .topTrailing)` at `ContentView.swift:162`; action at `ContentView.swift:163-165` snapshots the bag **before** flipping the flag: `settingsBag = makeSettingsBag()` then `isShowingSettings = true`. Accessibility: `.accessibilityLabel("Settings")` / `.accessibilityIdentifier("settingsButton")` (`ContentView.swift:172-173`).
- **Presentation state** — `@State private var isShowingSettings = false` (`ContentView.swift:256`); `@State private var settingsBag: SettingsBindings?` (`ContentView.swift:266`), doc comment `:262-265`: bag is "Recreated when the sheet opens… kept alive for the sheet's lifetime."
- **`.sheet`** — single presentation site: `.sheet(isPresented: $isShowingSettings) { settingsSheetContent }` (`ContentView.swift:244-246`); only sibling sheet is the purchase sheet (`:248-251`).
- **Dismiss resets bag** — `.onChange(of: isShowingSettings)` nils `settingsBag` when `!showing` (`ContentView.swift:236-243`), with comment "The bag is built in the gear-button action before the flag flips, so it is never nil when the sheet first renders."
- **Sheet content** — `settingsSheetContent` (`ContentView.swift:547-551`) guards `if let bag = settingsBag` then calls `settingsSheetWritebacks(bag)` (`:550`). Each of `makeSettingsBag()` / `settingsSheetContent` / `settingsSheetWritebacks` has exactly one call site (grep-verified).
- **Write-back chain** — `settingsSheetWritebacks(_:)` (`ContentView+Settings.swift:8-44`) constructs `SettingsView(bindings: bag, backgroundImage: viewModel.backgroundImage, availableLists: viewModel.store.availableLists, excludedLists: excludedListsBinding, entitlementStore: viewModel.store.entitlementStore, viewModel: SettingsViewModel())` (`:9-15`). Then chains `.onChange` observers that copy each bag value back to ContentView's `@AppStorage` properties (`:17-43`, comment at `:17-18` "write each changed value back… so settings survive relaunch").
- **iOS vs `#else` in `ContentView+Settings.swift`** — `settingsSheetWritebacks`: shared head adds 2 observers (`appearanceMode` `:19`, `textSize` `:20`); `#if os(iOS)` adds 6 more (allowsLandscape, enableActionButtons, showSwipePrompt, showUndoButton, notificationsEnabled, notificationIntervalHours — `:23-28`); `#else` is a passthrough (`:29-31`); shared tail adds 11 more (`:32-43`). Totals: iOS 19 observers, non-iOS 13. (File doc comment `:6-7` says "a single 17-modifier chain does not" type-check — actual counts are 19/13, an observed discrepancy.)
- **`makeSettingsBag()`** (`ContentView+Settings.swift:48-84`, `@MainActor` at `:48`): iOS branch (`:50-70`) passes all 19 fields; `#else` branch (`:71-83`) passes 13 — the 6 iOS-only fields silently take `SettingsBindings.init` defaults.
- **Bindings/observed objects** — `SettingsView` stores `@Bindable private var bindings` (`SettingsView.swift:149`) — the observed-object mechanism; each `NavigationLink` destination receives **slices** of the bag as individual `$bindings.X` bindings, never the whole bag (`SettingsView.swift:37-45` iOS Interface, `:47-53` non-iOS, `:59-63` Notifications, `:68-76` Reminder, `:80-88` FilterSort, `:92-98` Background, `:100` Purchase). `excludedLists` arrives separately as `@Binding` (`:146-147`) routed from `excludedListsBinding` (`ContentView.swift:141-146` → `viewModel.store.excludedListTitles` / `viewModel.setExcludedListTitles`).
- **Done toolbar item** — not platform-gated (`SettingsView.swift:128-136`): `.toolbar { ToolbarItem(placement: .confirmationAction) { Button("Done") { dismiss() } .accessibilityIdentifier("settingsDoneButton") } }`. `dismiss` is `@Environment(\.dismiss)` (`:141-143`).
- **Sheet root modifiers** — `.navigationTitle("Settings")` (`:126`), `.modifier(TextSizeModifier(textSize: bindings.textSize))` (`:138`) — text size read from the bag, not ContentView.

## Q2: Compile-time platform conditionals on the settings screen

### Findings
- **No `#elseif` anywhere in settings files; no `#if os(macOS)` inside any settings view.** macOS behavior is expressed exclusively through `#else` of iOS-only `#if`s and through `#if os(iOS) || os(macOS)` dual guards.
- **`SettingsView.swift`** — 2 `#if os(iOS)` blocks:
  - `:36-45` vs `:47-53`: Interface `NavigationLink` passes 7 bindings on iOS, **3 on macOS** (`appearanceMode`, `textSize`, `showMicrophoneButton` + `viewModel`). Row id `settingsInterfaceRow` (:55) identical on both.
  - `:57-64`: **Notifications link is iOS-only** (no `#else`); on macOS the row is entirely absent.
  - Reminder, Filtering & Sorting, Background, Purchase, Privacy, About rows: unconditional, present on both platforms (`:66-123`).
- **`SettingsBindings.swift`** — **zero conditionals**. All 19 properties declared unconditionally because "the compiler does not support `#if` directives inside a parameter list" (doc comment `:8-10`): "On macOS they are harmless: the values are simply never wired or read." Defaults at `:15-33`; note the comment enumerates only `allowsLandscape`, `enableActionButtons`, `showUndoButton` — `showSwipePrompt` is also iOS-only but not listed.
- **`SettingsViewModel.swift`** — `import WidgetKit` under `#if os(iOS) || os(macOS)` (`:2`); `allowsLandscapeChanged(_:)` → `AppDelegate.applyLock` is **iOS-only** (`:12-16`, absent on macOS); `showPreferenceChanged()` → `WidgetCenter.shared.reloadAllTimelines()` is iOS+macOS (`:18-24`).
- **`InterfaceSettingsView.swift`** — most-gated sub-view, 7 `#if os(iOS)` blocks: `@Binding var` decls for `allowsLandscape` (:14), `enableActionButtons` (:20), `showSwipePrompt` (:24), `showUndoButton` (:28); body toggles "Allow landscape" (:49-60 incl. `.onChange` → viewModel), "Show action buttons"/"Show swipe prompt"/"Show undo button" (:62-80); Preview init `#else` (:95-104). "Show microphone" toggle is **both platforms** (:67-74 in linear numbering). Doc comment `:3-4`: "platform-gated orientation + action button toggles."
- **`NotificationsSettingsView.swift`** — compiles unconditionally (its own comment `:4-5`: "The NavigationLink into this view is `#if os(iOS)` gated in `SettingsView`, so it is only reachable on iOS even though the file compiles on all platforms"); on macOS it is dead code.
- **`ReminderSettingsView.swift`** — all 5 toggles on both platforms; `#if os(iOS) || os(macOS)` `.onChange` → `showPreferenceChanged()` for `showDate` (:27-30), `showRecurrence` (:40-43), `showAlarms` (:49-52). `showList`/`showCompletionGlow` have no reload hook.
- **`ContentView+Settings.swift`** — 2 `#if os(iOS)` blocks: write-back chain (:21-32, `#else` at :29-31) and bag construction (:50-83, `#else` at :71-83 with 14 args per Q1; note Q4 counted 13 shared fields crossing `:32-43`).
- **Zero conditionals**: `BackgroundSettingsView.swift`, `ExcludedListsView.swift`, `FilterSortSettingsView.swift`, `PrivacySettingsView.swift`, `PrivacySettingsContent.swift`, `PurchaseSettingsView.swift`.
- **macOS-intentionally-omitted inventory**: Notifications link (`SettingsView.swift:57`); Interface rows Allow landscape / action buttons / swipe prompt / undo (`InterfaceSettingsView.swift:49,62`); backing `@AppStorage` keys `allowsLandscape:79`, `enableActionButtons:96`, `showSwipePrompt:101`, `showUndoButton:106`, `notificationsEnabled:109`, `notificationIntervalHours:112` (all inside `#if os(iOS)`, `ContentView.swift`); `AppViewModel` notification keys `:93-95`.
- **Explicit why-on-macOS comments**: `SettingsBindings.swift:8-10`, `NotificationsSettingsView.swift:4-5`, `InterfaceSettingsView.swift:3-4`. No comment states "macOS lacks feature X" for the Interface toggles or Notifications — omissions are implicit.
- **Shared dependencies with conditionals**: `Color+CrossPlatform.swift:3,16` (macOS NSColor systemBackground), `BackgroundImageStore.swift:5,244` (`#elseif os(macOS)` — UIImage vs NSImage decode; drives Background screen "Refresh wallpaper"), `CodeSpanFormatter.swift:143,146` (`#elseif canImport(UIKit/AppKit)`; `:147` note "macOS has no `.secondarySystemBackground`").

## Q3: Platform entry point & window lifecycle

### Findings
- **Single multiplatform `@main`** — `SingleThreadApp.swift:9-36`. `body` is **not** os-split: one `WindowGroup { ContentView(viewModel: viewModel.contentViewModel, appViewModel: viewModel) }` (`:19-23`); no `.commands`, no `MenuBarExtra`, no window-style modifiers.
- **Delegate adaptor split** — `@UIApplicationDelegateAdaptor(AppDelegate.self)` under `#if os(iOS)` (`:27-30`); `@NSApplicationDelegateAdaptor(MacAppDelegate.self)` under `#if os(macOS)` (`:31-34`).
- **`AppDelegate.swift`** — both delegates in one file. iOS `AppDelegate` (`:10-60`): `applyAppearance` sets `window.overrideUserInterfaceStyle` (`:15-28`), `applyLock` orientation mask (`:31-44`), `applicationDidBecomeActive` re-applies appearance (`:45-53`), `supportedInterfaceOrientationsFor` reads `allowsLandscape` from `UserDefaults.standard` (`:55-60`). macOS `MacAppDelegate` (`:67-90`): only sets `window.appearance = mode.appKitAppearance` over `NSApp.windows` (`:72-76`); `applicationDidFinishLaunching` (`:78-80`) + `applicationDidBecomeActive` (`:82-84`) → `applyLaunchAppearance()` (`:86-90`). **No orientation / notifications / connectivity code on macOS.**
- **No dedicated Settings scene** — repo-wide grep for `WindowGroup` finds only `SingleThreadApp.swift:20` and `SingleThreadWatch/SingleThreadWatchApp.swift:14`. Settings is a `.sheet` only.
- **Sheet sizing** — **no explicit sizing anywhere**: zero `presentationDetents` / `preferredContentSize` matches in the repo; no `.frame` on the sheet (repo `.frame(` hits are list-row/card centering only). Settings sheet relies on SDK-default container sizing on both platforms.
- **Root wiring divergence** — `ContentView.init` stores `appViewModel` **only on iOS** (`ContentView.swift:22-27`, property at `:133-134`); on macOS the argument is accepted and discarded. `ContentView.body` (`:137-206`): `BackgroundPhotoLayer` iOS-only (`:149-153`); undo overlay iOS-only (`:178-190`); notifications-status overlay iOS-only (`:197-203`). **macOS-only**: `actionButtons` cluster with `.keyboardShortcut("c"/"s")` (`:294-334`, rendered in `bottomBar` at `:601`); macOS mic branch is plain `micButton` (`#else` at `:625-644`); "Open Settings" deep-link button iOS-only (`:647-648`).
- **Scene-phase routing** — `.onChange(of: scenePhase)` (`:212-213`) → `handleScenePhaseChange` (`:575-594`): `.background`/`.active` schedule/cancel notifications **only under `#if os(iOS)`** (`:577-586`); `viewModel.dictation.refreshAuthorizationStatus()` runs on both (`:589`).
- **Info.plist** — fully generated (`GENERATE_INFOPLIST_FILE = YES`, `project.pbxproj:748,798`); no physical `Info.plist` on the app target (only `SingleThreadWidget/Info.plist`). All `INFOPLIST_KEY_UI*` keys are iOS-SDK-scoped (`[sdk=iphoneos*]`/`[sdk=iphonesimulator*]`, `project.pbxproj:752-759,802-809`); **no `[sdk=macosx*]` Info.plist keys exist**. macOS window behavior is driven purely by SwiftUI code (`NSApp.windows`, `WindowGroup`).

## Q4: Runtime state at render time

### Findings
- **Six constructor inputs** to `SettingsView` (`ContentView+Settings.swift:9-15`): (1) `bindings` bag (fresh from `makeSettingsBag()`, `@State `settingsBag`` at `ContentView.swift:266`); (2) `backgroundImage: BackgroundImageStore` (built in `AppViewModel.init` at `AppViewModel.swift:81`); (3) `availableLists: [String]` (`viewModel.store.availableLists`, `ReminderStore.swift:64`); (4) `excludedLists: Binding<Set<String>>` (`excludedListsBinding`, `ContentView.swift:141-146` → `store.excludedListTitles` `ReminderStore.swift:57`, `set` → `ContentViewModel.setExcludedListTitles` `:163-164`); (5) `entitlementStore` (`store.entitlementStore`, `ReminderStore.swift:110`, default `EntitlementStore()` at `:31`); (6) `viewModel: SettingsViewModel()` constructed inline per sheet build (`:14`).
- **Bag timing invariant** — bag built synchronously in gear action before flag flips (`ContentView.swift:164-165`); `settingsSheetContent` guards `if let bag` (`:549`); `.onChange` nils on dismiss (`:236-243`). Comment states bag is "never nil when the sheet first renders."
- **`@AppStorage` scalars** — all have inline defaults (`ContentView.swift:72-133`): `appearanceMode=.system`, `textSize=.system`, `showMicrophoneButton=true`, `backgroundEnabled=true` (`.standard`), `backgroundFadePercent=50`, `backgroundPinned=false` (`.standard`), `showUndatedReminders=false` (AppGroup), `sortOption=.priority` (AppGroup, via `SortOption.defaultsKey`), `showDate=true`, `showList=false`, `showRecurrence=true`, `showAlarms=true`, `showCompletionGlow=true` (AppGroup). `SettingsBindings.init` mirrors every default (`SettingsBindings.swift:15-33`). Missing persisted keys fall back to defaults; nothing can be nil/blank.
- **`settingsSheetWritebacks` platform split** — identical `SettingsView` args both platforms; only the 6 iOS-only `.onChange` wirings differ (`ContentView+Settings.swift:21-31`). Net: macOS constructs the **same settings List**, minus iOS-only rows.
- **`EntitlementStore` on macOS** — no `#if` gating in `EntitlementStore.swift`; default init starts `Transaction.updates` observation + `refreshEntitlement()` (`EntitlementStore.swift:40-44,70-90`). `isEntitled` starts `false` until async StoreKit refresh lands (`:48`) — identical deferred-value latency on iOS and macOS; flips the Purchase row label `Unlock` ⇄ `Manage Purchase` (`SettingsView.swift:139-140`), does not blank the sheet.
- **Empty-input analysis (macOS-specific?) — answer: no render-time input is absent on macOS only.**
  - `availableLists`/`excludedListTitles` default `[]` (`ReminderStore.swift:57,64`) and are populated only inside `reload()` (`:398-402`, `:560`), which runs only after `authorizationStatus == .fullAccess` (`:168-174,434-441`). Before EventKit access resolves on macOS, both are `[]` — **but** the settings `List` never iterates them; they feed only the nested `ExcludedListsView` (`ForEach(availableLists, …)` at `ExcludedListsView.swift:17-19`), so worst case the Excluded-Lists sub-menu renders zero toggles. Identical empty-until-granted state exists on iOS (same `requestFullAccessToReminders` grant path, `ReminderStore.swift:434-449`).
  - `backgroundImage`/`entitlementStore` are non-optional `let` fields — never nil.
  - `SettingsViewModel` is stateless, freshly allocated (`SettingsViewModel.swift:7-27`).
  - No macOS-only `#if` gates the settings body content rows (`SettingsView.swift:66-123` unconditional).
  - Conclusion (documentarian, not diagnostic): the data/initialization layer does not explain a macOS-only blank; any such behavior would live in the host/windowing layer, out of scope for this file set.

## Cross-Cutting Observations
- **One bag, one sheet, two flavors**: the entire settings UI is single-sourced from `ContentView+Settings.swift` (bag build + write-back chain) and `SettingsView.swift` (row list); platform variance is concentrated at exactly four `#if os(iOS)` sites in the sheet path (`ContentView+Settings.swift:21,50`, `SettingsView.swift:36,57`) — everything else is shared.
- **iOS-only prefs are "never wired or read" on macOS** (`SettingsBindings.swift:8-10`) — the bag is the documented mechanism that lets iOS-only config compile unconditionally: `#if` cannot appear in an init parameter list, so iOS-only fields exist with defaults and are simply never copied from/into `@AppStorage` on macOS (`ContentView+Settings.swift:71-83`, `:29-31`).
- **MacOS settings rows are a strict subset of iOS**: macOS loses Notifications row and 4 Interface toggles; all other 8 rows identical.
- **macOS shares the iOS shell**: one `WindowGroup`, one `ContentView`; only the delegate adaptor and appearance application differ. `appViewModel` is accepted-and-discarded on macOS (`ContentView.swift:22-27`).
- **Deferred/empty-by-design inputs**: `availableLists`/`excludedListTitles` are `[]` until first `.fullAccess` reload (both platforms); `isEntitled` `false` until StoreKit refresh (both platforms). None blank the sheet body.
- **macOS build is IAP-capable, widget/notification-free**: StoreKit runs (sandboxed, `com.apple.developer.in-app-purchases`, `Products.storekit` scheme ref); WidgetKit compiles and reload timelines are invoked but no widget is embedded; `UserNotifications` is compile-gated off macOS entirely.
- **Entitlements split mirrors platform features**: macOS sandbox file has app-groups + IAP + mic + calendars; iOS file has app-groups only (signing/entitlements like IAP on iOS are implicit, not in this file).
- **Test seams write real UserDefaults**: `--ui-testing`/`--seed` persist `enableActionButtons=true` to `UserDefaults.standard` (`AppViewModel.swift:252,298`) — a documented test-simulator trade-off; every persisted value round-trips through `AppGroup.defaults` or `.standard` per target seam.

## Open Areas
- **No macOS UI test coverage of settings**: macOS test runs are unit-only (`scripts/test.sh:288-292`, `Makefile mac-test`); no macOS UI-test target exists, so macOS settings rendering is covered only by SwiftUI-body string assertions compiled under `#else`.
- **Sheet sizing under macOS `WindowGroup`**: repo authors no `presentationDetents`/`preferredContentSize`/frame for the sheet; actual runtime container sizing is SDK-default behavior (framework territory, not observable from source).
- **Settings unit tests are shape-dependent**: `String(describing: view.body).contains(...)` assertions (e.g. `SettingsViewTests.swift:46-51`) can pass/fail on body-description changes independent of UI behavior.
- **Comment drift**: `ContentView+Settings.swift:6-7` mentions a "17-modifier chain" while the actual write-back observer counts are 19 (iOS) / 13 (non-iOS); `SettingsBindings.swift:8-10` enumerates 3 iOS-only fields while `showSwipePrompt` is also iOS-only.
- **CI shard gap**: three notifications/settings UI classes run only under the local whole-target invocation, not in CI's `-only-testing:` shards.
- **What could not be answered from code**: whether the mac app's EventKit reminder access is reliably `.fullAccess` at first render on a fresh machine (depends on OS-level TCC, not source); runtime StoreKit resolution on the desktop target (decided at runtime, not by `#if`).
