# Research Findings

## Q1: How is the iOS reschedule sheet constructed and presented?

### Findings
- `struct RescheduleSheet: View` (`SingleThread/RescheduleSheet.swift:8`) is a plain SwiftUI view, inputs: `reminder: EKReminder?`, `onReschedule: (DateComponents) async -> Bool`, `onCancel: () -> Void`, `nudgeMessage: String?` (:11–14). Doc comment (:4–7): "shared by the skip-nudge sheet and the action menu. Callers wrap it in a `NavigationStack` and provide Cancel in their own toolbar." The sheet itself has no toolbar/stack wrapper.
- `body` (:16–50): `VStack(alignment: .leading, spacing: 16)` containing: (1) optional `Text(nudgeMessage)` `.font(.headline)` id `"nudgeSheetTitle"` (:18–22); (2) `DatePicker("Reschedule to", selection: $date, displayedComponents: ...)` id `"rescheduleDatePicker"` (:24–29); (3) `HStack { Spacer(); Button { Label("Reschedule", systemImage: "calendar.badge.plus") } }` id `"rescheduleConfirmButton"` (:31–45) — Spacer pushes the button to the right edge; the button converts the picker date via `Calendar.current.dateComponents(Self.dateComponentsMask(...), from: date)` (:34–36), awaits `onReschedule(components)` then closes on `true` (:37–41). Outer `.padding().frame(maxWidth: .infinity, alignment: .leading)` (:48–49).
- Tailoring helpers: `hasDueTime` (:54–57) — `reminder.dueDateComponents.hour != nil`; `displayedComponents` (:60–62) — `[.date, .hourAndMinute]` vs `[.date]`; `dateComponentsMask` (:65–67) — `[.year,.month,.day,.hour,.minute]` vs `[.year,.month,.day]`. `@State date` defaults to tomorrow (:72).
- **Caller 1 — nudge flow** (`SingleThread/ContentView+iOS.swift`, `#if os(iOS)`): `nudgeSheetContent` (:59) wraps `NavigationStack { VStack(alignment: .leading, spacing: 16) { RescheduleSheet(...) } }` (:60–80) with `nudgeMessage: "This reminder keeps coming back."`, `onReschedule` → `viewModel.rescheduleNudgedReminder(to: components)`; Cancel is `ToolbarItem(placement: .cancellationAction) { Button("Cancel") ... }` (:75–78). Extra actions below: `nudgeViewInRemindersButton` (:96–109) and `nudgeDeleteButton` (`Button(role: .destructive)`) (:112–121). Trigger: `ContentView.swift:409` sets `isShowingNudgeSheet = true`, wired as `onNudgeTap` (:422) gated by `showNudge: viewModel.isNudged(...)` (:421); nudge identifier set by `store.onSkipNudgeRequested` (`ContentViewModel.swift:34`); `isNudged` compares it (`ContentViewModel.swift:232–233`).
- **Caller 2 — action-menu flow** (`SingleThread/ContentView+ActionMenu.swift`): opens from the bottom-bar `skipButton`'s `confirmationDialog` "Reschedule" button (:50–52) or the macOS menu (:117–118); `actionMenuRescheduleSheet` (:179–197) = `NavigationStack { RescheduleSheet(reminder: actionMenuRescheduleReminder, onReschedule: → viewModel.rescheduleReminder(identifier:, to:), nudgeMessage: nil) }` + toolbar Cancel (:191–195). `actionMenuRescheduleReminder` falls back to `store.visibleReminders.first` (:63–70; macOS :176–182).
- **Presentation**: `ContentView.swift:115` `isShowingNudgeSheet`, `:118` `isShowingRescheduleSheet`; `.sheet(isPresented:)` chain (:290–303) — reschedule: `.presentationDetents([.height(320)])` (:295–297, iOS+macOS unconditional); nudge: `.presentationDetents([.height(420)])` + `onDismiss` (:300–302, `#if os(iOS)`).
- **Data flow on confirm**: both flows → `ContentViewModel` → `ReminderStore.rescheduleReminder(identifier:, to:)` (`SingleThreadCore/Sources/SingleThreadCore/ReminderStore.swift:356`), guards `canMutate`, sets `dueDateComponents`, saves, resets skip count (doc :350–355). Nudge flow additionally clears `nudgeIdentifier` on success (`ContentViewModel.swift:251–257`).

## Q2: How is the watchOS reschedule sheet constructed and presented?

### Findings
- Sheet: `private func actionMenuRescheduleSheet() -> some View` (`SingleThreadWatch/WatchReminderView.swift:290`) with `@Bindable var viewModel = viewModel` (:291). Doc (:285–289): kept out of `reminderCard` to stay under SwiftLint's 50-line body limit.
- Root `NavigationStack { VStack(spacing: 12) { ... } .toolbar { ToolbarItem(placement: .cancellationAction) { Button("Cancel") ... } } }` (:292–316). Contents (:293–311): `DatePicker("Reschedule to", selection: $viewModel.rescheduleDate, displayedComponents: [.date])` (:294–296, date-only, **no accessibilityIdentifier**); `Button("Reschedule")` id `"rescheduleConfirmButton"` (:297–311). Handler (:298–308): `Calendar.current.dateComponents([.year,.month,.day], ...)` → if `store.visibleReminders.first?.calendarItemIdentifier` exists: `Task { await store.rescheduleReminder(...); isShowingRescheduleSheet = false }`, else just closes.
- Placement: `.sheet(isPresented: $viewModel.isShowingRescheduleSheet) { actionMenuRescheduleSheet() }` chained on `reminderCard`'s outer `VStack` after the action-menu `confirmationDialog("Reminder", isPresented: $viewModel.isShowingActionMenu)` (:277–282). Opener: `actionMenuDialogButtons` "Reschedule" sets `isShowingActionMenu = false; isShowingRescheduleSheet = true` (:211–217). Menu gated by `canShowActionMenu` (:81–85): `showEnableActionButtonsState.isEnabled && store.canMutate && store.visibleReminders.first != nil`.
- `reminderCard(:238)` = `VStack(alignment: .leading, spacing: 6)` with `ScrollView`; rendered from `reminderContent` (:89) at :108 (:93 for completion-glow ghost).
- View-model state (`SingleThreadWatch/WatchReminderViewModel.swift`): `isShowingRescheduleSheet = false` (:71), `rescheduleDate = Date().addingTimeInterval(86400)` — defaults to tomorrow (:74), `isShowingActionMenu` (:66). VM built by `WatchAppViewModel.reminderViewModel` (`WatchAppViewModel.swift:94`).
- **Confirm relays, doesn't save locally on watch**: `ReminderStore.rescheduleReminder` watch branch fires `onRescheduleReminder?(identifier, due)` and returns true (`ReminderStore.swift:355–361`); wired via `wireStoreSyncHooks` (`WatchAppViewModel.swift:220–222`) → `SkippedReminderSyncService.requestRescheduleReminder` sends `WCSession.sendMessage` with plist-safe `[String: Int]` components (`SkippedReminderSyncService.swift:268–290`); phone receives at :309–319 → `AppViewModel.swift:392–395` → actual EventKit save on iOS.

## Q3: iOS button and label styling conventions

### Findings
- Button styles: `.borderedProminent` = primary/confirm (`ReminderCardView.swift:164` nudge banner + `.tint(.white)` :165; `:212` swipe Dismiss + scheme-adaptive tint :213; `PurchaseSettingsView.swift:113`); `.bordered` = secondary (`PurchaseSettingsView.swift:89`); `.borderless` via shared `singleThreadButton()` modifier (`SingleThread/SingleThreadButtonModifier.swift:12, :20–23`) for icon-only controls (`ContentView.swift:187,203,534`; `ContentView+ActionMenu.swift:105,146,162`); `.plain` + hand-drawn plate for upgrade CTA (`PurchaseSettingsView.swift:191`).
- Sheet/toolbar confirm buttons use **no explicit buttonStyle — the platform default** (`RescheduleSheet.swift:38–46`, `SettingsView.swift:162`, `PurchaseSettingsView.swift:210`).
- Tints/roles: semantic action tints `.tint(.red/.green/.orange)` (`ContentView.swift:450,459,467`); `role: .destructive` for destructive menu/sheet items (`ContentView+ActionMenu.swift:55,120`; `ContentView+iOS.swift:113`). Scheme-adaptive colors centralized in `SingleThread/CardPlate.swift:26–44`.
- Labels: `Label(title, systemImage:)` title+icon pattern (`ContentView.swift:440,457,465`; `ContentView+ActionMenu.swift:39,100,125,141,157`; `PurchaseSettingsView.swift:21,182`; `AboutView.swift:24`); `.labelStyle(.iconOnly)` (`ContentView+ActionMenu.swift:40,101,126,142,158`); settings row pattern `Label { VStack { Text(title); SettingsCaption } } icon:` (`SingleThread/SettingsCaption.swift:24–35`). `SettingsCaption` = `.font(.caption)` + `.foregroundStyle(.secondary)` (:13–14). `.font(.headline)` for sheet/menu titles (`RescheduleSheet.swift:20`, `PurchaseSettingsView.swift:97,183`); `.font(.caption.bold())` small button text (`ReminderCardView.swift:159,207`).
- Centering/alignment: sheets are left-aligned `VStack(alignment: .leading)`, `.padding()`, `.frame(maxWidth: .infinity, alignment: .leading)` (`RescheduleSheet.swift:17,49`); confirm right-aligned via `HStack { Spacer(); Button }` (`RescheduleSheet.swift:37–46`); centered content via `.frame(maxWidth: .infinity, minHeight: …, alignment: .center)` for empty states (`ContentView.swift:381,394`) and `.multilineTextAlignment(.center)` (:638,648,690); right-edge `Spacer()` for full-width rows (`PurchaseSettingsView.swift:88,133,185`).
- Toolbar convention: Cancel via `.cancellationAction`; confirm via the sheet's own button (SettingsView/PurchaseSettingsView put a `.confirmationAction` "Done" in the toolbar instead — `SettingsView.swift:161–162`, `PurchaseSettingsView.swift:209–210`; `RescheduleSheet` carries its own confirm).

## Q4: watchOS button and label styling conventions

### Findings
- All watch UI construction is in one file (`SingleThreadWatch/WatchReminderView.swift`); `SingleThreadWatchApp.swift:10–12` mounts it in a `WindowGroup`; view models are logic-only.
- Button styles (5 distinct): (1) icon-only tinted action buttons — `Button { Label(..., systemImage:).labelStyle(.iconOnly) }` with `.tint(.green)` (:137) / `.tint(.orange)` (:152), each with `.accessibilityLabel(...)`, `.accessibilityIdentifier("completeButton"/"skipButton")`, `.accessibilityAddTraits(.isButton)` (:138–140, :153–155) — the only two tinted buttons; (2) plain text buttons with no styling mods — refresh (:202–206), menu Skip/Reschedule (:212–215); (3) `role: .destructive` delete buttons (:219, :263–266) — only role variant used; (4) reschedule-sheet confirm `Button("Reschedule")` with only `.accessibilityIdentifier("rescheduleConfirmButton")` (:297–311); (5) toolbar `Button("Cancel")` in `.cancellationAction` (:314–318).
- Labels: `Label(..., systemImage:)` + `.labelStyle(.iconOnly)` inside buttons only (:134–138, :149–153); `Label(SharedStrings.skipNudgeTitle, systemImage: "exclamationmark.bubble").font(.caption)` nudge banner (:258–259); `.font(.caption2)` + `.foregroundStyle(.secondary)` inline chips (:346–353). Shared copy via `SharedStrings.*` from SingleThreadCore.
- Text: `.font(.headline)` titles (:327, :333, :179, :165); `Text(due, style: .date).font(.caption)` (:336–338); secondary detail lines `.font(.caption2).foregroundStyle(.secondary)` (:342–343, :348, :353, :358, :230–231, :168–170); the only non-secondary color is the priority marker (:328) via `priorityColor` map (:364–369).
- Centering: implicit — `allDoneState`/`noRemindersState`/`upgradeOniPhonePrompt` wrap children in default-centered `VStack(spacing:)` with `.multilineTextAlignment(.center)` on wrapped text and `.frame(maxWidth: .infinity)` (:163–173, :177–181, :225–232). Card/details are `.leading`-aligned (`VStack(alignment: .leading, spacing: 6)` :240, :323). Reschedule sheet body is `VStack(spacing: 12)` + `.padding()` (:302–313).

## Q5: `EventKit.DatePicker` observed API surface and layout behavior

### Findings
- Exactly 2 usage sites in repo, same constructor shape: `DatePicker("Reschedule to", selection: <Binding<Date>>, displayedComponents: <Components>)` — iOS `SingleThread/RescheduleSheet.swift:24–30` (label string, selection `$date`, computed components, `.accessibilityIdentifier("rescheduleDatePicker")`); watch `SingleThreadWatch/WatchReminderView.swift:294–298` (label string, selection `$viewModel.rescheduleDate`, hardcoded `[.date]`, no a11y id).
- **`DatePicker` is a SwiftUI Swift-module control, not EventKit** — the sheets' `import EventKit` is for `EKReminder`/`DateComponents`. SDK metadata (`/Applications/Xcode.app/.../iPhoneOS.sdk/System/Library/Frameworks/SwiftUI.framework/Modules/SwiftUI.swiftmodule/arm64e-apple-ios.swiftinterface:18635`): `public struct DatePicker<Label> : SwiftUICore.View` (iOS 13.0+, watchOS 10.0+, macOS 10.15+); `body` is an `@_opaqueReturnTypeOf` opaque type — no implementation exposed.
- Constructors (:18650–18704): selection-only `init(selection: Binding<Foundation.Date>, displayedComponents: Components = [.hourAndMinute, .date], @ViewBuilder label: () -> Label)`; three range variants; `Label == Text` variants with `_ titleKey`/`_ titleResource`; plus `@_disfavoredOverload init<S>(_ title: S, …) where S : Swift.StringProtocol` — the overload both repo call sites hit. **Default `displayedComponents` is `[.hourAndMinute, .date]`.**
- `DatePickerComponents : Swift.OptionSet, Swift.Sendable` (:18708): literals `.hourAndMinute`, `.date`, and watchOS-only `.hourMinuteAndSecond` (not on iOS/macOS). `.datePickerStyle(.wheel)` available iOS 13.0+/watchOS 10.0+ (`WheelDatePickerStyle` :16381–16389).
- No source or layout docs in repo or SwiftPM caches; layout behavior exists only as compiled `.swiftdoc` prose ("Creates an instance that selects a `Date`…", `defaultWheelPickerItemHeight`). Actual rendering is platform-opaque — the label's visual position relative to the picker is not knowable from the SDK metadata.

## Cross-Cutting Observations

- **Two near-identical but independent implementations**: both are date-only-by-default sheets with label "Reschedule to", a confirm "Reschedule" button, Cancel in a `NavigationStack` toolbar — but iOS's confirm is `Label("Reschedule", systemImage: "calendar.badge.plus")` in a `Spacer()` HStack (right-aligned) while watchOS's is a plain `Button("Reschedule")` in a default-centered `VStack(spacing: 12)`. Neither currently centers the label+picker pair; on iOS the picker is left-aligned full-width, on watch it's in a centered VStack but with `.leading`-style layout absent.
- **iOS confirm button intentionally keeps native chrome**: the existing test `rescheduleSheetTextButtonsKeepNativeChrome` (`SingleThreadTests.swift:142–151`) pins that the sheet does NOT use `singleThreadButton()` (the `.borderless` modifier) and contains "Cancel" — a styling change to the confirm button may need to update this test if it switches modifier.
- **Watch strings are hardcoded, not shared**: `Button("Reschedule")` and `DatePicker("Reschedule to")` on watch are raw strings, whereas iOS uses the same raw strings too (both in `Localizable.xcstrings` extraction). `SharedStrings.*` is used for recurring copy but not these.
- **Both defaults default to tomorrow**: iOS `@State date = Date().addingTimeInterval(86400)` (`RescheduleSheet.swift:72`); watch `var rescheduleDate = Date().addingTimeInterval(86400)` (`WatchReminderViewModel.swift:74`).
- **iOS sheet is shared by two callers** (nudge + action menu) and supports a due-time (`hasDueTime`) variant; the watch sheet is bespoke, date-only, and its confirm merely relays to the paired phone via `onRescheduleReminder`.

## Open Areas

- **Ticket scope (iOS vs watchOS) is unstated** — both dialogs match the description verbatim; the design artifact must pin this.
- `DatePicker` label/picker spatial layout is platform-opaque (compiled `body`, no source/docs in repo or caches) — "label and date picker next to each other" may require verifying what the control renders on-device before assuming the change is purely layout.
- No test constructs the iOS `RescheduleSheet` view or the watch sheet, so current styling behavior is only pinned by one description-string assertion (`SingleThreadTests.swift:148–150`).
- macOS is an additional consumer of the iOS `RescheduleSheet` (action-menu path is iOS+macOS, `ContentView.swift:295–297` unconditional) — any iOS change also affects the macOS menu flow, which has its own chrome tests (`MacOSActionButtonChromeTests.swift`).
