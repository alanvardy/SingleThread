## Q1: Settings data flow on iOS vs macOS

### Findings

- **Three-layer field definition.** Layer 1: every setting is an `@AppStorage` property on `ContentView` — e.g. `appearanceMode` (`ContentView.swift:72`), `textSize` (`:75`), `showMicrophoneButton` (`:83`), background trio with explicit `store: .standard` (`:86,:89,:92`), `showUndatedReminders` (`store: AppGroup.defaults`, `:115`), `sortOption` (`:118`, key const `SortOption.defaultsKey = "sortOption"` — `SingleThreadCore/Sources/SingleThreadCore/SortOption.swift:18`), and the five `showDate`/`showList`/`showRecurrence`/`showAlarms`/`showCompletionGlow` (`store: AppGroup.defaults`, `ContentView.swift:121,124,127,129,132`).
- **Eight fields persist to `AppGroup.defaults`:** `enableActionButtons` (iOS-only), `showUndatedReminders`, `sortOption`, `showDate`, `showList`, `showRecurrence`, `showAlarms`, `showCompletionGlow` — `ContentView.swift:96,115,118,121,124,127,129,132`. Everything else falls to `UserDefaults.standard` (explicitly for the background trio, `:86,:89,:92`; by `@AppStorage` default otherwise).
- **Six iOS-only fields, gated identically in three places:** declarations under `#if os(iOS)` (`allowsLandscape` :79, `enableActionButtons` :96, `showSwipePrompt` :101, `showUndoButton` :106, `notificationsEnabled` :109, `notificationIntervalHours` :112 — block `ContentView.swift:78-113`); write-backs `.onChange(of: bag.X)` under `#if os(iOS)` (`ContentView+Settings.swift:23-28`), with the macOS branch a bare passthrough `let withIOSPreferences = withAppearance` (`:30`); bag construction full 19-arg on iOS (`ContentView+Settings.swift:51-70`) vs 13-arg on macOS (`:72-85`). `AppViewModel.NotificationKeys` constants `enabled`/`intervalHours` live at `AppViewModel.swift:52-55`, read via `UserDefaults.standard` (`:83,:87`).
- **Layer 2: in-memory bag.** `SettingsBindings` is `@MainActor @Observable final class` (`SettingsBindings.swift:18`) with a 19-parameter init with defaults (`:21-61`) and 19 plain vars (`:64-82`). Header comment `SettingsBindings.swift:1-16`: the bag "mirrors the @AppStorage defaults from ContentView exactly"; `excludedLists` deliberately not a bag property (passed as separate `Binding<Set<String>>`); the six iOS-only keys are declared unconditionally because "the compiler does not support `#if` directives inside a parameter list", and on macOS "the values are simply never wired or read".
- **Layer 3: `@Binding` into subscreens.** `SettingsView` holds `@Bindable private var bindings: SettingsBindings` (`SettingsView.swift:178`) and passes `$bindings.X` — `InterfaceSettingsView` (`SettingsView.swift:41-49` iOS / `:51-55` macOS), `ReminderSettingsView` (`:78-87`), `FilterSortSettingsView` (`:93-105`), `BackgroundSettingsView` (`:106-120`). Controls edit bindings, e.g. `Picker(selection: $appearanceMode)` (`InterfaceSettingsView.swift:35`), `Toggle(isOn: $enableActionButtons)` (`:87`).
- **Write-back chain to persistence.** Gear button: `settingsBag = makeSettingsBag(); isShowingSettings = true` (`ContentView.swift:196-197`); sheet presents `settingsSheetContent` (`:294-295`, built at `:575-585`); bag is single-instance per presentation and nilled on dismiss so a fresh one is built each open (`:286-291, :336`). `settingsSheetWritebacks(_:)` (`ContentView+Settings.swift:8-43`) wraps `SettingsView` in `.onChange(of: bag.X) { _, new in X = new }` — the assignment hits the `@AppStorage` setter, which writes to that property's `store:` suite. The bag itself is never persisted; comments at `ContentView.swift:328-335` and `ContentView+Settings.swift:13-16` document it stages values so edits don't snap back across `body` re-evaluations.
- **Independent post-write reactions** in `ContentView.body`: `backgroundPinned` → `setBackgroundPinned`, `showUndatedReminders` → `handleShowUndatedReminders`, `sortOption` → `handleSortOption`, `appearanceMode` → `handleAppearanceMode`, `notificationsEnabled` → `handleNotificationsEnabledChange` (`ContentView.swift:268-282`); handlers in `ContentViewModel.swift:121-133` (store reload/setSortOption; appearance dispatch `#if os(iOS)` `AppDelegate.applyAppearance` / `#elseif os(macOS)` `MacAppDelegate.applyAppearance`).
- **Side effects fired from subscreens:** `allowsLandscape` `.onChange` → `viewModel.allowsLandscapeChanged` → `AppDelegate.applyLock` (iOS only) — `InterfaceSettingsView.swift:59-73`, `SettingsViewModel.swift:12-16`, `AppDelegate.swift:31-35`; `showDate`/`showRecurrence`/`showAlarms` toggles → `viewModel.showPreferenceChanged()` → `WidgetCenter.shared.reloadAllTimelines()` — `ReminderSettingsView.swift:34-81`, `SettingsViewModel.swift:18-24` (iOS + macOS).
- **`AppGroup` wrapper:** `suiteName = "group.app.alanvardy.SingleThread"` (`AppGroup.swift:11`); `defaults = UserDefaults(suiteName: suiteName) ?? .standard` with documented fallback "when the group is unavailable (watchOS, unregistered simulators, and previews)" (`:12-17`). `BoolPreferenceStore` (`init(defaults: UserDefaults = AppGroup.defaults, key:, fallback:)`, `BoolPreferenceStore.swift:18-25`) is the non-`@AppStorage` read/write used by sync code; `isEnabled` treats nil as fallback (`:34-36`), `set` writes the suite (`:38-40`); keys enumerated in `BoolPreferenceKey` (`BoolPreferenceKey.swift:8-27`). `AppViewModel.showPreferenceStore(_:fallback:)` builds store-backed reads (`AppViewModel.swift:179-183`).
- **Connections (iOS):** definition (`@AppStorage`, `ContentView.swift:72-132`) → snapshot into fresh bag (`ContentView+Settings.swift:51-70`) → `$bindings.X` into controls (`SettingsView.swift:41-120`) → edit mutates bag → `.onChange` bridge copies into `@AppStorage` (`ContentView+Settings.swift:23-43`) → setter writes its `store:` (8 keys → App Group, rest → `.standard`). **macOS:** only 13 shared fields exist (`ContentView.swift:78-113` compiled out) → bag built with 13 (`ContentView+Settings.swift:72-85`), six iOS-only bag vars keep init defaults, never wired → 3 interface bindings (`SettingsView.swift:51-55`), no notifications row (`:64-76`) → same `.onChange` bridge for the 13 shared fields (`:30,:33-43`).

## Q2: Shared settings view layer

### Findings

- **One target, both platforms.** `SingleThread/` is a `PBXFileSystemSynchronizedRootGroup` — every `.swift` (incl. `SettingsView.swift`, `InterfaceSettingsView.swift`) compiles into the single app target (`project.pbxproj:112-114`, `:249-257`); `SUPPORTED_PLATFORMS = "iphoneos iphonesimulator macosx"` (`project.pbxproj:850`).
- **Exact split:** Interface `NavigationLink` built twice under `#if os(iOS)` / `#elseif os(macOS)` (`SettingsView.swift:40-56`). iOS passes 7 bindings: `appearanceMode` `:42`, `textSize` `:43`, `allowsLandscape` `:44`, `showMicrophoneButton` `:45`, `enableActionButtons` `:46`, `showSwipePrompt` `:47`, `showUndoButton` `:48` (+ `viewModel` `:49`). macOS passes 3: `appearanceMode` `:52`, `textSize` `:53`, `showMicrophoneButton` `:54` (+ `viewModel` `:55`).
- **`@Binding` declarations are platform-gated, not just rows:** unconditional `appearanceMode` (`InterfaceSettingsView.swift:9`), `textSize` (`:11`), `showMicrophoneButton` (`:17`); `#if os(iOS)` — `allowsLandscape` (`:13-14`), `enableActionButtons` (`:19-20`), `showSwipePrompt` (`:23-24`), `showUndoButton` (`:27-28`). Row statements sit inside the same `#if os(iOS)` regions (`:59` allow-landscape toggle, `:86-97` action-buttons toggle, `:98-108` swipe prompt, `:110-120` undo). **Rows/bindings a platform never passes are simply absent — the memberwise initializer on macOS doesn't even take those arguments; nothing is defaulted or synthesized.** Preview mirrors the split (`InterfaceSettingsView.swift:132-140` iOS / `:143-148` macOS).
- Only other platform-gated root row: whole `NotificationsSettingsView` `NavigationLink` under `#if os(iOS)` (`SettingsView.swift:64-76`); the subscreen file itself documents "The `NavigationLink` into this view is `#if os(iOS)` gated in `SettingsView`, so it is only reachable on iOS even though the file compiles on all platforms" (`NotificationsSettingsView.swift:4-5`). `NotificationsSettingsView` is also the **only subscreen missing `.settingsSubscreenLayout()`** (`NotificationsSettingsView.swift:37`; every other subscreen ends with it — `InterfaceSettingsView.swift:124`, `ReminderSettingsView.swift:95`, `FilterSortSettingsView.swift:59`, `BackgroundSettingsView.swift:88`, `PurchaseSettingsView.swift:56`, `ExcludedListsView.swift:31`, `PrivacySettingsView.swift:21`, `AboutView.swift:40`). Root requires the modifier by comment (`SettingsView.swift:11-13`).
- **Precedents for rows existing on one platform with cross-platform effect:**
  - `enableActionButtons` — settings row iOS-only (`InterfaceSettingsView.swift:86-97`), but effective on macOS through a second read path: `macShowActionMenu` evaluates `ActionMenuGate.showsActionMenu(enableActionButtons: AppGroup.defaults.bool(forKey: "enableActionButtons"), …)` (`ContentView+ActionMenu.swift:89-93`, read at `:91`); iOS persists via `@AppStorage("enableActionButtons", store: AppGroup.defaults)` (`ContentView.swift:96`). Same arrangement on watch (`ShowEnableActionButtonsState.swift:15,24`).
  - Appearance/Text Size — shared rows honored on both: write-back → `@AppStorage("appearanceMode")` (`ContentView+Settings.swift:19`), observed in `ContentView.swift:276-278`, dispatched per-platform (`ContentViewModel.swift:130-137`), applied via `window.overrideUserInterfaceStyle` (`AppDelegate.swift:15-27`) vs `NSApp.windows` `.appearance` (`AppDelegate.swift:71-76`).
  - `showMicrophoneButton` — row ungated (`InterfaceSettingsView.swift:75-85`); consumer runs on both: bottom-bar mic branch including macOS bare `micButton` (`ContentView.swift:675-697`).
- `settingsSubscreenLayout()` on macOS = `SettingsSubscreenLayout` modifier `.frame(maxHeight: .infinity, alignment: .top)` (`SettingsSubscreenLayout.swift:4-10`); on iOS returns `self` unchanged (`:16-21`).
- **Mutation flow (canonical):** control edit → `@Binding` → ephemeral bag (`SettingsView.swift:178`) → `settingsSheetWritebacks` `.onChange` for wired fields only (`ContentView+Settings.swift:19-43`) → `@AppStorage` setter (e.g. `enableActionButtons` into App Group, `ContentView.swift:96`; show-* into App Group, `:115-133`) → live consumers re-read on their own (`macShowActionMenu` raw read `ContentView+ActionMenu.swift:91`; iOS `showsActionButtons` `ContentView+ActionMenu.swift:18-23`).

## Q3: macOS action-button mechanics

### Findings

- **Structure:** one `ContentView` extension, compile-time platform blocks: `#if os(iOS)` `SingleThread/ContentView+ActionMenu.swift:14-67`, `#if os(macOS)` `:70-173`, shared `actionMenuRescheduleSheet` `:175-203`.
- **Menu vs direct skip:** macOS `actionButtons` — `HStack(spacing: 32)` — branches on `macShowActionMenu`: ON → `macCompleteButton` + `macActionMenu` (SwiftUI `Menu`); OFF → `macCompleteButton` + `macSkipButton` + `macDeleteButton` (`ContentView+ActionMenu.swift:75-86`, branch `:77-84`). Header comment: toggle-off is "behaviorally identical to the pre-menu app: direct Skip, and on macOS a standalone Delete button" (`:4-7`).
- **Gate:** `macShowActionMenu` = `ActionMenuGate.showsActionMenu(enableActionButtons: AppGroup.defaults.bool(forKey: "enableActionButtons"), canMutate: viewModel.store.canMutate, hasVisibleReminder: viewModel.store.visibleReminders.first != nil)` (`ContentView+ActionMenu.swift:89-93`). `ActionMenuGate.showsActionMenu` is pure `enableActionButtons && canMutate && hasVisibleReminder` — no storage inside (`SingleThreadCore/Sources/SingleThreadCore/ActionMenuGate.swift:7-13`); truth-table unit-tested (`SingleThreadTests/ActionMenuGateTests.swift:4-6,17-18`). Placement condition in `bottomBar`: `#if os(macOS)` + `visibleReminders.first != nil` (`ContentView.swift:635-638`).
- **Menu contents:** `macActionMenu` items — Skip → `viewModel.skipCurrentReminder()` (`:113-114`), Reschedule → `isShowingRescheduleSheet = true` (`:115-116`), Delete (`.role: .destructive`) → `Task { await viewModel.deleteCurrentReminder() }` (`:117-121`); items at `ContentView+ActionMenu.swift:111-133`. Direct branch: `macSkipButton` → `viewModel.skipCurrentReminder()` with no dialog (`:135-148`, action `:137`) beside `macDeleteButton` (`:150-165`). iOS analogue: single Skip surface; on tap checks `showActionMenu` and either captures `actionMenuReminder` + presents `.confirmationDialog`, or skips directly (`:18-23`, `:30-63`, tap `:32-37`, dialog `:46-58`).
- **Same App-Group-backed value as iOS:** iOS writes `@AppStorage("enableActionButtons", store: AppGroup.defaults) var enableActionButtons = false` (iOS-only, `ContentView.swift:96-97`), write-back `.onChange(of: bag.enableActionButtons)` (`ContentView+Settings.swift:24`). macOS carries the App Group entitlement via `[sdk=macosx*]` → `SingleThread/SingleThread.entitlements` (`project.pbxproj:742,:792`), declaring `com.apple.security.application-groups = group.app.alanvardy.SingleThread` (`SingleThread.entitlements:9-11`); iOS uses `AppGroup.entitlements` with same group (`pbxproj:740-741,:790-791`; `AppGroup.entitlements:5-7`). So macOS `AppGroup.defaults` resolves to the real suite and the macOS gate reads the same key iOS writes (doc comment `ContentView+ActionMenu.swift:72-74`). No macOS `@AppStorage` for the key; read raw via `bool(forKey:)` each render. One-time migration from `.standard` → App Group: `AppViewModel.registerDefaults()` (`AppViewModel.swift:163-172`), called from `AppViewModel.init` (`:26`), runs on both platforms. iOS non-view re-read: `ContentViewModel.showsActionButtons` = `AppGroup.defaults.bool(forKey:) && store.visibleReminders.first != nil` (`ContentViewModel.swift:64-67`).
- **`keyboardShortcut` modifiers — exactly four in the repo, all in the macOS block:** `macCompleteButton` `.keyboardShortcut("c", modifiers: [])` (`:105`); `macActionMenu` Delete item `.keyboardShortcut(.delete, modifiers: [])` (`:122`); the `Menu` itself `.keyboardShortcut("s", modifiers: [])` (`:129`); `macSkipButton` `.keyboardShortcut("s", modifiers: [])` (`:144`). Skip/Reschedule menu items have none. No per-shortcut platform guards; no shortcuts on iOS or watch.
- **Settings rows that toggle the feature:** iOS — `Toggle(isOn: $enableActionButtons)` "Show action buttons" / caption "Show complete, skip, and delete buttons.", id `showActionButtonsToggle` (`InterfaceSettingsView.swift:86-97`), iOS-only `@Binding` (`:19-20`), wired only in iOS branch of `SettingsView` (`SettingsView.swift:41-49`, arg `:46`). macOS — **no settings row** (macOS `InterfaceSettingsView` gets only appearance/textSize/showMicrophoneButton, `SettingsView.swift:51-55`; `makeSettingsBag()` omits the key on macOS, `ContentView+Settings.swift:72-85`). watchOS — no settings UI; the value comes from storage + sync callback (`ShowEnableActionButtonsState.swift:15,:24`; `WatchAppViewModel.swift:273-276`); the `--ui-testing-action-menu` seam force-applies it on/off, resetting to `false` on every other `--ui-testing` launch (`WatchAppViewModel.swift:61-68`).

## Q4: watchOS app structure and state holders

### Findings

- **Enumerated files** (all under `SingleThreadWatch/`): `SingleThreadWatchApp.swift` (`@main` App), `WatchAppViewModel.swift` (`@MainActor` composition root), `WatchReminderViewModel.swift` (`@MainActor @Observable`), `WatchReminderView.swift` (whole watch UI), and six `@Observable` state holders: `ShowDateState`, `ShowRecurrenceState`, `ShowAlarmsState`, `ShowListState`, `ShowCompletionGlowState`, `ShowEnableActionButtonsState` — plus `EntitlementState` (in `SingleThreadCore/Sources/SingleThreadCore/EntitlementState.swift`, `@MainActor @Observable`, in-memory only, no persistence).
- **Boot/composition:** `SingleThreadWatchApp.init()` builds `WatchAppViewModel()` (`SingleThreadWatchApp.swift:7-9`), body `WindowGroup { WatchReminderView(viewModel: viewModel.reminderViewModel) }` (`:13-16`). `WatchAppViewModel.init(arguments:)` picks a `ReminderStore` via the `--ui-testing` seam or `ReminderStore(loadsReminders: true)` (`WatchAppViewModel.swift:13-19`); creates the seven holders in order (`:37-43`); root VM `lazy var reminderViewModel = WatchReminderViewModel(store:…seven holders…)` (`:94-101`).
- **Storage tier per holder** (interval pattern `:28-31` in each `Show*State` — `BoolPreferenceStore(defaults: .standard, key:, fallback:)`):

  | Holder | Key | Backing store | Consumed by |
  |---|---|---|---|
  | `ShowDateState` | `showDate` | `.standard`, fallback `true` (`ShowDateState.swift:12-13,:21-23,:28-31`) | due-date row `WatchReminderView.swift:342` |
  | `ShowRecurrenceState` | `showRecurrence` | `.standard`, fallback `true` (:28-31) | repeats row `:352` |
  | `ShowAlarmsState` | `showAlarms` | `.standard`, fallback `true` (:28-31) | alert row `:357` |
  | `ShowListState` | `showList` | `.standard`, fallback `false` (:28-31) | list row `:347` |
  | `ShowCompletionGlowState` | `showCompletionGlow` | `.standard`, fallback `true` (`:27-30`) | glow gate `WatchReminderViewModel.swift:99-102` |
  | `ShowEnableActionButtonsState` | `enableActionButtons` | **`AppGroup.defaults` directly** — read `:14-15`, `apply` writes `:23-25` | `WatchReminderView.swift:82` |
  | `EntitlementState` (Core) | `isEntitled` | none (in-memory, `EntitlementState.swift:17-21`) | upgrade gate `WatchReminderView.swift:277` |

  `BoolPreferenceStore` reads `object(forKey:) as? Bool ?? fallback` and writes `set(_:forKey:)` (`BoolPreferenceStore.swift:26-32`). On a real watch `AppGroup.defaults` degenerates to `.standard` (`AppGroup.swift:16-19`), so the suites converge on-device; the suite path matters in simulator/UI-test contexts. `ShowEnableActionButtonsState` uses `AppGroup.defaults` deliberately because the sync pipeline's only App-Group write for a preference is this key (`SkippedReminderSyncService.swift:448-452`).
- **Writes arrive only via sync, never from watch UI:** `SkippedReminderSyncService` receive path persists `enableActionButtons` into `AppGroup.defaults` and fires `onEnableActionButtonsReceived` (`SkippedReminderSyncService.swift:448-452`); `WatchAppViewModel.wireStateReceiveHooks` maps each `on*Received` to `Task { @MainActor in state?.apply(value) }` (`WatchAppViewModel.swift:247-275`). Non-holder receive paths: `onShowUndatedRemindersReceived` sets `store.showsUndatedReminders` + reload (`:194-199`); `onSortOptionReceived` (`:208-210`); completion count → `AppGroup.defaults.set(count, forKey: "completionCount")` (`:215-217`); launch sort restore `store.sortOption = SortOptionStore().load()` (`:31`).
- **`canShowActionMenu`** = inline three-way AND — `showEnableActionButtonsState.isEnabled && store.canMutate && store.visibleReminders.first != nil` (`WatchReminderView.swift:81-85`) — the watch **duplicates** `ActionMenuGate.showsActionMenu` (`ActionMenuGate.swift:7-13`) rather than calling the shared helper. `store.canMutate` = `entitlementStore.isEntitled || completionCounter.count < EntitlementStore.freemiumCap` (`ReminderStore.swift:176-178`); completion counter reads `AppGroup.defaults`/`"completionCount"` (`CompletionCounterStore.swift:19-21`) and is live-updated from phone pushes (`WatchAppViewModel.swift:215-217`).
- **Action buttons** (`WatchReminderView.swift:129-157`): Complete → `Task { await viewModel.completeCurrentReminder() }` (`:131-132`), id `completeButton`; Skip branches on `canShowActionMenu` — ON sets `viewModel.isShowingActionMenu = true`, OFF calls `viewModel.store.skipCurrentReminder()` directly (`:142-147`), id `skipButton`. The button row itself renders only when `!(canMutate == false && !entitlementState.isEnabled)` — else the `lock.fill` "Upgrade on your iPhone" prompt (`:277-280`, prompt `:159-174`). Menu = `confirmationDialog` (`:283-286`) with three buttons from `actionMenuDialogButtons` (`:209-222`): Skip → `store.skipCurrentReminder()` (`:211-213`), Reschedule → sets `isShowingRescheduleSheet = true` (`:215-217`), Delete (destructive) → `await store.deleteCurrentReminder()` (`:219-220`). Reschedule sheet (`:287-289`, body `:297-327`) builds `.year/.month/.day` components → `await store.rescheduleReminder(identifier:to:)`, which relays watch→phone via `onRescheduleReminder` → `service.requestRescheduleReminder` (`ReminderStore.swift:355-361`, `WatchAppViewModel.swift:238-240`).
- View-model-held (non-persisted) state driving the menu: `isShowingActionMenu` (`WatchReminderViewModel.swift:61-62`), `isShowingRescheduleSheet` (`:64-65`), `rescheduleDate` default `Date().addingTimeInterval(86400)` (`:67-68`), nudge state `nudgeIdentifier`/`isShowingNudgeDialog` (`:53-58`). Skip nudge: 6th skip of a reminder triggers `onSkipNudgeRequested` and stops advancing (`ReminderStore.swift:380-403`); card renders nudge banner + dialog (`WatchReminderView.swift:261-275`).

## Q5: Phone↔watch preferences sync

### Findings

- **Transport:** `SkippedReminderSyncService` is the only WatchConnectivity bridge, compiled `#if os(iOS) || os(watchOS)` (`SkippedReminderSyncService.swift:4`). `WCSession` hidden behind the `SkipSyncSession` seam exposing `activate()`, `updateApplicationContext(_:) throws`, `sendMessage(...)` (`:8-16`; `extension WCSession: SkipSyncSession {}` `:17`). Two channels: `updateApplicationContext` full-snapshot sync (latest-wins, auto-delivered on (re)connect — `:20-22,:196-199`) and `sendMessage` for interactive watch→phone commands. **No `transferUserInfo`/`sendMessageData`/`didReceiveUserInfo`/`didReceiveMessageData` anywhere in Swift sources.**
- **Instantiation:** iPhone — `AppViewModel.init` → `setupSyncService(with:)` under `#if os(iOS)` (`AppViewModel.swift:33-37`), guarded `WCSession.isSupported() && !usesInMemoryStore` (`:356`); service built `:357-370` with App Group–backed show-* `BoolPreferenceStore`s (`showPreferenceStore(_:fallback:)` helper `:396-402`) and explicit `sendsShowDate: true, sendsEntitled: true` (`:369-370`); other `sends*` flags left at init-default `true` (`SkippedReminderSyncService.swift:52-57`) — **phone snapshot carries the full key set**. Receive hooks: `onCompleteReminderReceived` → `store.completeReminder` (`:372-374`), `onDeleteReminderReceived` → `store.deleteReminder` (`:376-378`), `onRescheduleReminderReceived` → `store.rescheduleReminder` (`:380-382`), `onExcludedListTitlesReceived` → `refreshExcludedListTitles` (`:384-386`), `onSkipCountsReceived` → `reload` (`:388`); `service.activate()` `:389`; store hooks `:391-404`. Watch — `WatchAppViewModel.setupSyncService(arguments:)` guarded `WCSession.isSupported()` (`WatchAppViewModel.swift:172-173`), **all preference stores injected `defaults: .standard`** (`:178-190`), `sendsShowDate/Recurrence/Alarms/List/CompletionGlow: false, sendsEntitled: false` (`:192-193`) — **watch transmits none of the show-*/entitled keys**.
- **`pushAll()` payload** (`SkippedReminderSyncService.swift:200-241`; one combined context via `updateApplicationContext` `:237`):
  - Always present (`:203-209`): `skippedReminderIdentifiers`, `skipCounts`, `excludedListTitles`, `showUndatedReminders`, `sortOption` (rawValue), `completionCount`, `enableActionButtons` — the last read **raw from `AppGroup.defaults.bool(forKey:)`, no injected store** (`:209`).
  - Gated by `sends*` flags (default true): `showDate` (`:212-213`), `showRecurrence` (`:215-216`), `showAlarms` (`:218-219`), `showList` (`:221-222`), `showCompletionGlow` (`:224-225`), `isEntitled` from `entitlementStore` via `MainActor.assumeIsolated` (`:226-236`).
  - Key literals in private `PayloadKey` enum (`:343-358`; `enableActionButtons = "enableActionButtons"` `:358`).
- **Watch→phone `sendMessage`:** `requestCompleteReminder(_:)` `[PayloadKey.completeReminderIdentifier: identifier]` (`:245-253`); `requestDeleteReminder(_:)` `[:255-262]`; `requestRescheduleReminder(identifier:dueDateComponents:)` with year/month/day/hour/minute dict (`:268-288`). All pass `replyHandler: nil` — **no acknowledgment path**. Phone `session(_:didReceiveMessage:)` decodes all three and invokes hooks (`:300-320`). Watch-side origins: watchOS-only `ReminderStore` branches fire `onCompleteReminder` (`ReminderStore.swift:235`), `onDeleteReminder` (`:301`), `onRescheduleReminder` (`:359-360`), wired `WatchAppViewModel.swift:236-240`. Phone also has send-side hooks: `store.onCompleteReminder → requestCompleteReminder` (`AppViewModel.swift:394`) and `onDeleteReminder → requestDeleteReminder` (`:399`, "kept for symmetry" — inert on iOS, `:395-398`).
- **Receive persistence:** `didReceiveApplicationContext` → single `apply(context:)` (`SkippedReminderSyncService.swift:294-297,:386-444`) + `applyRemaining` (`:447-465`).
  - **Phone** (all service stores default to `AppGroup.defaults` — `BoolPreferenceStore.swift:15`, `ReminderSkip.swift:124`, `SkipCountStore.swift:26`, `ExcludedListStore.swift:7`, `SortOption.swift:25`): skipped IDs `:395-398`, excluded titles `:400-403`, showUndated `:405-408`, sortOption `:410-414`, showDate `:416-419`, showRecurrence `:421-424`, showAlarms `:426-429`, showList `:431-434`, showCompletionGlow `:436-439`; `applyRemaining`: skipCounts `:453-456`, `enableActionButtons` explicitly `AppGroup.defaults.set(_, forKey:)` `:448-451`. `isEntitled` (`:458-460`) and `completionCount` (`:462-464`) only fire hooks (phone wires neither → not persisted on iOS).

## Cross-Cutting Observations

- **`enableActionButtons` is the load-bearing cross-platform flag.** iOS-only settings row (`InterfaceSettingsView.swift:86-97`) → App Group suite (`ContentView.swift:96`) → macOS gate (`ContentView+ActionMenu.swift:91`) → watch holder (`ShowEnableActionButtonsState.swift:15,24`) — with a one-shot migration (`AppViewModel.swift:163-172`), unconditional sync key (`SkippedReminderSyncService.swift:209`), UI-test seams on both sides (`AppViewModel.swift:264,:323`; `WatchAppViewModel.swift:61-68`), and dedicated tests (`EnableActionButtonsSyncTests`, `EnableActionButtonsMigrationTests`, `ActionMenuGateTests`, `ActionButtonTests`, `ShowEnableActionButtonsStateTests`).
- **App Group is the shared-context abstraction; `.standard` is the fallback-everywhere.** `AppGroup.defaults` = suite or `.standard` (`AppGroup.swift:16-17`); on a real watch and unregistered simulators everything silently lands in `.standard`. This is why AGENTS.md mandates App Group for every watch-shared value, why the show-* watch holders use explicit `.standard` stores (`WatchAppViewModel.swift:178-190`), and why `ShowEnableActionButtonsState` alone uses `AppGroup.defaults` (matching the sync pipeline's sole preference write, `SkippedReminderSyncService.swift:448-452`).
- **Ephemeral bag vs persisted store.** `SettingsBindings` never persists; the `.onChange` bridge copies into `@AppStorage` setters which own the storage (`ContentView+Settings.swift:8-43`; `SettingsBindings.swift:1-16`). Sync code uses `BoolPreferenceStore`, not `@AppStorage`, reading the same keys (`BoolPreferenceStore.swift:18-40`; keys `BoolPreferenceKey.swift:8-27`).
- **Platform gating pattern is "compile out, don't stub".** iOS-only bindings are `#if os(iOS)` at both declaration and row (`InterfaceSettingsView.swift:13-28,:59-120`) so macOS call sites never pass them; the bag can't do that (no `#if` in param lists) so it carries all 19 unconditionally with "never wired or read" on macOS (`SettingsBindings.swift:4-13`).
- **The action-menu UI is duplicated rather than shared.** macOS uses a SwiftUI `Menu` (`ContentView+ActionMenu.swift:111-133`), iOS a `.confirmationDialog` (`:46-58`), watch its own `confirmationDialog` (`WatchReminderView.swift:283-286`) — and the watch inlines the `ActionMenuGate` AND (`WatchReminderView.swift:81-85`) instead of calling the shared pure helper (`ActionMenuGate.swift:7-13`). Keyboard shortcuts exist only on macOS (four total: `ContentView+ActionMenu.swift:105,:122,:129,:144`).
- **Sync is directionally asymmetric.** Phone sends everything (`sends*` defaults true, `SkippedReminderSyncService.swift:52-57`); watch sends none of the show-*/entitled keys (`WatchAppViewModel.swift:192-193`), only skip-set changes via `pushAll` and complete/delete/reschedule via `sendMessage`. `pushAll` snapshots *replace* on receive (`:387-394`), and phone App-Group writes echo back one extra push until the `last*` diff guard settles (`AppViewModel.swift:450-492`).
- **Tests gate behavior through state seams, not view bodies.** iOS gate seam `ContentViewModel.showsActionButtons` (`ActionButtonTests.swift`, rationale `:6-13`); watch through launch-arg forced `apply`s (`WatchAppViewModel.swift:45-68`); watch UI determinism via `InMemoryEventStore` (`:106-167`). `--seed` is iOS-only; watch uses `--ui-testing*` flags.
- **Watch is receive-only for preferences** — no settings sheet on watch; the bag/write-back machinery exists only in the iOS/macOS target.
