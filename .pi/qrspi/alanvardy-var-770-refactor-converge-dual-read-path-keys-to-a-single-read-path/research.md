# Research Findings

Topic: how preference values are read across the SingleThread ecosystem — `@AppStorage` bindings, raw `UserDefaults` reads, typed store types in `SingleThreadCore`, the phone→watch sync pipeline, and the widget.

Suite shorthand: **STD** = `UserDefaults.standard`; **AG** = `AppGroup.defaults` = `UserDefaults(suiteName: "group.app.alanvardy.SingleThread") ?? .standard` (`SingleThreadCore/Sources/SingleThreadCore/AppGroup.swift:11`, `:15-17`) — a **new** `UserDefaults(suiteName:)` instance per access, falling back to `.standard` on watchOS/previews/unregistered sims.

## Q1: @AppStorage surface and freshness semantics

### Findings
- All 19 `@AppStorage` properties live in ONE file, the iOS/macOS app target: `SingleThread/ContentView.swift:72-133`. None in watch, widget, or Core (repo-wide grep; `SingleThreadCore/Sources/SingleThreadCore/SortOption.swift:16` only mentions it in a comment).
- **STD-suite** bindings: `appearanceMode` (`:72-73`), `textSize` (`:75-76`), iOS-only `allowsLandscape` (`:79-81`), `showMicrophoneButton` (`:83-84`), iOS-only `enableActionButtons` (`:96-97`), `showSwipePrompt` (`:101-103`), `showUndoButton` (`:106-107`), `notificationsEnabled` / `notificationIntervalHours` keyed by `AppViewModel.NotificationKeys` (`:109-113`). Explicit `store: .standard`: `backgroundEnabled` (`:86-87`), `backgroundFadePercent` (`:89-90`), `backgroundPinned` (`:92-93`).
- **AG-suite** bindings: `showUndatedReminders` (`:115-116`), `sortOption` via `SortOption.defaultsKey` (`:118-119`), `showDate` (`:121-122`), `showList` (`:124-125`), `showRecurrence` (`:127-128`), `showAlarms` (`:129-130`), `showCompletionGlow` (`:132-133`).
- **Freshness mechanism**: framework-owned. `@AppStorage` is a `DynamicProperty` that subscribes to `UserDefaults.didChangeNotification` on the specific `UserDefaults` instance it was initialized with; binding-setter writes post the same notification. The repo's only consumer of that notification is `AppViewModel.setupSyncObservation` (`SingleThread/AppViewModel.swift:418-427`): `addObserver(forName: UserDefaults.didChangeNotification, object: AppGroup.defaults, queue: .main)` → `handlePreferencesChanged` (`:429-455`) raw-reads the five `show-*` keys and diffs against `lastShow*` shadows (`:453-457`) → `syncService?.pushAll()` (`:448`). Registered at init (`:87-89`); token `syncDefaultsObserver` (`:464`), never removed. No `onReceive(didChangeNotification)` exists in any view.
- **Suite nuance**: because `AppGroup.defaults` returns a NEW instance per access, the observer holds one AG instance while each `@AppStorage(store: AppGroup.defaults)` holds another — notification `object` filtering depends on which instance posts. On targets where the group is `nil`, AG *is* `.standard`, so paths collapse into one suite. The watch files document that watching raw UserDefaults for `@AppStorage` read-back is OS-version-dependent enough that they removed it (`SingleThreadWatch/ShowDateState.swift:4-7` and the four sibling `Show*State.swift` files).
- **Writes that bypass @AppStorage**:
  - Raw STD writes: `UserDefaults.standard.set(false, forKey: NotificationKeys.enabled)` on permission denial/error (`AppViewModel.swift:185`, `:189`); UI-test seams `set(true,"enableActionButtons")` (`:291`, `:350`), `removeObject` `showCompletionGlow`/`showSwipePrompt` (`:286`, `:289`); `registerDefaults` seeds `showMicrophoneButton = true` (`:207-208`, comment `:205-206`: `@AppStorage` initializers are invisible to raw `bool(forKey:)` reads).
  - Store/typed writes to AG keys: `SortOptionStore().save` on the sort-change hook (`AppViewModel.swift:73-76`), `Show*Preference.set` on context receive (`SingleThreadCore/Sources/SingleThreadCore/SkippedReminderSyncService.swift:351-371`), `ReminderStore.showsUndatedReminders` direct property assignment with `didSet` firing only the hook (`ReminderStore.swift:103-106`, `:134-139`) — driven by the widget (`SingleThreadWidget/NextThingWidget.swift:79`) and watch launch restore (`SingleThreadWatch/WatchAppViewModel.swift:33-34`), and by seeded-suite writes (`AppViewModel.swift:342`, `:346`).
- **Write-back chain**: `@AppStorage` values are NOT written directly by settings UI. `SettingsBindings.swift:14-16` is an `@Observable` bag mirroring all 19 values; `settingsSheetWritebacks(_:)` (`SingleThread/ContentView+Settings.swift:16-52`) assigns each bag change back into the `@AppStorage` property via `.onChange`, and `makeSettingsBag()` snapshots current values (`:55-83`). Sheet hosting at `ContentView.swift:588-595`. `SettingsViewModel` itself writes no UserDefaults (`SettingsViewModel.swift:11-14` orientation lock, `:18-23` timeline reload only).
- Side-effect `.onChange`s attached to the `@AppStorage` setters: `backgroundPinned` → `BackgroundImageStore.setPinned` (`ContentView.swift:241-243`), `showUndatedReminders` → store + reload (`:244-246`), `sortOption` → `store.setSortOption` (`:247-249`), `appearanceMode` → `applyAppearance` (`:250-252`), `notificationsEnabled` → permission request/cancel (`:254-256`).

## Q2: Raw read sites and their execution context

### Findings
- **Launch-time / AppDelegate (STD)**:
  - `allowsLandscape`: `UserDefaults.standard.object(forKey:)`/`bool(forKey:)` in `application(_:supportedInterfaceOrientationsFor:)` (`SingleThread/AppDelegate.swift:50-57`) — runs before any SwiftUI view; key is written later in-session only via `@AppStorage` toggle; absent → `true`.
  - `appearanceMode`: `AppearanceMode.load()` raw `object(forKey:)` (`SingleThread/AppearanceMode.swift:80`, `:78-85`) called from `applicationDidBecomeActive` (`AppDelegate.swift:47`, macOS mirrors `:84`, `:89`) — reads the prior session's write, not the current one.
- **Background scene-phase handler (STD)**: `scheduleNotificationIfNeeded()` (`AppViewModel.swift:120-124`) reads `NotificationKeys.enabled` (`:129`) and `intervalHours` (`:133`, absent/0 → fallback 48 at `:134`); fired from `ContentView.handleScenePhaseChange(.background)` (`ContentView.swift:627`). Values were written earlier via `@AppStorage`/permission flow (`AppViewModel.swift:185`, `:189`).
- **View-rendering computed property (STD)**: `ContentViewModel.showsActionButtons` (`SingleThread/ContentViewModel.swift:53-59`) reads `bool(forKey:"enableActionButtons")` at `:58` during body evaluation.
- **Store `load()`s in Core — all `defaults.object/integer/string/stringArray/dictionary(forKey:)` inside SingleThreadCore** (default suite AG):
  - `Show*Preference.isEnabled` (`object(forKey:) as? Bool`): `ShowDatePreference.swift:20`, `ShowRecurrencePreference.swift:20`, `ShowAlarmsPreference.swift:20`, `ShowCompletionGlowPreference.swift:20`, `ShowListPreference.swift:20`; `ShowUndatedRemindersPreference.load()` at `ShowUndatedRemindersPreference.swift:19`.
  - Read contexts: `AppViewModel.handlePreferencesChanged` (`AppViewModel.swift:432-437`) and init-time `lastShow*` snapshots (`:453-457`), widget `makeEntry()` (`NextThingWidget.swift:62-65`), sync `pushAll()` (`SkippedReminderSyncService.swift:182-188`), watch `Show*State.init` on `.standard` (`ShowDateState.swift:13`, siblings).
  - `SortOptionStore.load()` (`SortOption.swift:35`, missing → `.priority`): composition-root init on all targets — iOS `AppViewModel.swift:25`, watch `WatchAppViewModel.swift:31`, widget `NextThingWidget.swift:72` and intents `SingleThreadCore/Sources/SingleThreadCore/ReminderIntents.swift:20`, `:43`.
  - `CompletionCounterStore.count` (`CompletionCounterStore.swift:31`) read every time `ReminderStore.canMutate` is evaluated (`ReminderStore.swift:143-145`) at gesture time on app/watch/widget.

- **Watch launch composition root (STD — no App Group registered)**: `Show*State` init from `.standard`-backed prefs (`ShowDateState.swift:13,26` and siblings `:13`), `SortOptionStore().load()` (`WatchAppViewModel.swift:31`), `ShowUndatedRemindersPreference(defaults:.standard).load()` (`:34`). Launch reads precede any synced value; sync receive later overwrites via `.set()` (`SkippedReminderSyncService.swift:351-371`).
- **Widget timeline build (AG)**: only raw-literal read is `AppGroup.defaults.bool(forKey:"showUndatedReminders")` (`NextThingWidget.swift:71`) in `makeEntry()` (`@MainActor`, `:61-72`); the rest go through store types (see Q7).
- **Timing observations**: iOS init order is `makeStore` → `SortOptionStore().load()` (`AppViewModel.swift:25`) → `registerDefaults()` (`:26`) → observer setup (`:84-89`) — so `lastShow*` defaults evaluate before any notification can fire. The didChange observer runs on `queue: .main` (`:402-406`) and raw-reads AG only when the notification fires — read frequency equals write frequency for AG keys. Sync receive persists via `.set()` before `reload()` re-reads (`WatchAppViewModel.swift:178-187`). `registerDefaults` (`AppViewModel.swift:206-209`) is the only registration guard for raw `bool(forKey:)` reads (`showMicrophoneButton`).

## Q3: Core preference store types

### Findings
- Uniform shape — small public structs, `init(defaults: UserDefaults = AppGroup.defaults, key: String = "<literal>")`, `private let defaults/key`; read via a computed `isEnabled: Bool` = `defaults.object(forKey:) as? Bool ?? <default>`; write via `set(_:)` = `defaults.set(enabled, forKey:)`:
  - `ShowAlarmsPreference` (`ShowAlarmsPreference.swift:10-12` init, `:16-19` read, `:21-23` set), `ShowCompletionGlowPreference` (`:10-12/:16-19/:21-23`), `ShowDatePreference` (`:10-12/:16-19/:21-23`), `ShowRecurrencePreference` (`:10-12/:16-19/:21-23`), `ShowListPreference` (`:10-12/:16-19/:21-23`).
  - **Odd one out**: `ShowUndatedRemindersPreference` uses `load()`/`save(_:)` instead of `isEnabled`/`set` (`ShowUndatedRemindersPreference.swift:8-11` init, `:13-16` load, `:18-20` save).
  - `SortOptionStore` (in `SingleThreadCore/Sources/SingleThreadCore/SortOption.swift`): `enum SortOption: String, CaseIterable` with `static let defaultsKey = "sortOption"` (`:18`); store init (`:24-26`), `load()` falls back to `.priority` on missing or unrecognized raw (`:31-36`), `save(_:)` writes `rawValue` (`:38-40`).
- **Default-when-missing**: `true` for showAlarms/showCompletionGlow/showDate/showRecurrence; `false` for showList and showUndatedReminders; `.priority` for sortOption. Deliberately `object(forKey:) as? Bool ?? …`, NOT `bool(forKey:)` (which yields false for missing keys) — documented per type (e.g. `ShowDatePreference.swift:3-7`).
- **Instantiation / usage**:
  - iOS: `SortOptionStore().load()` at composition root (`AppViewModel.swift:25`); sync service constructed with AG-defaulted `ShowDate/Recurrence/Alarms/CompletionGlowPreference()` (`:33-36`); sort change → `SortOptionStore().save(option); service.pushAll()` (`:70-74`); `ContentViewModel` holds injected `showCompletionGlow: ShowCompletionGlowPreference()` read at trigger time (`ContentViewModel.swift:18`, `:137`).
  - Watch: all sync stores built with explicit `.standard` (`WatchAppViewModel.swift:164-172`); each `Show*State` owns `private let preference = Show*Preference(defaults: .standard)` and applies via `apply(_:)` (`ShowDateState.swift:25-35`, siblings `:25-31`).
  - Widget: default-init stores → AG (`NextThingWidget.swift:64-67`, `:72`); intents `SortOptionStore().load()` (`ReminderIntents.swift:20`, `:43`).
  - Sync service: stores injectable with AG defaults (`SkippedReminderSyncService.swift:31-37`, stored `:301-307`); `pushAll` reads them (`:180-188`); `apply(context:)` persists through them (`:329-394`).

## Q4: Key-string definition and centralization

### Findings
- **Only two shared constants**:
  - `SortOption.defaultsKey = "sortOption"` (`SortOption.swift:18`) — used by `SortOptionStore` default arg (`:25`), app `@AppStorage(SortOption.defaultsKey, …)` (`ContentView.swift:118`), widget load (`NextThingWidget.swift:72`).
  - `AppViewModel.NotificationKeys` — `enabled = "notificationsEnabled"`, `intervalHours = "notificationIntervalHours"` (`AppViewModel.swift:95-101`) — used by both `AppViewModel` reads/writes (`:129`, `:133`, `:185`, `:189`) and `@AppStorage` (`ContentView.swift:109`, `:112`).
- **Canonical per-store key literals** (the store init default arg is the single production declaration; several are repeated at call sites): `"skippedReminderIdentifiers"` (`ReminderSkip.swift:124`), `"skipCounts"` (`SkipCountStore.swift:26`), `"excludedListTitles"` (`ExcludedListStore.swift:7`), `"showUndatedReminders"` (`ShowUndatedRemindersPreference.swift:11`), `"showDate"/"showList"/"showRecurrence"/"showAlarms"/"showCompletionGlow"` (`Show*Preference.swift:11` each), `"completionCount"` (`CompletionCounterStore.swift:21`), `"pendingCompletionIdentifiers"` (`PendingCompletionStore.swift:22` — single site, never on the wire).
- **Ad-hoc `@AppStorage` literals in ContentView** (STD unless noted): `"appearanceMode"` (`ContentView.swift:72` + raw read `AppearanceMode.swift:80`), `"textSize"` (`:75`), `"allowsLandscape"` (`:79` + `AppDelegate.swift:53,55`), `"showMicrophoneButton"` (`:83` + `registerDefaults` `AppViewModel.swift:208`), `"backgroundEnabled"/"backgroundFadePercent"/"backgroundPinned"` (`:86,:89,:92`), `"enableActionButtons"` (`:96` + raw read `ContentViewModel.swift:58` + seams `AppViewModel.swift:291,350`), `"showSwipePrompt"` (`:101`), `"showUndoButton"` (`:106`); AG-duplicated literals `"showUndatedReminders"` (`:115`), `"showDate"` (`:121`), `"showList"` (`:124`), `"showRecurrence"` (`:127`), `"showAlarms"` (`:129`), `"showCompletionGlow"` (`:132`).
- **PayloadKey vs local keys** (`SkippedReminderSyncService.swift:278-294`): a private 14-key `enum PayloadKey` shared by sender and receiver. The wire keys are **string-identical** to the local store keys but declared as **independent literals** (e.g. `.sortOption = "sortOption"` at `:284` does not reference `SortOption.defaultsKey`; `.completionCount` `:291`, `.skippedReminderIdentifiers` `:279`, `.excludedListTitles` `:281` copy the store strings by value). Two payload-only keys with no UserDefaults backing: `completeReminderIdentifier` (`:282`), `deleteReminderIdentifier` (`:283`) — sendMessage-only. Store keys never on the wire: `"pendingCompletionIdentifiers"` and all `.standard` cosmetic keys. See also `UITestingSeed.swift:73-98` for a 24-key `persistedKeys` wipe list that independently repeats these strings.
- **Multi-site literal count** (worst offenders): `"completionCount"` 6 sites (store `CompletionCounterStore.swift:21`, seed writes `AppViewModel.swift:342,:369`, watch seams `WatchAppViewModel.swift:27,:202`, wipe list `UITestingSeed.swift:84`, PayloadKey `SkippedReminderSyncService.swift:291`); `"showUndatedReminders"` 5 sites (`ShowUndatedRemindersPreference.swift:11`, `ContentView.swift:115`, `NextThingWidget.swift:71`, `UITestingSeed.swift:82`, PayloadKey `:285`); the five `show-*` keys 4-5 sites each (store init + ContentView `@AppStorage` + PayloadKey `:286-291` + wipe list `:77-80`). `"isEntitled"` is payload-only (`SkippedReminderSyncService.swift:292`, `UITestingSeed.swift:85`) — `EntitlementStore` is in-memory, no UserDefaults backing.

## Q5: Phone→watch preference sync

### Findings
- **Triggers (phone)**:
  1. `NotificationCenter` observer on `UserDefaults.didChangeNotification` with `object: AppGroup.defaults`, `queue: .main` (`AppViewModel.swift:418-427`) → `handlePreferencesChanged` (`:429-455`) diffs AG `show-*` values → `pushAll()` only when one changed (`:448`). Observed writes come from the AG `@AppStorage` toggles (`ContentView.swift:115-133`).
  2. Store hooks: `onSkipSetChanged` / `onShowUndatedRemindersChanged` / `onExcludedListsChanged` → `pushAll()` (`AppViewModel.swift:60-62`); `onSortOptionChanged` saves `SortOptionStore().save(option)` then `pushAll()` (`:70-76`). Complete/delete use the `sendMessage` route (`requestCompleteReminder`/`requestDeleteReminder`, `:67-70`).
  3. Entitlement: `withObservationTracking` on `store.entitlementStore.isEntitled`, re-registered recursively; every change → `pushAll()` (`:402-411`).
- **Payload**: one combined latest-wins `applicationContext` (`SkippedReminderSyncService.swift:176-212`). **Always** includes `skippedReminderIdentifiers`, `skipCounts`, `excludedListTitles`, `showUndatedReminders`, `sortOption`, `completionCount` (`:176-184`); per-key `sends*` flags gate `showDate` (`:187`), `showRecurrence` (`:190`), `showAlarms` (`:193`), `showList` (`:196`), `showCompletionGlow` (`:199`), `isEntitled` (`:206-210`). Sent via `session.updateApplicationContext(context)` (`:212`).
- **Receive / target stores** (`apply(context:)`, `SkippedReminderSyncService.swift:320-394`): latest-wins full-shape replace, absent keys no-op (`:321-328`); each key persisted into the injected store — `skipStore.save` (`:329-333`), `excludeStore.save` (`:334-338`), `showUndatedStore.save` (`:339-343`), `sortStore.save` (`:344-349`), `showDateStore.set` (`:350-354`), `showRecurrenceStore.set` (`:355-359`), `showAlarmsStore.set` (`:360-364`), `showListStore.set` (`:365-369`), `showCompletionGlowStore.set` (`:370-374`); `applyRemaining`: `countStore.save` (`:382-386`), `onEntitlementReceived` (`:387-390`), `onCompletionCountReceived` (`:391-394`).
- **On the watch** every preference/counter store is constructed with `defaults: .standard` (`WatchAppViewModel.swift:164-172`), so received preference values persist to watch **STD** (AG on watch = `.standard` via fallback). Watch-side hooks: `onShowUndatedRemindersReceived` → `store.showsUndatedReminders = value` + reload (`:176-179`); `onSkippedIdentifiersReceived`/`onSkipCountsReceived` → reload (`:183-189`); `onSortOptionReceived` → `store.setSortOption` (`:192-194`); `onCompletionCountReceived` → `AppGroup.defaults.set(count, "completionCount")` (falls back to STD on watch) (`:201-203`); `onExcludedListTitlesReceived` → `store.refreshExcludedListTitles` (`:206-208`); show-* hooks call `state.apply(value)` on the main actor (`:218-253`).
- **Watch read-back**: launch restore reads `.standard` (`WatchAppViewModel.swift:31`, `:34`); live updates flow through the `@Observable` `Show*State.apply(_:)` holders (set + publish; `ShowDateState.swift:13-15,21-24,27` and siblings). Rendering reads the observable state, **not** UserDefaults: `WatchReminderView.swift:257,262,267,272`, `WatchReminderViewModel.swift:87`, `WatchReminderView.swift:235` (entitlement).
- **Direction of authority**: preferences are **phone → watch only**. The watch has no settings UI (`SingleThreadWatch/SingleThreadWatchApp.swift:14-18` hosts only `WatchReminderView`), `Show*State.isEnabled` is `private(set)` with the sole writer being sync `apply(_:)`, and the watch passes `sendsShowDate/…/sendsEntitled = false` (`WatchAppViewModel.swift:174-175`). The transport is technically bidirectional for the ungated shared keys: watch `store.onSkipSetChanged → pushAll()` (`:210`) echoes `skippedReminderIdentifiers`/`skipCounts`/`excludedListTitles`/`showUndatedReminders`/`sortOption`/`completionCount` back to the phone, whose `apply` persists them (`SkippedReminderSyncService.swift:329-394`).
- Naming note: `SkippedReminderSyncService` is NOT skipped-reminders-only — preferences ride the same combined context, payload and receive path; the class name is historical.

## Q7: Widget read path

### Findings
- `@main SingleThreadWidgetBundle` returns exactly one widget, `NextThingWidget()` (`SingleThreadWidget/SingleThreadWidgetBundle.swift:4-9`). `getTimeline` (`NextThingWidget.swift:51`) spawns a `Task`, awaits `makeEntry()` (`:52-53`), returns one entry with `.after(now + 15 min)` policy (`:54-55`). `makeEntry` is `@MainActor` (`:61-62`) and is the single preference-read site (placeholders at `:30-48` read nothing).
- **Every preference read resolves to the AG suite**:
  - `ShowDatePreference().isEnabled` (`:64`), `ShowListPreference().isEnabled` (`:65`), `ShowRecurrencePreference().isEnabled` (`:66`), `ShowAlarmsPreference().isEnabled` (`:67`) — store types default to `AppGroup.defaults`.
  - `AppGroup.defaults.bool(forKey: "showUndatedReminders")` (`:71`) — a raw literal that bypasses the `ShowUndatedRemindersPreference` wrapper (same key string, same default `false` semantics via `bool(forKey:)`).
  - `SortOptionStore().load()` (`:72`).
- **App-Group wiring**: the widget target carries `CODE_SIGN_ENTITLEMENTS = SingleThread/AppGroup.entitlements` in both Debug (`SingleThread.xcodeproj/project.pbxproj:1000`) and Release (`:1031`), and `AppGroup.entitlements:10` grants `com.apple.security.application-groups = [group.app.alanvardy.SingleThread]` — a real shared container, so AG never falls back to `.standard` on device. Bundle id `app.alanvardy.SingleThread.widget` (`pbxproj:1015,:1046`); iOS-only target.
- **Interaction with app writes**: the app writes the identical keys to the identical suite via `@AppStorage(..., store: AppGroup.defaults)` (`ContentView.swift:115-133`), so widget timelines observe exactly what the app last wrote. The app nudges refresh: `store.onRemindersChanged` → `WidgetCenter.shared.reloadAllTimelines()` (`AppViewModel.swift:77-81`, `#if os(iOS) || os(macOS)`), plus `SettingsViewModel.swift:21-23`.
- **Transitive reads**: `ReminderStore(loadsReminders: true)` (`NextThingWidget.swift:70`) takes default-AG stores (`SkippedReminderStore`, `SkipCountStore`, `PendingCompletionStore`, `ExcludedListStore`; `ReminderStore.swift:25-28`); `reload()` reads skip/exclude sets from AG (`ReminderStore.swift:654,656`) and writes the reconciled skip list back (`:657`). Widget intents (`CompleteReminderIntent`/`SkipReminderIntent`, `NextThingWidget.swift:168,:177`) build a fresh store, apply `SortOptionStore().load()`, reload, and the Skip intent persists via `skipStore.save` (`ReminderIntents.swift:18-21,41-44,49`; `ReminderStore.swift:657`) — a widget→app write path through the same AG suite.

## Cross-Cutting Observations

- **Two coexisting read paths for the same keys**: `@AppStorage` bindings (view-owned, SwiftUI-observed) and raw/typed reads (AppViewModel, sync service, widget, watch states). The only bridge is AppViewModel's single `didChangeNotification` observer on the AG suite (`AppViewModel.swift:418-427`); STD-suite keys (`appearanceMode`, `textSize`, `background*`, `enableActionButtons`, `showSwipePrompt`, `showUndoButton`, notifications) have **no** in-repo observer — their "freshness" is purely SwiftUI's.
- **Key strings are duplicated, not centralized**: the same literal is declared independently in the Core store init default, the ContentView `@AppStorage`, the `PayloadKey` enum, the `UITestingSeed` wipe list, and test seams (Q4). The two constants (`SortOption.defaultsKey`, `AppViewModel.NotificationKeys`) are exceptions, and even `PayloadKey.sortOption` does not reference the constant.
- **Suite identity nuance**: `AppGroup.defaults` yields a fresh `UserDefaults(suiteName:)` per access (`AppGroup.swift:15-17`); on watchOS/unregistered simulators it *is* `.standard`, which is why the watch can use `.standard`-constructed stores and still receive the same keys. Read-vs-write consistency across targets depends on this fallback, not on shared instance identity.
- **Missing-key defaults differ per key** (Q3 table): five `show-*` keys are true-by-default except `showList`/`showUndatedReminders` (false), `sortOption` → `.priority`. All use `object(forKey:)` casts, not `bool(forKey:)`, except the widget's raw `showUndatedReminders` read (`NextThingWidget.swift:71`), which relies on `bool(forKey:)` returning false for missing keys — matching the wrapper default.
- **API asymmetry within the family**: `ShowUndatedRemindersPreference` is `load()/save(_:)` and is additionally written through `ReminderStore.showsUndatedReminders` (didSet) and read raw by the widget — it participates in three distinct read patterns while its siblings use one.
- **Sync payload vs store keys**: 12 wire keys are byte-identical to local store keys but independently declared; two wire keys (`completeReminderIdentifier`, `deleteReminderIdentifier`) have no persistence; one persisted key (`pendingCompletionIdentifiers`) never travels.
- **Execution-context taxonomy holds** (Q2): launch-time reads (AppDelegate orientation/appearance; watch composition root), view-render reads (`ContentViewModel.showsActionButtons`), background-handler reads (scenePhase notifications), store-load reads at init, sync-receive `.set()` before reload.
