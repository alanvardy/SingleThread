## Q2: Preference-store API family

### Findings
- **Template (5 of 6)**: `public init(defaults: UserDefaults = AppGroup.defaults, key: String = "<key>")`; read `defaults.object(forKey: key) as? Bool ?? <fallback>`; write `defaults.set(enabled, forKey: key)` — e.g. `ShowDatePreference.swift:11,19-25` with `private let defaults`/`key` at `:29-30` (identical in the other four, e.g. `ShowListPreference.swift:11,19-25`). All six read as **object-cast bool, never `bool(forKey:)`**; every write in all 12 types is untyped `set(_:forKey:)` (no `setValue` anywhere, grep-verified).
- **`ShowUndatedRemindersPreference` outlier**: API is `func load() -> Bool`/`save(_:)` (`ShowUndatedRemindersPreference.swift:18-24`) vs `isEnabled`/`set(_:)` for the other five; doc `:3-4` says "mirroring `SortOptionStore`".
- **Sibling stores** (all `init(defaults:key:)` unless noted):
  - `SkippedReminderStore` — `ReminderSkip.swift:121-137`; `load() -> [String]` `stringArray ?? []`.
  - `SortOptionStore` — `SortOption.swift:22-47`; `load() -> SortOption` `string ?? .priority`; key via shared constant `SortOption.defaultsKey` (`:18`, consumed `:25`); `SortOption: String, CaseIterable, Sendable` `:6`.
  - `ExcludedListStore` — `ExcludedListStore.swift:4-20`; `load() -> [String]` `?? []` — identical to `SkippedReminderStore` bar the key.
  - `SkipCountStore` — `SkipCountStore.swift:23-39`; `load() -> [String: Int]` `dictionary ?? [:]`, cast failure also collapses to `[:]`.
  - `CompletionCounterStore` — `CompletionCounterStore.swift:16-49`; **not load/save-shaped**: computed `count` via `integer(forKey:)` (absent → 0) plus `increment()`/`decrement()`/`resetForTesting()` mutators; `decrement` floors at 0.
  - `PendingCompletionStore` — `PendingCompletionStore.swift:17-84`; only type with params beyond `defaults`/`key` (`expiry: TimeInterval = 300`, `now: @escaping () -> TimeInterval`); `load() -> Set<String>` of non-expired entries; `record(_:)` and `save(_:)` (never unions); reads `dictionary(forKey:)` with per-entry `TimeInterval` cast.
- **Inconsistencies observed**: `isEnabled/set` vs `load/save`; `*Preference` vs `*Store` suffix split for the same job, and sync-service params named `showDateStore` etc. for the `*Preference` types (`SkippedReminderSyncService.swift:31-38`); deliberate fallback split (nil→true: date/recurrence/alarms/glow; nil→false: list/undated) pinned by tests (`SingleThreadTests/ShowDatePreferenceTests.swift:8-21`); 11 of 12 keys are inline literals (only sortOption uses a constant); `CompletionCounterStore` and `PendingCompletionStore` deviate in read/write shape; `UITestingSeed.persistedKeys` covers the six keys but omits `pendingCompletionIdentifiers` (`UITestingSeed.swift:73-97`).
- **Generic reuse: none.** No protocol/base/typealias ties the twelve types; each re-declares `private let defaults`/`key` and the same init body (e.g. `ShowDatePreference.swift:12-13,29-30`). `Extension EKReminder: @retroactive @unchecked Sendable` (`ReminderDateFilter.swift:23`) is unrelated.

## Cross-Cutting Observations
- **The six keys each have three representations**: a `Show*Preference` struct (Core), an `@AppStorage` mirror (iOS), and a `Show*State` holder (watch) — with a raw-read variant in the widget and the sync service as the only cross-process writer.
- **Fallback values are consistent across all four representations** and the var-759 audit: true×4 (date, recurrence, alarms, glow), false×2 (list, undated).
- **Two keys are "special"**: `showUndatedReminders` (load/save API, unconditional push, in-memory `ReminderStore` property, raw widget read) and `showCompletionGlow` (not passed to the card, `.standard` reset seam vs App-Group storage, only watch state holder with a dedicated serialized test suite).
- **Divergent concrete types, converged call sites**: `SkippedReminderSyncService.init` accepts 12 stores by concrete type; tests bridge the divergence with a UUID-key + switch helper. No generic exists — the audit's T4.4 and the deferred action list explicitly target a generic `BoolPreferenceStore`.
- **Platform asymmetry**: App Group on iOS/widget; `.standard` on watch; effective sync direction phone→watch; iOS does not react to received show* values (no hooks), the watch does.
- **`SettingsViewModel` is the only widget-reload trigger from settings, and only for 3 of 6 keys** — the doc comment in `ReminderSettingsView.swift:4-7` overstates coverage.
