## 2. SettingsBindings structure

- 19 stored vars — lines 64-82: appearanceMode, textSize, allowsLandscape, enableActionButtons, showSwipePrompt, showUndoButton, notificationsEnabled, notificationIntervalHours, showMicrophoneButton, backgroundEnabled, backgroundFadePercent, backgroundPinned, showUndatedReminders, sortOption, showDate, showList, showRecurrence, showAlarms, showCompletionGlow.

What it wraps: a plain in-memory snapshot of every @AppStorage-backed preference. It is NOT write-through — doc comment lines 4-15: "Single bag of all @AppStorage-backed preference values, passed down from SettingsView to sub-views via @Bindable … mirrors the @AppStorage defaults from ContentView exactly. excludedLists is NOT here: it is store-backed (not @AppStorage)". iOS-only keys are declared unconditionally because #if is not allowed inside parameter lists (lines 10-15).

Ownership / wiring:
- SettingsView holds it as @Bindable private var bindings: SettingsBindings — SingleThread/SettingsView.swift:174, plus @Binding private var excludedLists: Set<String> — SettingsView.swift:172.
- ContentView creates it: settingsBag = makeSettingsBag() in the gear-button action — SingleThread/ContentView.swift:185-187; @State private var settingsBag: SettingsBindings? — ContentView.swift:300-304 (kept alive for the sheet lifetime so edits do not snap back on re-evaluation; nil-ed on dismiss via .onChange(of: isShowingSettings) at ContentView.swift:259-266).
- makeSettingsBag() (iOS branch) copies every @AppStorage value into the bag — SingleThread/ContentView+Settings.swift:48-87 (iOS branch 50-70).
- Write-back: settingsSheetWritebacks(_ bag:) attaches one .onChange per bag property that assigns back to the matching @AppStorage property — SingleThread/ContentView+Settings.swift:8-44.

## 6. Previews: how preference values are injected without touching real defaults

Mechanisms in use: .constant bindings, an in-memory SettingsBindings() bag, InMemoryEventStore, read-only @AppStorage reads, and one preview-only appearance modifier. There is no fake-store protocol for preference defaults and no launch-arg injection in previews (launch-arg seams exist only for UI tests — see below).

Per-view previews (each constructs SettingsViewModel() fresh; SettingsViewModel has no stored state — SettingsViewModel.swift:6-11):
- ReminderSettingsView.swift:100-109 — showDate: .constant(true), showList: .constant(false), showRecurrence: .constant(true), showAlarms: .constant(true), showCompletionGlow: .constant(true), viewModel: SettingsViewModel(). A .constant binding never changes, so the .onChange(of: showDate) → showPreferenceChanged() hooks never fire and WidgetCenter is untouched.
- FilterSortSettingsView.swift:64-71 — sortOption: .constant(.priority), showUndatedReminders: .constant(false), availableLists: ["Work", "Personal"], excludedLists: .constant([]).
- InterfaceSettingsView.swift:129-149 — all .constant values (.system / true / false per key).
- NotificationsSettingsView.swift:43-48 — .constant(false), .constant(48).
- BackgroundSettingsView.swift:93-100 — .constant(true), .constant(50), .constant(false), backgroundImage: BackgroundImageStore() (persists photo bytes/metadata to Application Support files, never UserDefaults — BackgroundImageStore.swift:130-133).
- SettingsView.swift:184-213 — bindings: SettingsBindings() (plain in-memory bag with defaults, no UserDefaults backing), backgroundImage: BackgroundImageStore(), availableLists: ["Work", "Personal"], excludedLists: .constant([]). The "Dark + Extra Large" preview (192-213) mutates the bag directly in code (e.g. sortOption: .dueDate, showList: true, showDate: false) and applies .preferredColorScheme(AppearanceMode.dark.colorScheme) (212) instead of writing the appearanceMode key.
- ContentView+Previews.swift:28-100 — six previews use the preview init overloads (ContentView.swift:26-66): loadsReminders: false, eventStore: InMemoryEventStore(), in-memory reminders / skippedIDs / authorizationStatus. The ContentView @AppStorage properties still read real UserDefaults (falling back to the declared default when the key is absent) but nothing in the previews writes a preference key. Dark previews use .preferredColorScheme(AppearanceMode.dark.colorScheme) — AppearanceMode.swift:39-50 (colorScheme property). The .task chain calls backgroundImage.setPinned(...), which only mutates the in-memory isPinned flag (BackgroundImageStore.swift:102-108); refreshIfNeeded writes photo files to Application Support, not UserDefaults.
- The preview init overloads set #if os(iOS) appViewModel = nil — ContentView.swift:35, 64-65 — so previews get no AppViewModel observer / watch / widget wiring.

## 7. Documentary notes / observed gaps (description only, no suggestions)

- showList and showCompletionGlow toggles have no widget-reload hook in ReminderSettingsView (only showDate / showRecurrence / showAlarms call showPreferenceChanged()), despite the file doc comment ReminderSettingsView.swift:4-7 claiming "Each changes widget timelines".
- .onChange handlers for the show* keys exist only in ReminderSettingsView (3 of 5 keys: showDate, showRecurrence, showAlarms) and in the ContentView+Settings write-back chain; ContentView.body has no .onChange for showDate / showList / showRecurrence / showAlarms / showCompletionGlow — the render path reads the @AppStorage-backed properties directly in reminderList (ContentView.swift:426-438).
- The ReminderCardView swipe-prompt Dismiss button writes false through the showSwipePrompt binding (ReminderCardView.swift:186), an app-layer write to @AppStorage("showSwipePrompt") outside the settings sheet.
- Unit test exercising the settings side effects: SingleThreadTests/SettingsViewModelTests.swift:10-24 (initializationAndMutationsDoNotCrash calls allowsLandscapeChanged and showPreferenceChanged).
- SettingsViewTests.swift:15-17 asserts the bag defaults (bag.showCompletionGlow true; explicit false round-trips).
- Watch receive side persists show* values into .standard via Show*Preference(defaults: .standard) (e.g. ShowListState.swift:28, ShowDateState.swift:31) and the watch restores sortOption / showsUndatedReminders from .standard stores at launch (WatchAppViewModel.swift:24-26).
