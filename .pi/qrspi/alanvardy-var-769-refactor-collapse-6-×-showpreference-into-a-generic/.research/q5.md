## 3. Findings T2.1, T2.3, T2.4, T3.1, T4.4

All quotes verbatim from `audit/findings.md`. Tier definitions at `audit/findings.md:5-11`: T1 = Reachable Contradiction/Data Loss; T2 = Cross-Target Divergence (`Two targets disagree on what a key means or where it lives; same logical value lands in different containers depending on process`); T3 = Dual-Read-Path Drift; T4 = Hygiene / Naming / Doc Drift.

### T2.1 — AppGroup-vs-`.standard` namespace collapse (`audit/findings.md:28-32`)
- **Tier**: T2 (`:29`)
- **Evidence**: `AppGroup.swift:13-14`, `WatchAppViewModel.swift:155-161`, `ContentView.swift:115-132` (`:30`)
- **Description** (`:31`): `AppGroup.defaults` is literally `.standard` when the group entitlement is absent (watchOS, previews, unregistered simulators). The watch explicitly pins 7 stores to `.standard` (`WatchAppViewModel.swift:155-161`). On iOS, 11 keys live in the group container (`ContentView.swift:115-132`); on watchOS, the same logical keys live in `.standard` — the same logical value exists under one name across two containers depending on process. This is the root cause of the counter echo (T1.2) and the watch double-persistence (T2.3).
- **Affected components**: `AppGroup.swift:13-14` (suite accessor fallback), `WatchAppViewModel.swift:155-161` (`.standard`-pinned stores on watch), `ContentView.swift:115-132` (iOS @AppStorage group declarations). The six show* keys are among the 11 group keys (`ContentView.swift:115,121,124,127,129,132`).
- **Per-key fallback values documented here**: none — T2.1 documents container topology, not per-key defaults.
- **Next action** (`:32`): `Top refactor candidate. Decide target topology (single suite? group on both? hybrid?) in a design-phase spike. The group-registered watch harness is a prerequisite. Separate spike + refactor tickets.`

### T2.3 — Watch double-persistence on show* receive (`audit/findings.md:40-44`)
- **Tier**: T2 (`:41`)
- **Evidence**: `SkippedReminderSyncService.swift:338-359`, `ShowDateState.swift:21-23,28` (`:42`)
- **Description** (`:43`): `Received `showDate`/`showList`/`showRecurrence`/`showAlarms`/`showCompletionGlow` values are written twice into `.standard` — once by the service store (`SkippedReminderSyncService.swift:338-359`, stores injected `.standard` per T2.1) and again by the hook\’s `Show*State.apply()` (`ShowDateState.swift:22-23`, identical in all five; each state holder constructs its own `.standard`-backed preference at `:28`). Redundant but currently harmless because both writers target the same key-suite pair.
- **Affected components**: five watch receive path writers — service stores inside `SkippedReminderSyncService.swift:338-359` (the `showDate` write is at `:339`, `showRecurrence` at `:344`, `showAlarms` at `:349`, `showList` at `:354`, `showCompletionGlow` at `:359`, per `audit/factbase.tsv`) and the watch `Show*State.apply()` hooks (`ShowDateState.swift:21-23` `:28`, identical in all five). `showUndatedReminders` is explicitly excluded from this finding (its single-writer pattern is noted at `audit/clusters.md:172` and `plan.md:514`).
- **Per-key fallback values documented here**: none — T2.3 documents write paths, not defaults.
- **Next action** (`:44`): `Collapse to one write path during the sync-contract refactor.`

### T2.4 — `showCompletionGlow` straddles suites (`audit/findings.md:46-50`)
- **Tier**: T2 (`:47`)
- **Evidence**: `ContentView.swift:132`, `AppViewModel.swift:247`, `ShowCompletionGlowState.swift:27` (`:48`)
- **Description** (`:49`): `iOS writes `showCompletionGlow` to App Group (`ContentView.swift:132`), but the reset seam removes it from `.standard` (`AppViewModel.swift:247`). On watchOS, the key lives in `.standard` (`ShowCompletionGlowState.swift:27`). The key effectively exists in different suites depending on the writing process.
- **Affected components**: iOS @AppStorage declaration (`ContentView.swift:132`), iOS reset seam (`AppViewModel.swift:247` — `UserDefaults.standard.removeObject(forKey: "showCompletionGlow")` per `audit/factbase.tsv`), watch state `ShowCompletionGlowState.swift:27`.
- **Per-key fallback value documented here**: none — suite placement only.
- **Next action** (`:50`): `Resolved by the suite-migration refactor (T2.1).`

### T3.1 — 12 keys with dual read paths (`audit/findings.md:54-58`)
- **Tier**: T3 (`:55`)
- **Evidence** (`:56`), the six show* entries verbatim: `ShowDatePreference.swift:20` (`showDate`), `ShowListPreference.swift:20` (`showList`), `ShowRecurrencePreference.swift:20` (`showRecurrence`), `ShowAlarmsPreference.swift:20` (`showAlarms`), `ShowCompletionGlowPreference.swift:20` (`showCompletionGlow`), `ShowUndatedRemindersPreference.swift:19` (`showUndatedReminders`), plus `SortOption.swift:35` (`sortOption`) and five non-show keys.
- **Description** (`:57`): `12 keys (`enableActionButtons`, `notificationsEnabled`, `notificationIntervalHours`, `allowsLandscape`, `appearanceMode`, and the 7 show* keys) are read through both `@AppStorage` (which SwiftUI observes) and a raw `UserDefaults.*` call. In normal operation both read the same underlying value, but `@AppStorage` refreshes on `UserDefaults.didChangeNotification` while raw reads reflect the value at call time. A write that lands after `@AppStorage`\’s last observed notification but before a raw read could produce a transient divergence.
  - Note: the phrase `the 7 show* keys` (also in the plan draft at `plan.md:776` and task files `P5.md:121`, `P5-section.md:66`) counts six show* keys plus `sortOption` to reach 12; the six show* keys are `showDate`, `showList`, `showRecurrence`, `showAlarms`, `showCompletionGlow`, `showUndatedReminders`.
- **Affected components**: each show* key\’s raw wrapper read (`Show*Preference.swift:19-20`) versus its `@AppStorage` declaration (`ContentView.swift:115,121,124,127,129,132`).
- **Per-key fallback values documented here**: none — T3.1 documents read-path divergence, not defaults.
- **Next action** (`:58`): `Converge each key to a single read path during the refactor. Deferred.`

### T4.4 — 6 duplicated `Show*Preference` structs (`audit/findings.md:80-84`)
