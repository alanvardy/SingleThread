# Q2 — Preference-store API family survey (SingleThreadCore)

Scope: the six `Show*Preference` structs and the six sibling `*Store` types
(`SortOptionStore`, `ExcludedListStore`, `SkipCountStore`,
`CompletionCounterStore`, `PendingCompletionStore`, `SkippedReminderStore`).
All paths are repo-relative to the checkout root. Static analysis only; no
builds/tests run.

## 0. Shared foundation: `AppGroup.defaults`

Every type below defaults its `defaults:` parameter to
`AppGroup.defaults`, defined at
`SingleThreadCore/Sources/SingleThreadCore/AppGroup.swift:16-18`:

```swift
public static var defaults: UserDefaults {
    UserDefaults(suiteName: suiteName) ?? .standard
}
```

`suiteName = "group.app.alanvardy.SingleThread"` (`AppGroup.swift:11`). The doc
comment at `AppGroup.swift:3-9` enumerates the payload families: UI preferences
(`showDate`, `showList`, `showRecurrence`, `showAlarms`, `showCompletionGlow`,
`showUndatedReminders`, `sortOption`) and store-backed payloads
(`skippedReminderIdentifiers`, `excludedListTitles`, `completionCount`,
`pendingCompletionIdentifiers`).

## 1. The six `Show*Preference` structs

Five of the six are the same template; only the doc comment, the default `key`
string, and the `?? ` fallback differ. The sixth
(`ShowUndatedRemindersPreference`) uses a different API surface (`load()` /
`save(_:)` instead of `isEnabled` / `set(_:)`).

### 1a. Template shape (5 of 6)

`SingleThreadCore/Sources/SingleThreadCore/ShowDatePreference.swift`:

- Struct: `public struct ShowDatePreference` — `ShowDatePreference.swift:8`
- Init: `public init(defaults: UserDefaults = AppGroup.defaults, key: String = "showDate")` — `ShowDatePreference.swift:11`
- Read: `public var isEnabled: Bool { defaults.object(forKey: key) as? Bool ?? true }` — computed property `ShowDatePreference.swift:19-21` (read statement `:20`)
- Write: `public func set(_ enabled: Bool) { defaults.set(enabled, forKey: key) }` — `ShowDatePreference.swift:23-25` (write statement `:24`)
- Private stored state: `private let defaults: UserDefaults` `:29`, `private let key: String` `:30`
- Absent-key fallback: `nil` → `true` (`:20`). Doc `:3-7` states this explicitly: "Unlike `SkippedReminderStore`, an absent key resolves to `true` … `bool(forKey:)` would hide dates on first launch. `nil` (missing key) therefore maps to `true`."
- Encoding: read `defaults.object(forKey: key) as? Bool` (not `bool(forKey:)`); write `defaults.set(_:forKey:)`.

The other four identical-template types:

| Type | Struct line | Key default | Fallback | Read stmt | Write stmt |
|---|---|---|---|---|---|
| `ShowListPreference` | `ShowListPreference.swift:8` | `"showList"` (`:11`) | `false` (`:20`) | `:20` | `:24` |
| `ShowRecurrencePreference` | `ShowRecurrencePreference.swift:8` | `"showRecurrence"` (`:11`) | `true` (`:20`) | `:20` | `:24` |
| `ShowAlarmsPreference` | `ShowAlarmsPreference.swift:8` | `"showAlarms"` (`:11`) | `true` (`:20`) | `:20` | `:24` |
| `ShowCompletionGlowPreference` | `ShowCompletionGlowPreference.swift:8` | `"showCompletionGlow"` (`:11`) | `true` (`:20`) | `:20` | `:24` |

Each has the same `isEnabled` computed property at `:19-21`, `set(_:)` at
`:23-25`, and `private let defaults` `:29` / `private let key` `:30`.

Fallback rationale is documented per-type:
- `ShowListPreference.swift:5-7`: "absent key resolves to `false`: the feature is new, so missing state must preserve today's card look (no list name)."
- `ShowRecurrencePreference.swift:5-7`: "absent key resolves to `true` … rather than `bool(forKey:)`'s `false`."
- `ShowAlarmsPreference.swift:6-7`: "An absent key resolves to `true` … rather than `bool(forKey:)`'s `false`."
- `ShowCompletionGlowPreference.swift:5-7`: "Like `ShowDatePreference`, an absent key resolves to `true` (today's always-on behavior)".

## 4. Naming and semantic inconsistencies

1. **`isEnabled`/`set(_:)` vs `load()`/`save(_:)`.** Five `Show*Preference`
   structs expose `var isEnabled` + `func set(_:)`
   (`ShowDatePreference.swift:19,23`, `ShowListPreference.swift:19,23`,
   `ShowRecurrencePreference.swift:19,23`, `ShowAlarmsPreference.swift:19,23`,
   `ShowCompletionGlowPreference.swift:19,23`) while
   `ShowUndatedRemindersPreference` exposes `func load()` + `func save(_:)`
   (`ShowUndatedRemindersPreference.swift:18,22`) — the same concept, a
   persisted Bool, with a different read/write vocabulary. Its doc (`:3-4`)
   attributes the choice to "mirroring `SortOptionStore`".
2. **`Preference` vs `Store` suffix.** The persistence-store family is split
   into `*Preference` (six Bool toggles) and `*Store`
   (array/dict/int/enum payloads), yet each type is a thin
   `defaults`+`key` wrapper doing the same job. At the call-site layer the
   boundary blurs further: `SkippedReminderSyncService` parameters are named
   `showUndatedStore`, `showDateStore`, `showRecurrenceStore`, `showAlarmsStore`,
   `showListStore`, `showCompletionGlowStore`
   (`SkippedReminderSyncService.swift:31-38`) — `*Store`-suffixed names for
   the `*Preference` types.
3. **Deliberate fallback split within the Bool family.** nil→`true`:
   `showDate`/`showRecurrence`/`showAlarms`/`showCompletionGlow`; nil→`false`:
   `showList`/`showUndatedReminders` (`ShowListPreference.swift:20`,
   `ShowUndatedRemindersPreference.swift:19`). The divergence is documented in
   each file (e.g. `ShowDatePreference.swift:5-7`, `ShowListPreference.swift:5-7`),
   and tests pin it: `SingleThreadTests/ShowDatePreferenceTests.swift:8-21`
   asserts "missing key defaults to enabled". The `@AppStorage` mirrors in the
   app match the struct fallbacks (e.g. `SingleThread/ContentView.swift:121-122`
   `showDate = true`, `:124-125` `showList = false`).
4. **Absent-key strategy differs by payload shape.** String arrays and
   dictionaries fall back to empty (`ReminderSkip.swift:132`,
   `ExcludedListStore.swift:15`, `SkipCountStore.swift:34`,
   `PendingCompletionStore.swift:70`); the enum falls back to `.priority`
   (`SortOption.swift:35-36`); the counter falls back to `0` via
   `integer(forKey:)` (`CompletionCounterStore.swift:31`); the Bools fall back
   per-toggle using `object(forKey:) as? Bool` — chosen deliberately over
   `bool(forKey:)` so the fallback is not forced to `false`.
5. **Key-string sourcing inconsistency.** 11 of 12 types choose default keys as
   inline string literals in the initializer
   (e.g. `ShowDatePreference.swift:11`, `ReminderSkip.swift:124`). Only
   `SortOptionStore` uses a shared constant (`SortOption.defaultsKey`,
   `SortOption.swift:18`, consumed at `:25`).
6. **`CompletionCounterStore` is not `load`/`save`-shaped.** It replaces the
   family `load() -> T` / `save(_:)` pair with a computed `count` property
   plus `increment()`/`decrement()`/`resetForTesting()` mutators
   (`CompletionCounterStore.swift:30,35,41,47`); its doc (`:28-29`) explicitly
   embraces the `integer(forKey:)` zero-default.
7. **Missing from the UI-test wipe list.** `UITestingSeed.persistedKeys`
   (`SingleThreadCore/Sources/SingleThreadCore/UITestingSeed.swift:73-97`)
   lists 24 keys including all six `show*` keys, `sortOption`, `skipCounts`,
   `skippedReminderIdentifiers`, `excludedListTitles`, `completionCount` — but
   not `"pendingCompletionIdentifiers"`, the one App-Group store key the
   `AppGroup` doc enumerates (`AppGroup.swift:3-9`) that is absent from the
   wipe.
8. **Init shape variance.** 9 of 12 types use the single-line
   `init(defaults:key:)` form; three use a multi-line form
   (`ShowUndatedRemindersPreference.swift:9-14`,
   `CompletionCounterStore.swift:19-24`, `PendingCompletionStore.swift:20-30`);
   only `PendingCompletionStore` adds parameters beyond `defaults`/`key`
   (`expiry`, `now` — `:22-23`).
9. **Cross-referential doc comments describe a fallback lattice.**
   `ShowDatePreference.swift:5` contrasts `SkippedReminderStore`;
   `ShowListPreference.swift:6` contrasts `ShowDatePreference`;
   `ShowRecurrencePreference.swift:5` contrasts `ShowListPreference`;
   `ShowCompletionGlowPreference.swift:5` contrasts `ShowDatePreference`;
   `ShowUndatedRemindersPreference.swift:3-4` and `SortOption.swift:21` each
   claim to mirror or be mirrored by the `SortOptionStore`/`SkippedReminderStore`
   pair respectively.
10. **A raw UserDefaults read bypasses the store family.** The widget reads the
    undated-reminders toggle directly:
    `store.showsUndatedReminders = AppGroup.defaults.bool(forKey: "showUndatedReminders")`
    (`SingleThreadWidget/NextThingWidget.swift:71`) instead of
    `ShowUndatedRemindersPreference().load()` — the only raw `bool(forKey:)`
    read in production code, with an inline literal key, while the same file
    uses `ShowDatePreference().isEnabled`, `ShowListPreference().isEnabled`,
    `ShowRecurrencePreference().isEnabled`, `ShowAlarmsPreference().isEnabled`
    (`:64-67`) and `SortOptionStore().load()` (`:72`).

## 5. Generic reuse check

None exists. Grep across `SingleThreadCore`, `SingleThread`,
`SingleThreadWatch`, `SingleThreadWidget` for `protocol [A-Za-z]+Store`,
`struct [A-Za-z]+<`, `AnyPreference`, `PreferenceProtocol`, `: Preference`
returned no matches. No generic store template, no shared protocol, no
typealias or base type ties these twelve types together. Each struct
independently re-declares the same two stored properties — e.g.
`private let defaults: UserDefaults` at `ShowDatePreference.swift:29`,
`ShowListPreference.swift:29`, `ShowRecurrencePreference.swift:29`,
`ShowAlarmsPreference.swift:29`, `ShowCompletionGlowPreference.swift:29`,
`ShowUndatedRemindersPreference.swift:28`, `SortOption.swift:47`,
`ExcludedListStore.swift:24`, `SkipCountStore.swift:43`,
`CompletionCounterStore.swift:53`, `PendingCompletionStore.swift:64` — and the
same init body (`self.defaults = defaults; self.key = key`, e.g.
`ShowDatePreference.swift:12-13`, `ReminderSkip.swift:125-126`). The repeated
boilerplate is twelve hand-written copies of the same pattern; callers
construct each type individually (e.g.
`SingleThreadCore/Sources/SingleThreadCore/ReminderStore.swift:25-36` defaults
`skipStore`, `skipCountStore`, `pendingCompletionStore`, `excludeStore`,
`completionCounter`; `SkippedReminderSyncService.swift:28-39` injects all six
preference types plus three stores).
