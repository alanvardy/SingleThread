### Push (sender builds snapshot; transport = `updateApplicationContext`)
- `pushAll()` — `SkippedReminderSyncService.swift:176-214`. Builds one combined `[String: Any]` dictionary, then `try session.updateApplicationContext(context)` at `:212`. All six keys are read from the injected preference stores and embedded:

  - `:187` showDate only `if sendsShowDate`; `:190` showRecurrence only `if sendsShowRecurrence`; `:193` showAlarms only `if sendsShowAlarms`; `:196` showList only `if sendsShowList`; `:199` showCompletionGlow only `if sendsShowCompletionGlow`.
- `sends*` flags are init parameters defaulting to `true` — `SkippedReminderSyncService.swift:44-48`.

### iOS (phone) push triggers — `SingleThread/AppViewModel.swift`
1. `store.onShowUndatedRemindersChanged = { _ in service.pushAll() }` — `:61` (fires whenever the `ReminderStore.showsUndatedReminders` didSet fires).
2. `store.onSkipSetChanged = { _ in service.pushAll() }` — `:60`; `store.onExcludedListsChanged = { _ in service.pushAll() }` — `:62`; `store.onSortOptionChanged` persists sort then `service.pushAll()` — `:71-73`.

4. `setupEntitlementObservation()` fires `pushAll` on `isEntitled` changes — `:404-408`.

### Watch push (watch → phone)
- The watch constructs the service with all six stores as `…Preference(defaults: .standard)` — `SingleThreadWatch/WatchAppViewModel.swift:166-171` — and `sendsShowDate: false, sendsShowRecurrence: false, sendsShowAlarms: false, sendsShowList: false, sendsShowCompletionGlow: false, sendsEntitled: false` — `:174-175`.
- The only watch push trigger is `store.onSkipSetChanged = { _ in service.pushAll() }` — `:202` (skip sync). Because of the `sends* = false` flags, the watch-pushed context contains **only the unconditional keys**: `showUndatedReminders` (read from the watch `.standard` store), plus skip IDs/counts/excluded titles/sort/completionCount. The other five preference keys are never sent watch → phone.

### Receive (both sides share one code path)
- `session(_:didReceiveApplicationContext:)` — `SkippedReminderSyncService.swift:242-244` → `apply(context:)` — `:320`. Latest-wins: each present key is decoded, persisted, then its hook fired; absent keys are no-ops (`:321-377`).
- Per-key receive sequence (persist step → hook):
  - `showUndatedReminders` — `showUndatedStore.save(received)` `:340`, then `onShowUndatedRemindersReceived?(received)` `:341`.
  - `showDate` — `showDateStore.set(showDate)` `:351`, then `onShowDateReceived?(showDate)` `:352`.
  - `showRecurrence` — `:356-357`; `showAlarms` — `:361-362`; `showList` — `:366-367`; `showCompletionGlow` — `:371-372`.

### Where the applied value is written, per side
- **Watch-side receive**: the stores injected at `WatchAppViewModel.swift:166-171` all use `defaults: .standard`, so `save`/`set` land in **`UserDefaults.standard`** on the watch. Then:
  - `onShowDateReceived` → `ShowDateState.apply(value)` — `WatchAppViewModel.swift:228-230` → `preference.set(value)` to `.standard` (`ShowDateState.swift:22-24`) and publishes `isEnabled`.
  - Same pattern for recurrence `:231-233` / `ShowRecurrenceState.swift:22-24`, alarms `:234-236` / `ShowAlarmsState.swift:22-24`, list `:237-239` / `ShowListState.swift:22-24`, completionGlow `:240-242` / `ShowCompletionGlowState.swift:21-23`.
  - `onShowUndatedRemindersReceived` — `WatchAppViewModel.swift:176-181` — sets the store property and reloads (persistence was the `save` at `SkippedReminderSyncService.swift:340`, which because of `.standard` lands in `UserDefaults.standard`).
  - State holders are created at `WatchAppViewModel.swift:36-40`; their `init` re-reads `.standard` (`Show*State.swift` init).
- **Phone-side receive**: the iOS service uses the default stores (`AppGroup.defaults`), so any incoming context values would be `save`/`set` into the **App Group**. However, `AppViewModel` wires **none** of the six `onShow*Received` hooks (only `onCompleteReminderReceived`, `onDeleteReminderReceived`, `onExcludedListTitlesReceived`, `onSkipCountsReceived` — `AppViewModel.swift:50-58`), so on iOS the incoming six keys are inert except for the App-Group write. In practice the watch never sends them anyway (`sends* = false`).
- **Widget**: no sync involvement — reads `AppGroup.defaults` directly at timeline generation (`NextThingWidget.swift:64-67,71`). It never writes the six keys.
- **Message path (non-context)**: `sendMessage` carries `completeReminderIdentifier` / `deleteReminderIdentifier` only (`SkippedReminderSyncService.swift:218-238`, handled at `:247-257`) — not the six preference keys.

### Direction summary
- Effective preference direction is **phone → watch only**: the five `sends*`-gated keys are pushed solely by the phone; `showUndatedReminders` is pushed by both sides, but the watch copy originates from the phone-applied value (a `.standard` mirror of what the phone sent).
