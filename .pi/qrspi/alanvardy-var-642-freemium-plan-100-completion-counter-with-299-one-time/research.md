## Q1: Completion funnel

### Findings
- **Single convergence point:** every surface reaches `ReminderStore.completeReminder(identifier:)` (`SingleThreadCore/Sources/SingleThreadCore/ReminderStore.swift:145`), which branches `#if os(watchOS)` (`:146–152`) vs `#else` (`:154–167`).
- **EventKit save** (iOS/macOS branch): `reminder.isCompleted = true` then `try eventStore.save(reminder, commit: true)` (`ReminderStore.swift:158–159`), followed by 200 ms settle (`eventKitSettleDelay`, `:364`) and `await reload()` (`:160–161`). The save goes through the `EventKitStoring` protocol (`EventKitStoring.swift:29–32`, `#if !os(watchOS)` at `:26`); tests use `InMemoryEventStore.save`, which just appends (`InMemoryEventStore.swift:64–66`).
- **Return semantics:** `-> Bool`, `@discardableResult`. Non-watch: `false` on missing identifier (`:156`), `false` on save throw (logged, `:164–165`), `true` only after save + reload (`:162`). Watch: `true` iff a locally-held reminder matched (optimistic removal; EventKit never touched, `:147–152`). `completeCurrentReminder()` (`:171–174`) forwards `visibleReminders.first`'s identifier and returns `false` when none exists.
- **iOS surfaces:** leading swipe (`SingleThread/ContentView.swift:345–352`, `.leading`, task at `:347`); bottom action cluster (`completeButton` `:421–431`, cluster `:445–450`, rendered only when `viewModel.showsActionButtons` at `:407–408`); macOS button bar (Complete `:220–230`, `keyboardShortcut("c")` `:228`, rendered only when a visible reminder exists, `:383–385`). Context menu has **no Complete** — only "View in Reminders" deep-link (`:327–336`) and Delete (`:337–343`). All route through `ContentViewModel.completeCurrentReminder()` (`ContentViewModel.swift:108–112`), which triggers the completion glow only when `await store.completeCurrentReminder()` returns true **and** `showCompletionGlow.isEnabled` (`:109–110`).
- **Watch surface:** button at `SingleThreadWatch/WatchReminderView.swift:103–111` → `WatchReminderViewModel.completeCurrentReminder()` (`WatchReminderViewModel.swift:48–52`) → watch branch (local removal + `onCompleteReminder?(identifier)` fired at `ReminderStore.swift:150`). Glow gated on `showCompletionGlowState.isEnabled` (`WatchReminderViewModel.swift:49`).
- **Watch relay:** `WatchAppViewModel.swift:167` wires `store.onCompleteReminder → service.requestCompleteReminder(identifier)`; send is fire-and-forget `session.sendMessage([PayloadKey.completeReminderIdentifier: identifier], replyHandler: nil)` (`SkippedReminderSyncService.swift:177–185`). Phone receives in `session(_:didReceiveMessage:)` (`:204–208`) → `AppViewModel.onCompleteReminderReceived` → `Task { await store?.completeReminder(identifier:) }` (`SingleThread/AppViewModel.swift:41–43`) → re-enters the same `#else` branch (EventKit save + reload). No acknowledgement path back to the watch.
- **Widget surface:** `Button(intent: CompleteReminderIntent())` (`SingleThreadWidget/NextThingWidget.swift:158–166`); intent builds a fresh `ReminderStore(loadsReminders: true)`, reloads, calls `completeCurrentReminder()` and **ignores the Bool** (`ReminderIntents.swift:18–24`).
- **Hooks after mutation:** `reload()` always ends with `onRemindersChanged?()` (`ReminderStore.swift:320`, declared `:82`). iOS/macOS wires it to `WidgetCenter.shared.reloadAllTimelines()` (`AppViewModel.swift:72–74`). Watch never wires `onRemindersChanged`. Widget extension wires no hooks (fresh store, all nil) — WidgetKit auto-reloads the tapped widget's timeline after `perform()` (`ReminderIntents.swift:4–6`).
- **No completion counter exists anywhere today** (grep for `completionCount`/`maxCompletions` returns only `.pi/` docs).

### Findings

## Q6: Watch + widget mutation constraints

### Findings
- **Shared mutation core:** `ReminderStore` is `@MainActor @Observable` (`ReminderStore.swift:13–14`) compiled into iOS, watchOS, macOS, and widget intents; each surface constructs its **own instance** against the same underlying stores.
- **Watch EventKit read-only, enforced at three layers:**
  1. `#if os(watchOS)` branches that never touch EventKit: `completeReminder` (`:146–152`), `deleteReminder` (`:182–185`), `addReminder` returns `false` unconditionally with comment "On watchOS, EventKit is read-only" (`:212–213`), `reload()` skips `refreshSourcesIfNecessary()` (`:266–267`).
  2. Protocol level: `EventKitStoring` declares `save`/`remove`/`makeReminder` only inside `#if !os(watchOS)` (`EventKitStoring.swift:31–46`) — no write surface compiles on watch.
  3. UI operations relay through hooks: `store.onCompleteReminder → service.requestCompleteReminder` (`WatchAppViewModel.swift:167`), `onDeleteReminder → requestDeleteReminder` (`:168`), `onSkipSetChanged → pushAll()` (`:164`).
- **Relay service:** `SkippedReminderSyncService` (`#if os(iOS) || os(watchOS)`, `:4`). Payload keys `PayloadKey.completeReminderIdentifier`/`deleteReminderIdentifier` (`:238–239`); hooks `onCompleteReminderReceived`/`onDeleteReminderReceived` (`:74`, `:79` — `nonisolated(unsafe)`, write-once-before-`activate()` invariant at `:65–72`). Send: `sendMessage` fire-and-forget, `replyHandler: nil` (`:177–194`). Receive: `didReceiveMessage` (`:204–211`) snapshots and invokes handlers. Tests asserting the relay: `SkippedReminderSyncServiceTests.swift:287–295, 297–304, 326–334, 336–343`.
- **Phone receive handlers:** `AppViewModel.swift:41–43` (complete), `:45–47` (delete) — `Task { await store?.complete/deleteReminder(identifier:) }` into the shared store (iOS branch, real EventKit write). `AppViewModel.swift:57,62` wire the reverse direction but are documented inert on iOS (iOS branches never fire those hooks). Sync wiring gated on `WCSession.isSupported(), !usesInMemoryStore` (`:27`).
- **Widget fresh-store constraint:** every intent `perform()` builds `ReminderStore(loadsReminders: true)` (`ReminderIntents.swift:19–20, 43–44`); every timeline `makeEntry()` too (`NextThingWidget.swift:70–73`). All hooks are nil in the extension process — no push, no `onRemindersChanged`; WidgetKit auto-reloads the widget's timeline after `perform()` (`ReminderIntents.swift:11–12`). Widget Complete runs the **iOS branch** (genuine EventKit save). Widget Skip uses `skipCurrentReminderImmediately()` (`:46`), the no-settle variant whose doc cites WidgetKit process suspension safety (`ReminderStore.swift:251–256`, impl `:257–263`). **No delete intent exists.**
- **Per-surface matrix:** iPhone = one long-lived store, direct + relay completes/deletes, EventKit writes yes. Watch = one store, complete/delete relay (no EventKit), skip local + `pushAll`. Widget timeline = read-only display. Widget intents = complete (EventKit write) and skip (App Group write).

## Cross-Cutting Observations

- **One store, many instances.** `ReminderStore` is the single mutation engine; the phone holds one long-lived instance, the watch one, and widget intents/timeline create a fresh one per operation with nil hooks. Persistence-sharing therefore happens via `AppGroup.defaults` (phone↔widget) and WatchConnectivity (phone↔watch) — two independent channels, with `.standard` fallback making watch reads device-local.
- **Mutation return values are surface-dependent.** Only the iOS/macOS branch of `completeReminder` reflects a real EventKit save in its Bool (`ReminderStore.swift:162`); the watch branch is optimistic/local (`:147–152`) and its relay is unacknowledged (`replyHandler: nil`, `SkippedReminderSyncService.swift:180`); the widget intent discards the Bool (`ReminderIntents.swift:22`). Any success-gated behavior must account for all three shapes.
- **Observable hooks after mutations:** `onRemindersChanged` fires only on the phone (via `reload()` at `ReminderStore.swift:320`) and drives `WidgetCenter.reloadAllTimelines()`; the watch wires `onCompleteReminder`/`onDeleteReminder`/`onSkipSetChanged` only; widget extensions wire nothing.
- **Key-name discipline:** one userspace string per synced key shared across the Core store-struct, phone `@AppStorage`, the private `PayloadKey` enum, and `UITestingSeed.persistedKeys`; maintained by convention. Two known exceptions: widget's raw `showUndatedReminders` read and `backgroundFadePercent` missing from the seed reset list.
- **Settings plumbing is uniform:** struct ⇄ `@AppStorage` ⇄ `SettingsBindings` bag ⇄ sheet write-back ⇄ (store hook | defaults-diff) ⇄ `pushAll()` snapshot; `PayloadKey` names literally equal the UserDefaults keys.
- **Conventions relevant to feature work:** mutations go through view models on iOS but straight through `viewModel.store` on watch; Complete is always async, Skip always sync, Delete always async; `.disabled` is rare (2 sites), conditional rendering is preferred; only one confirmation dialog exists (watch refresh/delete); warnings-as-errors + SwiftLint `--strict` + SwiftFormat in CI (`AGENTS.md`); `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` only on app+watch targets.
