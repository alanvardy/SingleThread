# Research Findings

Scope: iOS reminder list & card rendering (`SingleThread/`) and skip-count persistence (`SingleThreadCore/Sources/SingleThreadCore/`). Path shorthand below: `Core/X.swift` = `SingleThreadCore/Sources/SingleThreadCore/X.swift`.

## Q1: Reminder card width flow — from `List` row through `.cardPlate` to `ReminderCardView`

### Findings
- **List & row scaffold** (`SingleThread/ContentView.swift`): content sits in a `GeometryReader` (:373); `viewHeight` = height minus safe-area edges (:374-376). The list holds exactly one visible `ReminderCardView` row (:415-427).
- **Row modifier chain (SwiftUI order — later = outer)** (:428-435), the decisive width chain:
  1. `.listRowBackground(viewModel.rowChromeBackground)` :428 — `rowChromeBackground` is `.clear` (ContentViewModel.swift:73-75), photo shows through.
  2. `.padding(.horizontal, 40)` :429 — **caps card width at rowWidth − 80**.
  3. `.padding(.vertical, 12)` :430 — height only.
  4. `.frame(maxWidth: .infinity, alignment: .center)` :433 — **the stretch-to-full-width mechanism**: fills the plain-style row, centers the padded card horizontally.
  5. `.frame(minHeight: viewHeight, alignment: .center)` :434 — centers vertically in the viewport.
  6. `.listRowSeparator(.hidden)` :435.
- **List styling**: `.listStyle(.plain)` :475; `.scrollContentBackground(.hidden)` :479 with comment (:474) that iPadOS gives `List` an opaque scroll background that would hide the photo; `.background(Color.clear)` :482. `.refreshable` :488. **No `listRowInsets` anywhere** — plain-list default insets apply.
- **Card interior** (`SingleThread/ReminderCardView.swift`): `VStack(alignment: .leading, spacing: 4)` :35 → `.cardPlate(fill: CardPlate.plateFill(for:), padding: 12, restoresGeometry: true)` :44.
- **CardPlate modifier** (`SingleThread/CardPlateModifier.swift`): `content.padding(padding)` → `RoundedRectangle(cornerRadius: 10).fill(fill)` → `.padding(restoresGeometry ? -padding : 0)` (:23-30). With `restoresGeometry: true` the +12/−12 cancel — **outer geometry is net-zero**, so the plate is purely a background shape; the row frame modifiers above are what size it. Doc comment: only the card-text plate uses restore; prompt/empty-state plates occupy genuine layout (:9-16). `cardPlate` extension entry point :45-50.
- **Subcomponents**: the swipe `prompt` has `.frame(maxWidth: .infinity)` then `.cardPlate(promptBoxFill)` (ReminderCardView.swift:206-207), forcing full row width when visible. The `nudgeBanner` deliberately avoids `maxWidth: .infinity` (doc :138-142 says an unbounded banner would stretch the content-hugging plate edge-to-edge).
- **Net chain determining final card width**: `List` (plain, full row width) → `padding(.horizontal, 40)` :429 → `frame(maxWidth: .infinity, center)` :433. The plate itself hugs content (net-zero padding), so unless the swipe prompt shows, plate width = intrinsic VStack text width, centered in the row. Height comes from `.padding(.vertical, 12)` + `.frame(minHeight: viewHeight)` :430/434.
- `ContentView+iOS.swift` / `ContentView+ActionMenu.swift` contain no reminder rows (only nudge sheet and action buttons/menus).

## Q2: Skip-count data flow — persistence, surfacing, and the label

### Findings
- **Storage**: `SkipCountStore` (Core/SkipCountStore.swift) persists a `[String: Int]` map (`EKReminder.calendarItemIdentifier` → count) in `UserDefaults` key `"skipCounts"` (:6-8, :29-37). Defaults = `AppGroup.defaults` = `UserDefaults(suiteName: "group.app.alanvardy.SingleThread") ?? .standard` (Core/AppGroup.swift:11-18).
- **Threshold logic (pure, nonisolated)**: `SkipCountLogic.defaultThreshold = 6` (SkipCountStore.swift:12); `shouldNudge(_:threshold:)` = `count >= threshold` (:14-16); `crossedThreshold(from:to:)` = `old < threshold && new >= threshold` — fires **once on first crossing** (:17-19, doc :20-25); count must reset or be pruned to re-cross.
- **Write path**: UI skip entry points all call `viewModel.skipCurrentReminder()` (ContentViewModel.swift:149-151) — bottom-bar skip button (ContentView+ActionMenu.swift:30-48; embedded in `actionCluster` ContentView.swift:519-522), trailing swipe action (ContentView.swift:465-470). `ReminderStore.skipCurrentReminder()` (ReminderStore.swift:380-412) calls private `incrementSkipCount(for:)` (:571-578): loads map, `new = old + 1`, `skipCountStore.save(counts)` (:572-576), returns `crossedThreshold(from:to:)`.
- **6th-skip interrupt**: on iOS/watchOS, if crossing returns true the store fires `onSkipNudgeRequested?(identifier)` and **returns without advancing the card** (:384-389, hook declared :95). macOS always advances (:390-392). Widget path `skipCurrentReminderImmediately()` increments and always applies the skip (:421-433, hook at :428). Non-crossing skips build the new skip set, then async `settle → applySkipSet → reload` (:393-402); `applySkipSet` saves IDs and fires `onSkipSetChanged` (:614-620).
- **Count resets**: `resetSkipCount(for:)` (:581) on complete (:236, :248), delete (:300, :306), reschedule (:352, :369); `reconcileSkipCounts(visibleShown:)` (:590) prunes out-of-window IDs during `reload` (called :685); counts survive `clearSkipped` (:682-684, addressed by legit re-adds).
- **Surfacing**: `onSkipNudgeRequested` wired in `ContentViewModel.init` → sets `nudgeIdentifier` (ContentViewModel.swift:27-29); `isNudged(_:)` compares (:216-218). ContentView passes `showNudge: viewModel.isNudged(reminder.calendarItemIdentifier)` (ContentView.swift:426); `ReminderCardView` renders `nudgeBanner` in the VStack (:37-38, :143-159).
- **Label is STATIC, not derived from the stored count** (key finding): banner text = `Text(SharedStrings.skipNudgeTitle)` (ReminderCardView.swift:147), which is `String(localized: "Skipped 6 times", …)` (Core/LocalizedString+Shared.swift:25-28, doc :24). Accessibility label is also a hardcoded literal `"Skipped 6 times — tap to manage"` (ReminderCardView.swift:157). The per-reminder reader `skipCount(for:)` (ReminderStore.swift:516-518) is consumed **only by unit tests** (ReminderStoreTests.swift:530, :576), never by view code. So the visible "6" and `SkipCountStore.swift:12` are two independent hardcoded 6s; changing the threshold does not change the label.
- **Watch sync**: `onSkipSetChanged` → `syncService.pushAll()` (AppViewModel.swift:391), packing `PayloadKey.skipCounts: countStore.load()` (Core/SkippedReminderSyncService.swift:190, key :281). Receive side saves counts and fires `onSkipCountsReceived` (:467-475); handlers reload and reconcile (AppViewModel.swift:388, WatchAppViewModel.swift:208-210). Receiving never increments.
- **Nuance**: because the 6th-skip interrupt returns before `applySkipSet` (:384-389 vs :393-402), `onSkipSetChanged`/`pushAll` does not fire for that exact bump — the count of 6 persists locally but reaches the watch only on the next hook-firing mutation.

## Q3: Sheet sizing on iPad vs iPhone — post-skip management sheet & reschedule sheet

### Findings
- **Zero explicit sizing anywhere**: no `presentationDetents` / `presentationStyle` / `presentationSizing` / `UISheetPresentationController` / `preferredContentSize` matches in any Swift source (verified by grep across SingleThread/, Core, Watch, Widget). Every sheet uses the plain `.sheet` modifier → SDK-default presentation (pageSheet-style, single full-height detent on iPadOS; deployment target iOS 18.7 per `SingleThread.xcodeproj/project.pbxproj:765,815,843`).
- **All four sheet attachment points** (`SingleThread/ContentView.swift`): settings :294-295; purchase :297-299 (container `NavigationStack`, PurchaseSettingsView.swift:201-215); reschedule :302-303 (`actionMenuRescheduleSheet`); nudge :306-307 (`nudgeSheetContent`). State: `isShowingNudgeSheet` :137, `isShowingRescheduleSheet` :140.
- **Post-skip (nudge) management sheet** — `nudgeSheetContent` (ContentView+iOS.swift:56-82): `NavigationStack` → `VStack(alignment: .leading, spacing: 16)` holding `RescheduleSheet` + View-in-Reminders + Delete, `.padding()` then `.frame(maxWidth: .infinity, alignment: .leading)` (:74); Cancel in `.toolbar` `.cancellationAction` (:77). Entered by tapping the banner (ReminderCardView.swift:143-159; tap wired via `onNudgeTap` ContentView.swift:414/427).
- **Reschedule sheet** — `actionMenuRescheduleSheet` (ContentView+ActionMenu.swift:175-193): `NavigationStack` → `RescheduleSheet` + Cancel toolbar. `RescheduleSheet` itself: `VStack(alignment: .leading, spacing: 16)`, optional nudge text, `DatePicker`, Reschedule button, `.frame(maxWidth: .infinity, alignment: .leading)` (RescheduleSheet.swift:17-50, frame at :49). Triggered by iOS `confirmationDialog` Reschedule (ContentView+ActionMenu.swift:51-53) and macOS `Menu` Reschedule (:116-118) — same shared sheet used by nudge and action menu.
- **What produces large blank areas above/below content on iPad**: no `.presentationDetents` → system default single large (full-height) detent; the short top-aligned VStacks sit full-height with blank space below. Nothing bounds height — no `maxHeight`, no content-sized presentation. `.frame(maxWidth: .infinity)` (ContentView+iOS.swift:74, RescheduleSheet.swift:49) stretches width only. macOS-only contrast: settings sheet `#if os(macOS) .frame(minWidth: 400, minHeight: 500)` (ContentView.swift:577-579). The content-hugging cap pattern exists only for empty states (`EmptyStateCard.maxContentWidth`) and is **not** applied to sheets.
- **Related card facts**: card row stretch chain ContentView.swift:428-434; nudge banner content-sized (ReminderCardView.swift:138-142).
- **Tests** assert no dimensions/detents/iPad layout: SkipNudgeUITests.swift:26,:63; ActionMenuUITests.swift:66.

## Q4: Adaptive layout patterns — iPad vs iPhone

### Findings
- **Pattern A — viewport-relative width cap** (`EmptyStateCard.maxContentWidth(viewportWidth:)` = `min(340, viewportWidth * 0.6)`, SingleThread/EmptyStateCard.swift:42-44, doc :36-41 "Relative so the card stays proportionate on iPads, with an absolute ceiling").
  - Applied to empty/all-done states: `.allDone` ContentView.swift:383 and `.empty(hasHidden:)` :398, both via the GeometryReader :373; description `.frame(maxWidth: maxWidth)` EmptyStateCard.swift:31.
  - **Not applied to the reminder card**: ReminderCardView has no width cap (ReminderCardView.swift:20-38); its text is unconstrained.
- **Pattern B — content-hugging + centering** (cap + `.frame(maxWidth: .infinity)` + `.center`):
  - Empty/all-done: centering delegated to caller — `.frame(maxWidth: .infinity, minHeight: viewHeight, alignment: .center)` ContentView.swift:386 and :399, with the cap inside EmptyStateCard.swift:31.
  - Reminder card: only the centering half exists — `.frame(maxWidth: .infinity, alignment: .center)` ContentView.swift:433; the width-cap half is absent. Card interior stays leading via `VStack(alignment: .leading)` ReminderCardView.swift:35.
  - Elsewhere: watch `WatchReminderView.swift:368` (and :115, :173), widget `NextThingWidget.swift:161`.
- **Pattern C — size-class checks (`horizontalSizeClass`/`userInterfaceSizeClass`)**: **zero matches** in all four targets (app, Core, Watch, Widget, tests).
- **Pattern D — device-idiom checks (`userInterfaceIdiom`/`.pad`)**: **zero matches**; only a comment about Split View/Slide Over deny (AppDelegate.swift:29).
- **Pattern E — `#if os(...)` divergences**: only one iPadOS-specific and it's unconditional list scaffolding, not a card: `.scrollContentBackground(.hidden)` + `.background(Color.clear)` ContentView.swift:476-482 (comment :474). `#if os(iOS)` blocks exist for macOS-vs-iOS only: `.contextMenu` :436, `swipePromptBinding` :351, swipe actions :446-466. `ListContent` switch sites: Core/ListContent.swift:6-24 (resolver), ContentView.swift:377, WatchReminderView.swift:133-144, NextThingWidget.swift:139-150.
- **Fixed-size chrome**: `ControlPlateModifier.plateSize = 56` (SingleThread/ControlPlateModifier.swift:47) — same on all devices.
- **Patterns NOT applied to the reminder card**: the `maxContentWidth` cap (A) — empty states only. Size-class and idiom branching (C, D) exist nowhere in the repo.

## Cross-Cutting Observations

- **Card plate = pure background shape**: `restoresGeometry` net-zero padding (CardPlateModifier.swift:23-30) means all card *sizing* lives in the row modifiers in ContentView (padding 40 / maxWidth infinity / minHeight) — nothing inside the card controls width except the swipe prompt's `maxWidth: .infinity`.
- **The two 6s**: nudge threshold 6 (SkipCountStore.swift:12) and the hardcoded label "Skipped 6 times" (LocalizedString+Shared.swift:25-28) are disconnected constants; the label never reads the persisted count, and `skipCount(for:)` (ReminderStore.swift:516) is test-only.
- **No size-class / idiom branching anywhere**: the codebase is iPhone-first everywhere; iPad differences are handled only by (a) viewport-relative caps on empty states (EmptyStateCard.swift:42-44) and (b) the unconditional list-background fix (ContentView.swift:476-482). The reminder card participates in neither adaptation.
- **Sheets are never content-sized**: all four `.sheet`s rely on the SDK default full-height pageSheet; the two short sheets (nudge :56-82, reschedule :175-193) top-aligned `.leading` VStacks inside NavigationStack with only `maxWidth: .infinity` stretch — blank space below content on iPad.
- **Card/nudge flows are well-tested but never layout-asserted**: unit tests pin objects (CardPlate, modifier chain, SkipCountStore logic, RescheduleSheet helpers); UI tests drive end-to-end via `--seed` with skipCounts but assert no frames/dimensions; no iPad UI assertions exist.
- **Skip-count sync gap on the 6th skip**: interrupt return before `applySkipSet` (ReminderStore.swift:384-389) skips the `onSkipSetChanged`→`pushAll` hook for the crossing bump — a real behavior any watch-facing change must account for.
