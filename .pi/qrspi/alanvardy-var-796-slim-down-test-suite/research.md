# Research Findings

Scope: four test targets — `SingleThreadTests` (470 Swift Testing `@Test`), `SingleThreadWatchTests` (38), `SingleThreadUITests` (52 XCTest), `SingleThreadWatchUITests` (17 XCTest). Counts verified live via `scripts/count_tests.sh` (508 unit total; comment literals inside that script are stale — e.g. `count_tests.sh:9,10,20,21,22`). All paths relative to repo root.

## Q1: Empirical timing profile and measurement tooling

### Findings
- **Local result-bundle producers are only the three Makefile coverage targets**: `coverage` → `build/Coverage.xcresult` (`Makefile:37-48`), `coverage-ui` (`Makefile:50-61`), `coverage-all` (`Makefile:63-73`), all with `xcrun xccov view --report` after. Bundles at `build/` (`Makefile:10-12`), gitignored (`Makefile:10-12` refs; `.gitignore:11`).
- **`scripts/test.sh` records no phase wall times**: no `time`, `date`, `SECONDS`, or `-showBuildTimingSummary` anywhere; phases are sequential `==> banner` blocks (`test.sh:196-296`). Phase flags: iOS unit uses `-parallel-testing-enabled YES` + `-maximum-test-execution-time-allowance 900` (`test.sh:234-235`) and `test-without-building` (`:236`); UI/tests use no parallel flags (`test.sh:241-245`); macOS phase is a single `test` action (build+test combined, `test.sh:287-294`); watch build-for-testing builds both watch bundles (`test.sh:249-254`). All test phases are `test-without-building`, so per-phase compile time is attributable only to that phase's `build-for-testing` step.
- **CI**: `-showBuildTimingSummary` on build steps only (`ci.yml:63,131,192,251,302,363,418`), emitted as step stdout — never archived. Result bundles only on failure (`TestResults.xcresult` upload `ci.yml:80-87`; `TestResults-mac.xcresult` `ci.yml:313-322`). Timeouts: build 20 min (`ci.yml:55`), unit 35 min (`:66`), UI 45 min (`:134,195,254`), watch build 20 / UI 45 (`:409,421`). CI disables parallel testing for unit+UI (`ci.yml:76-77,145-146,204-205,265-266`), opposite of local `test.sh:234`.
- **Machine artifact survey** (M4 Pro, Xcode 26.6): 30 `~/Library/Developer/Xcode/DerivedData/SingleThread-*/` dirs hold 10 Test bundles **all from older working copies (var-747…var-788), none from var-796**; repo-local `DerivedData/` does not exist for this repo. No `SingleThreadWatch-*` bundle exists anywhere — no watch-phase timing evidence.
- **Per-test durations are extractable**: `xcrun xcresulttool get test-results tests` yields leaf `durationInSeconds` (no per-test startTime in schema). Sample observed: unit bodies 0.2–1.5 s (33-test bundle sum 10.8 s; outlier `reentryGuardBlocksConcurrentCalls` 1.52 s); UI bodies 7.5–29 s (sum 38.5 s for 4 tests; 29.06 s single relaunch test). Wall-clock vs body split: warm incremental compile 4–18 s, launch/install 24–60 s, plus large un-itemized infrastructure (e.g. ~598 s of 641.8 s in a 3-clone coverage run) the action-log tree attributes to no named child.
- **What cannot be established without running**: cold-build compile times for any phase, any var-796 wall time at all (no local run exists), watch phase timings, local `test.sh`-flags profile (parallel YES local vs NO CI), per-test start times.

## Q2: Structure of runtime cost in the suites

### Findings
- **Guaranteed sleeps** (floor cost): notification family totals ~15 s unconditional `Task.sleep` — `backgroundAndForeground` helper 3 s × 4 tests (`NotificationSchedulingUITests.swift:33-40`), `NotificationsUITests.swift:58,60` (2+1 s); plus `usleep(500_000)` after toggle flips in both files (`:31`, `:19`), `usleep(300_000)` (`ActionMenuUITests.swift:108`), 100 ms poll tick in `flipToggle` (`SingleThreadUITestCase.swift:37`, loop `:28-44`).
- **Configured wait budgets are upper bounds** (`waitForExistence` returns on appearance; ~1 s poll cadence documented at `SingleThreadWatchUITestsFlows.swift:299`): `SingleThreadUITestsFlows.swift` 348 s sum (two 5 s `waitForNonExistence` at `:139,142`), watch `Flows` 191 s (10 s at `:69`, 8 s at `:310`), `SkipNudgeUITests.swift` 77 s, `ActionMenuUITests.swift` 61 s.
- **App-side time invisible to test code dominates**: 200 ms EventKit settle sleep after every mutation — `ReminderStore.swift:38-40` default, applied at complete/undo/delete/add/reschedule/skip (`:249,:280,:307,:340,:370,:396`); the app composition never injects a substitute (`AppViewModel.swift:257-285`), so **every mutation tap in every UI test pays 200 ms**. Plus 1 s minimum display duration after refresh (`ContentViewModel.swift:186-187`), 0.5 s glow production duration (`CompletionGlow.swift:35-42`), 5 s watch `asyncAfter` behind the live-exclusion test's 10 s wait (`WatchAppViewModel.swift:287-291`).
- **Serialized suites = every explicit `@Suite`**: 20 in `SingleThreadTests/` + 4 in `SingleThreadWatchTests/` (grep shows zero non-serialized `@Suite`). Concentration: `ReminderStoreTests` (`ReminderStoreTests.swift:15`) + 3 nested (`:511,:720,:898`) + `ReminderStoreGateTests` (`:11`) + 3 `EventKitStoringTests` suites (`:148,:355,:502`) ≈ 70 tests forced sequential by annotation, mostly on file-scope `EKEventStore` fixtures and timing-sensitive mutations. Unit wait budget is structurally negligible: ~4.2 s total across 4 iOS files (EntitlementStoreTests `:57,83`, CompletionGlowTests `:35-40`, ReminderDictationTests `:53,59,272,293`) + 0.2 s watch (`ShowCompletionGlowStateTests.swift:225,256`); unit tests avoid settle via `noopSettle` (`ReminderStoreTests.swift:12`, `ReminderStoreGateTests.swift:8`).
- **App launches: 56 iOS (52 tests) + 17 watch (17 tests)**; no launches in any `setUp`/`tearDown`. iOS: 33 launches from `SingleThreadUITestsFlows.swift` alone (3 relaunch tests: `testBackgroundAndPinTogglesPersistAcrossRelaunch` 3 launches/2 `terminate` `:303-351`; `testReminderTogglesPersistAcrossRelaunch` 2/1 `:426-448`; swipe-prompt persistence 2/1 `:530-546`). Watch: exactly one launch per test, no terminate/relaunch. `runsForEachTargetApplicationUIConfiguration = false` in 4 iOS files (`SingleThreadUITests.swift:18-20` et al.); watch launch class keeps `true` (`SingleThreadWatchUITestsLaunchTests.swift:6-8`).
- **Per-launch work**: `--seed` launches parse JSON (`UITestingSeed.swift:48-56`), materialize a real `EKEventStore`+`EKCalendar`+`EKReminder` (`:96-134`), run `resetPersistedState()` — 24 keys × 2 stores = 48 `removeObject` calls (`UITestingSeed.swift:62-69,73-96`), then seed `completionCount`/`skipCounts`/`enableActionButtons` (`AppViewModel.swift:309-320`). `--ui-testing` launches do **not** reset (deliberate — relaunch-persistence tests, `SingleThreadUITestsFlows.swift:302,425-427,529-538`).
- **Likely dominant-cost tests**: the 4 `NotificationSchedulingUITests` (3 s sleeps each + real background/foreground + first SpringBoard "Allow" dialog), the relaunch trio, watch `testLiveExclusionHidesReminderWithoutRelaunch` (~5 s real), watch `testCompleteHoldsCardDuringGlow` (2.5 s real glow), `testCodeBlocksRenderWithoutBacktickFences` (`XCTNSPredicateExpectation` polling whole tree, `Flows:403-404`), and the accessibility audits (`SingleThreadUITests.swift:43-57`, `ActionButtonsUITests.swift:70-76`, `NotificationsUITests.swift:103-110`).

### Findings

- **Bypass seams (S1-S11)**: `InMemoryEventStore.authorizationStatus = .fullAccess` (`InMemoryEventStore.swift:37-39`) + `requestFullAccessToReminders → true` (`:45-47`); `FakeEventStore` configurable auth + recording request (`EventKitStoringTests.swift:13,29,56-70`); `loadsReminders: false` (`ReminderStore.swift:199`); `authorizationStatus: .fullAccess` init seed (`ReminderStore.swift:33,50,72`); `--seed` (every seeded launch reads `.fullAccess` on `start()`, plus reset clears `notificationsEnabled` so toggles start OFF); `--ui-testing` iOS/watch (`AppViewModel.swift:279-286`, `WatchAppViewModel.swift:149-166`); `--no-reminders` (`AppViewModel.swift:288`). ## Q6: Shared state, isolation, and suite serialization

### Findings
- **Defaults topology**: App Group `group.app.alanvardy.SingleThread` (`AppGroup.swift:11`), `defaults = UserDefaults(suiteName:) ?? .standard` (`:16-18`). **On watchOS (and unregistered sims) `AppGroup.defaults === UserDefaults.standard`** (doc `AppGroup.swift:12-15`, `PendingCompletionStore.swift:8-14`) — so a real key written in watch unit tests and watch UI tests is one shared domain; that is why `ShowCompletionGlowStateTests` (`.standard` `showCompletionGlow`, `:26-29`), `ShowEnableActionButtonsStateTests`, and watch sync suites are all `.serialized`. On the iOS simulator the suite persists **across the iOS unit phase and iOS UI phase** (same pre-booted sim, phases sequential, `test.sh:28-47`) — unit-host leftovers reach later `--ui-testing` launches; `--seed` launches wipe first.
- **Persisted key inventory** (24-key authoritative reset list, `UITestingSeed.swift:73-96`; `resetPersistedState()` `:62-69` removes each from both `AppGroup.defaults` and `UserDefaults.standard`): `skippedReminderIdentifiers` (`ReminderSkip.swift:124`), `skipCounts` (`SkipCountStore.swift:26`), `excludedListTitles` (`ExcludedListStore.swift:7`), show-* prefs (`BoolPreferenceKey.swift:10-21` + `@AppStorage` `ContentView.swift:115-132`), `sortOption` (`SortOption.swift:17,25`), `completionCount` (`CompletionCounterStore.swift:20`), `isEntitled` (wire-protocol key only — no defaults write, `EntitlementStore.swift:57-59`; listed for hygiene), `enableActionButtons`, `.standard` keys `showMicrophoneButton`/`showSwipePrompt`/`showUndoButton`/`background*`/`allowsLandscape`/`textSize`/`appearanceMode`/`notificationsEnabled`/`notificationIntervalHours` (registered default `showMicrophoneButton: true` at `AppViewModel.swift:165`). `pendingCompletionIdentifiers` watch-only with 300 s expiry (`PendingCompletionStore.swift:21-22`), not in reset list. Sync-payload keys (`SkippedReminderSyncService.swift:342-359`) are wire-only, not UserDefaults.
- **File-scope `EKEventStore` fixtures** force serialization within files: iOS `ReminderStoreTests.swift:1094`, `EventKitStoringTests.swift:536`, `ListContentTests.swift:5`, `ReminderDisplayTests.swift:6`, `PendingCompletionLogicTests.swift:5`, `ReminderStoreGateTests.swift:177`; watch `ShowCompletionGlowStateTests.swift:11`, `ReminderStoreWatchTests.swift:10`, `WatchReminderViewRegressionTests.swift:15`; production `InMemoryEventStore.sharedStore` (`InMemoryEventStore.swift:164`).
- **Serialized suites (all 20 iOS + 4 watch) and their shared state**: store-family suites on fixtures + timing (`ReminderStoreTests.swift:15,511,720,898`, `ReminderStoreGateTests.swift:11`, `EventKitStoringTests.swift:148,355,502`); real-`UserDefaults` suites (`EnableActionButtonsMigrationTests.swift:11`, `EnableActionButtonsSyncTests.swift:14`, `EntitlementSyncTests.swift:11`, `BackgroundCardTests.swift:43`, `CompletionCounterStoreTests.swift:5`, `UITestingSeedTests.swift:9`, `ListContentTests.swift:8`); timer suites (`CompletionGlowTests.swift:13,48` — auto-dismiss task `CompletionGlow.swift:32-46`); `SKTestSession` (one active per process — `EntitlementStoreTests.swift:8`); file-I/O (`BackgroundImageStoreTests.swift:8`); one-shot gate (`ResumptionGateTests.swift:12`). Watch: `ShowCompletionGlowStateTests.swift:27`, `ShowEnableActionButtonsStateTests.swift:12`, `WatchEnableActionButtonsSyncTests` (`WatchSyncPipelineTests.swift:526`), `ReminderStoreWatchTests.swift:26`.
- **Reset/isolation mechanisms**: `resetPersistedState()` via app on every `--seed` launch (`AppViewModel.swift:303`), the UI-test isolation primitive (UI tests never call it themselves); per-test `defer removeObject` on real `.standard`/App-Group keys (`MicrophoneToggleTests.swift:76-250`, `AppDelegateTests.swift:27-49`, `ActionButtonTests.swift:27-66`, many more); UUID-scoped keys (`SkippedReminderSyncServiceTests`, `WatchSyncPipelineTests`, `BoolPreferenceStoreTests.swift:14-44`); `removePersistentDomain` only at `BoolPreferenceStoreTests.swift:56`; `resetForTesting()` (`CompletionCounterStore.swift:48`). **No suite-level `setUp`/`tearDown` clearing defaults anywhere.**

Inherently sequential: one XCUIApplication per simulator, one shared `DerivedData`, `set -euo pipefail` abort-on-failure. CI instead shards the 5 iOS UI classes into 3 disjoint `-only-testing:` groups (`ci.yml:13-18`) with parallelism disabled and `-retry-tests-on-failure`.

## Cross-Cutting Observations
- **One mutation, many costs**: every complete/skip/delete/reschedule carries the 200 ms settle (`ReminderStore.swift:38-40,249-396`), and in UI tests this is paid with the production default since `AppViewModel.makeStore` never injects `settle:` — the same sleep the unit suites eliminate via `noopSettle`. Compounding: glow hold, 1 s minimum-display, and `waitForExistence` budgets stack per mutation-bearing test.
- **The in-memory EventKit trio is the backbone**: `InMemoryEventStore` (`.fullAccess`, request→true, scratch `EKEventStore`) + `loadsReminders:false` + `authorizationStatus:.fullAccess` init seed make every unit and UI seam `start()` short-circuit to `reload()` — the Reminders prompt simply cannot appear under any seam (Q5 S1-S11).
- **Sync/wire protocol is a shared-key lattice**: `SkippedReminderSyncService` reads/writes the same App-Group keys (`skipCounts`, `excludedListTitles`, show-* prefs, `enableActionButtons`, isEntitled) the UI seams seed and the reset list wipes; tests are isolated per direction with fakes (`FakeSession`/`WatchFakeSession`), while the **receive side** is exercised for real only by the watch live-exclusion UI test.
- **UI-parallelism asymmetry**: local `test.sh` parallelizes only iOS unit (`test.sh:234`); CI parallelizes nothing and documents EventKit SIGTRAP teardowns + clone-connection timeouts under clone contention (`ci.yml:68-77,136-146`). Watch UI is serialized by construction (one simulator, one launch per test).
- **Nothing measures itself**: no `measure(`/XCTMetric/`ContinuousClock` in any Swift file; no phase timing in `test.sh`; `count_tests.sh` counts tests but is grep-only and its inline comment literals are stale (`count_tests.sh:9,10,20,21,22`); local xcresult evidence exists only via the `coverage*` Makefile targets or manual `xcresulttool` runs.
