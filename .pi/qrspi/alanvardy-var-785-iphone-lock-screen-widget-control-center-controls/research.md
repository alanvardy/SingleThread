# Research Findings

Scope: `SingleThreadWidget/`, shared `SingleThreadCore/`, `SingleThread.xcodeproj/project.pbxproj`, and the test suites. Line numbers were grep-verified against the working tree during synthesis (the six fan-out reports used slightly stale widget-view line numbers; the authoritative numbers are from `grep -n` on `SingleThreadWidget/NextThingWidget.swift` and are used below).

## Q1: Widget provider & timeline flow

### Findings
- **Bundle registration**: `@main struct SingleThreadWidgetBundle: WidgetBundle` (`SingleThreadWidget/SingleThreadWidgetBundle.swift:5`), body returns a single widget `NextThingWidget()` (:7-8). Bundle is the `@main` entry of the `SingleThreadWidget` appex target (`project.pbxproj:339-360`), extension point `NSExtensionPointIdentifier = com.apple.widgetkit-extension` (`SingleThreadWidget/Info.plist:6-8`).
- **Widget declaration**: `struct NextThingWidget: Widget`, `let kind = "NextThing"` (`NextThingWidget.swift:113-114`), a **`StaticConfiguration`** (no intent-configuration support) with `.containerBackground(.fill.tertiary, for: .widget)` (:117-119), `.configurationDisplayName`/`.description` (:121-127), `.supportedFamilies([.systemSmall, .systemMedium, .systemLarge])` (:128).
- **Provider**: `NextThingProvider: TimelineProvider` (:27). `placeholder` (:30-38) and `getSnapshot` (:40-49) return synthetic `.reminder` entries ("Next thing" / "Buy groceries", all four show flags true). `getTimeline` (:51-59) runs `Task { let entry = await Self.makeEntry(); … }` and returns `Timeline(entries: [entry], policy: .after(Date().addingTimeInterval(15 * 60)))` — one entry per timeline, 15-minute self-reschedule (:53-55). This is the only timer in the widget.
- **`makeEntry`** (:61-108, `@MainActor private static`): reads the four show-flags via typed stores `ShowDatePreference()`/`ShowListPreference()`/`ShowRecurrencePreference()`/`ShowAlarmsPreference()` (:64-67, all default to `AppGroup.defaults`), then switches on `EKEventStore.authorizationStatus(for: .reminder)` (:68). `.fullAccess` → constructs a **fresh `ReminderStore(loadsReminders: true)`** (:70; defaults to a real `EKEventStore()`, `ReminderStore.swift:18-27`), sets `showsUndatedReminders` from a raw `AppGroup.defaults.bool(forKey: "showUndatedReminders")` (:71), `store.setSortOption(SortOptionStore().load())` (:72), `await store.reload()` (:73). `default:` (any non-fullAccess, including `.notDetermined`) → `.noAccess` (:98-108).
- **Entry state machine** `NextThingEntry.State` (`NextThingWidget.swift:10-15`): `noAccess` / `empty(Bool)` (hasHidden) / `allDone` / `reminder(ReminderDisplay)`. Build order in `makeEntry`: `.fullAccess` + `store.reminders.isEmpty` → `.empty(store.hasHidden)` (:74-80); else `guard let current = store.visibleReminders.first` else → `.allDone` (:81-88); else `.reminder(ReminderDisplay(reminder: current))` (:90-97). Note `.allDone` is reached when reminders exist but every one is skipped or excluded (visible set empty), *not* when nothing exists. `hasHidden` = reminders exist but are out of the date window (`ReminderStore.swift:62,159-161,377-395`).
- **Data flow**: the widget cannot see the app's in-memory `ReminderStore`; it rebuilds state from `EKEventStore` + App Group `UserDefaults` per materialization (:70-73). `visibleReminders` filters `skippedIDs` + `excludedListTitles` then sorts by `sortOption` (`ReminderStore.swift:129-135`). Display mapping via `ReminderDisplay` (`SingleThreadCore/Sources/SingleThreadCore/ReminderDisplay.swift:6-58`).
- **Reload triggers**: (1) `Timeline.policy .after(15m)` (:55); (2) `WidgetCenter.shared.reloadAllTimelines()` from the app — `store.onRemindersChanged` hook at `SingleThread/AppViewModel.swift:76-79`, and settings-preference hook at `SingleThread/SettingsViewModel.swift:15-22` (wired to show-date/recurrence/alarms toggles). No singular `reloadTimelines` call site. (3) AppIntents: tapped widget timeline reloads automatically after `perform()` returns (`ReminderIntents.swift:4-6` doc comment; system behavior of `Button(intent:)`). There is **no** scenePhase-driven widget reload — `ContentView.swift` scenePhase handling (`.onChange(of: scenePhase)` → `handleScenePhaseChange`, `SingleThread/ContentView.swift:210-211,573-589`) never calls `WidgetCenter`.

## Q2: Widget view layer

### Findings
- **Single view file**: all view/entry/provider code lives in `NextThingWidget.swift` (134 lines of view code); the bundle hosts exactly one widget. No other widget source files.
- **View hierarchy**: `NextThingWidgetView` (:134) → `body` is a `switch entry.state` (:141-162): `.noAccess` → `messageView` "Reminders Access" (`lock.shield`) + "Open SingleThread to enable access." (:142-147); `.empty(hasHidden)` → `messageView` "No Reminders" (`checklist`), message `nothingDueRightNow` vs `noRemindersYet` (:148-153); `.allDone` → `messageView` "All Done" (`checkmark.circle`), nil message (:154-157); `.reminder(display)` → `reminderView` (:158-160).
- **Family handling**: `supportedFamilies` only `.systemSmall/.systemMedium/.systemLarge` (:128). No `environment(\.widgetFamily)` branch anywhere — the view body is identical for every family; `.empty`/`.allDone`/`.noAccess` all collapse to `messageView` regardless of size. Accessory families are not referenced.
- **Container/environment**: only `.containerBackground(.fill.tertiary, for: .widget)` (:119). No `showsWidgetContainerBackground`, no `widgetRenderingMode`, no `.colorScheme`, no dynamicType handling.
- **`messageView`** (:188-205): VStack of decorative `Image(systemName:)` `.accessibilityHidden(true)`, `Text(title).font(.headline)` with `accessibilityIdentifier("emptyStateTitle")` (:197), optional `.caption2` message.
- **`reminderView`** (:208-249): VStack with optional `priorityMarker` Text (`"priorityMarker"` :215), `titleAttributed` headline (lineLimit 2), then rows gated on `entry.showsDate/showsList/showsRecurrence/showsAlarms` (due date `.style(.date)`, list name, `"recurrenceLabel"` :235, `"alertLabel"` :241, notes lineLimit 2), `Spacer` + `actionButtons`.
- **Interactive elements** (:166-184): the only interactive elements are two `Button(intent:)` — `CompleteReminderIntent()` tinted green, `accessibilityLabel(completeReminderAccessibility)`, id `"completeButton"` (:168-175); `SkipReminderIntent()` tinted orange, id `"skipButton"` (:177-184). No `.widgetURL` anywhere. Accessibility labels resolve to "Complete reminder"/"Skip reminder" (`LocalizedString+Shared.swift:24-30`).
- **Placeholder state**: `placeholder`/`getSnapshot` emit synthetic `.reminder` entries (gallery/preview positions), not the real empty state (NextThingWidget.swift:30-49).
- **Strings**: shared states use `SharedStrings` from Core (`LocalizedString+Shared.swift:12-73`); widget-only strings ("Next Thing", "Open SingleThread to enable access.", description) live in `SingleThreadWidget/Resources/Localizable.xcstrings` (referenced via `table: "Localizable", bundle: .main`).

## Q3: AppIntents end-to-end

### Findings
- **Location & conformance**: both intents live in `SingleThreadCore/Sources/SingleThreadCore/ReminderIntents.swift` (`import AppIntents` :1). `CompleteReminderIntent: AppIntent` (:7-25), `SkipReminderIntent: AppIntent` (:30-52). Neither conforms to `WidgetIntent`; neither declares `@Parameter` (input is implicit: the first visible reminder); no `AppShortcuts`/`@AssistantIntent`/`EntityQuery` anywhere in the repo.
- **Attribution**: registration is **implicit AppIntents discovery** plus SwiftUI `Button(intent:)`. No intent metadata: `StaticConfiguration` has no `supportingIntent` (`NextThingWidget.swift:117`); the widget `Info.plist` contains only `NSExtensionPointIdentifier = com.apple.widgetkit-extension` (`Info.plist:5-10`); app Info.plist is generated (`GENERATE_INFOPLIST_FILE = YES`, `project.pbxproj:751/:801`) with no intent keys. The intents compile into the appex because Core is a package dependency of the widget target (`project.pbxproj:355-357`) and are reached only via the two `Button(intent:)` call sites (`NextThingWidget.swift:168,177`).
- **`isDiscoverable = false`** (`ReminderIntents.swift:15,38`): keeps both out of Shortcuts/Siri; they are only usable from the widget UI.
- **`CompleteReminderIntent.perform()`** (:17-24, `@MainActor` on the method): fresh `ReminderStore(loadsReminders: true)` (:19) → `setSortOption(SortOptionStore().load())` (:20) → `await store.reload()` (:21) → `await store.completeCurrentReminder()` (:22) → `.result()` (:23). The returned Bool is ignored. `completeCurrentReminder` → `visibleReminders.first` → `completeReminder` (`ReminderStore.swift:227-231,236-268`): freemium-gated by `canMutate` (`isEntitled || completionCounter.count < EntitlementStore.freemiumCap(100)`, :150-152, `EntitlementStore.swift:57`), EventKit save + `completionCounter.increment()` (`CompletionCounterStore.swift:36-38`) + undo-store retain + 200 ms `settle()` + full `reload()`.
- **`SkipReminderIntent.perform()`** (:40-51): same store setup (:42-44), then `store.skipCurrentReminderImmediately()` (:49). This is the **synchronous** variant (`ReminderStore.swift:346-353`): freemium gate, `visibleReminders.first`, `applySkipSet` → `skipStore.save(...)` — a synchronous App Group `UserDefaults` write (`ReminderSkip.swift:135-138`) — then returns. No EventKit write, no settle, no reload, no counter/undo. Doc at `ReminderStore.swift:340-345`: the immediate variant exists for the widget intent "whose process WidgetKit may suspend right after `perform()` returns — the settle sleep used by the interactive path is unsafe there." The interactive app path `skipCurrentReminder()` (:279-288) defers the write behind a 200 ms settle in a `Task` with a generation gate (:491-498); the intent deliberately uses the immediate path. The intent-local comment (`ReminderIntents.swift:45-48`) explains skip routes through the store (not a direct UserDefaults write) so persistence + `onSkipSetChanged`/`onRemindersChanged` hooks take the same code path as complete.
- **Process-lifetime constraints**: intents run in the **widget extension process**; no static store instances — a fresh `ReminderStore` (fresh `EKEventStore`) per `perform()` (only static store is the test-only `InMemoryEventStore.sharedStore`, `InMemoryEventStore.swift:126`). Persistence across process lifetimes is the App Group suite (`AppGroup.swift:11,16-18`); keys touched: `skippedReminderIdentifiers`, `sortOption`, `completionCount`, plus excluded/pending via the suite. `ReminderStore` is `@MainActor` (`ReminderStore.swift:9`), hence `@MainActor` on both `perform()`s (the AppIntent protocol requires main-actor `perform`).
- **Tests pin configuration only**: `SingleThreadTests/ReminderIntentsTests.swift:11-19` (`completeIntentIsConfigured`) and :25-32 (`skipIntentIsConfigured`) assert `isDiscoverable == false` and that the title resolves via the `.main` catalog. `perform()` is never executed by any test.

## Q4: Cross-process state sharing

### Findings
- **Substrate**: `AppGroup.defaults = UserDefaults(suiteName: "group.app.alanvardy.SingleThread") ?? .standard` (`AppGroup.swift:11,16-18`) — suite on iPhone + widget; `.standard` fallback on watchOS and unregistered simulators/previews. All persisted keys default to `AppGroup.defaults` (watch explicitly injects `.standard`).
- **Store APIs (whole-value replace, never union)**: `SkippedReminderStore` (`ReminderSkip.swift:119-139`; key `"skippedReminderIdentifiers"` :123; `load` :131-132; `save` = `defaults.set` :135-138); `ExcludedListStore` (`ExcludedListStore.swift:4-22`; key `"excludedListTitles"`; `load` :15; `save` :19); `SortOptionStore` key `"sortOption"`, load falls back `.priority` (`SortOption.swift:14,21-36`); `CompletionCounterStore` key `"completionCount"` (`CompletionCounterStore.swift:10-13,36-38`). `ReminderStore` default-initializes all of them (`ReminderStore.swift:20-23`) and re-reads them in `reconcileSkipState` on every `reload()` (:557-569).

- **Widget vs app visibility**: widget performs its own immediate writes (skip via intents; completion counter); reads sort/excluded/show flags only. Out-of-process mutations become visible on the app's **next `reload()`** (reconcile re-reads `ReminderStore.swift:558-561`). A widget-originated skip does **not** trigger an immediate phone→watch push — the phone's `UserDefaults.didChangeNotification` observer diffs only the 5 show-* prefs (`AppViewModel.swift:366-395`); the watch gets it only when the phone later republishes.
- **`SkippedReminderSyncService`** (`SkippedReminderSyncService.swift:23`; compiled `#if os(iOS) || os(watchOS)` :22): one instance per process, wraps `WCSession` behind the `SkipSyncSession` seam (:8-17). Two channels: `updateApplicationContext` for state (latest-wins, auto-delivered on reconnect; `pushAll` :167-211 — one combined context: skips, exclusions, showUndated, sort, completionCount, gated show-* and isEntitled) and `sendMessage` for interactive Complete/Delete relays (:214-229). Receive side `apply(context:)` (:308-367) decodes each present key → persists → fires matching `on*Received` hook; values **replace** local state (documented :309-312). iPhone publishes gated show-* + isEntitled (`AppViewModel.swift:38-39`); watch omits them (`WatchAppViewModel.swift:159-160`). Phone push triggers: store hooks (:61-74), show-* App Group observer (:366-395), entitlement change (:344-356).
- **Non-persisted cross-process key**: `isEntitled` — in-memory `EntitlementStore` (phone) / `EntitlementState` (watch), crossed only via the wire payload (`SkippedReminderSyncService.swift:281,372`).

## Q5: Concurrency & build configuration

### Findings
- **`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`** is set **only on the two app targets**: SingleThread Debug/Release (`project.pbxproj:777/:827`) and SingleThreadWatch Debug/Release (:961/:989). **Not** on the widget target (:997-1055), nor on any test target, nor project-level (:617-729 — these set CLANG/GCC, `SWIFT_OPTIMIZATION_LEVEL`, `SWIFT_TREAT_WARNINGS_AS_ERRORS` only). `SWIFT_VERSION = 6.0` and `SWIFT_APPROACHABLE_CONCURRENCY = YES` appear in all 14 target-level blocks; `.swift-version` = `6.0` at repo root.
- **SingleThreadCore package**: `// swift-tools-version: 6.0` (`SingleThreadCore/Package.swift:1`), platforms iOS 18.7 / watchOS 26.5 / macOS 26.5 (:6-7). **No** `swiftLanguageModes`/`swiftSettings` — isolation is expressed purely in source annotations.
- **Explicit `@MainActor` in extension code**: widget `makeEntry` is `@MainActor` (`NextThingWidget.swift:61`); `TimelineProvider` methods are not isolated and call it inside a `Task` (:51-52). Both intent `perform()`s are `@MainActor` (`ReminderIntents.swift:17,40`). Core types annotated regardless of defaults: `ReminderStore` :9, `InMemoryEventStore` :12, `EntitlementStore`, `EntitlementState`, `CompletionGlow`, `UndoStore`, `EventKitStoring`; pure conversion enums are `nonisolated` (`ReminderDateFilter.swift:26`, `ReminderSort.swift:4`, `PendingCompletionLogic.swift:6`).
- **Factual comment drift**: `ReminderDateFilter.swift:13` claims the "watch/widget targets" both skip MainActor-default isolation, but the watch target **does** set it (pbxproj:961/:989); only the widget omits it.
- **Widget target wiring**: `productType = "com.apple.product-type.app-extension"` (`project.pbxproj:360`), output `SingleThreadWidget.appex` (:95, `wrapper.app-extension`). Embedded via the **Embed Foundation Extensions** `PBXCopyFilesBuildPhase` (:77-87; appex file entry `platformFilter=ios` :17) which is in the app target `buildPhases` (:249); app `dependencies` list the widget target with `platformFilter = ios` (:250-251). Synchronized root group for `SingleThreadWidget/` with a membership exception excluding `Info.plist` (:131-137, :101-106), `objectVersion = 77`.
- **Entitlements**: widget uses `CODE_SIGN_ENTITLEMENTS = SingleThread/AppGroup.entitlements` unconditionally (:1000/:1031 — `application-groups = [group.app.alanvardy.SingleThread]` only). App uses per-sdk entitlements: same AppGroup file on iphoneos/sim, `SingleThread.entitlements` (in-app-purchases, sandbox, audio-input, calendars) on mac (:740-742/:790-792), plus `REGISTER_APP_GROUPS = YES` app-only (:772/:822).
- **Platforms/deployment**: widget is **iOS-only** — `SUPPORTED_PLATFORMS = "iphoneos iphonesimulator"` (:1019/1048), `TARGETED_DEVICE_FAMILY = "1,2"` (:1024/1055), `IPHONEOS_DEPLOYMENT_TARGET = 18.7` (:1009/1040), `SKIP_INSTALL = YES`. App: `SUPPORTED_PLATFORMS = "iphoneos iphonesimulator macosx"`, iOS 18.7 (:765/:815), macOS 26.5. Watch: `SDKROOT = watchos`, watchOS 26.5, device family 4 (:964/:992). Widget carries `INFOPLIST_KEY_NSRemindersFullAccessUsageDescription` (:1008/:1039) — the extension process itself does EventKit saves for Complete.
- **Flag**: the widget process runs in the extension bundle id `app.alanvardy.SingleThread.widget` (:359 area).

## Cross-Cutting Observations
- **The widget is a stateless renderer of App Group + EventKit state.** Every materialization (makeEntry) and every intent `perform()` builds a fresh `ReminderStore`; all durable coordination is the App Group suite (`AppGroup.swift:11`). No in-memory object crosses process boundaries; hooks (`onRemindersChanged` etc.) exist only on the app-side store instance.
- **Two reload paths into the widget**: timeline policy refresh (15 min) and app `WidgetCenter.shared.reloadAllTimelines()` (store mutation `AppViewModel.swift:77`, settings change `SettingsViewModel.swift:22`). Post-intent reload is a system side effect.
- **Skipped-state writes are the only widget-originated mutation**; completion increments the freemium counter (shared budget with the app via `canMutate`, `ReminderStore.swift:150-152`). Skips go through the store's synchronous immediate path because WidgetKit may kill the extension process.
- **MainActor policy is asymmetric on purpose**: app/watch default to MainActor; widget + Core + tests use explicit annotations (`NextThingWidget.swift:61`, `ReminderIntents.swift:17,40`; `ReminderStore.swift:9`). One comment (`ReminderDateFilter.swift:13`) is stale about the watch.
- **Design conventions**: tiny single-file widget (bundle + provider + view ~300 lines), `StaticConfiguration` over `AppIntentConfiguration`, `isDiscoverable = false` for widget-only intents, `Button(intent:)` for interactivity, accessibility identifiers on every stateful element, no accessory/lock-screen families.
