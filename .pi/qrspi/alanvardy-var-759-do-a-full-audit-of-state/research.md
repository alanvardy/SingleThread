### Multiple-read-path summary (verified)
Keys with @AppStorage **plus** an independent raw read: `enableActionButtons`, `notificationsEnabled`, `notificationIntervalHours`, `allowsLandscape`, `appearanceMode`, and all 7 `show*` group keys (via their wrapper structs + AppViewModel lastShow cache + widget direct reads) plus `sortOption`/`showUndatedReminders`. Single-path keys: `textSize`, `showMicrophoneButton`, `backgroundEnabled/FadePercent/Pinned`, `showSwipePrompt`, `showUndoButton`.

### Namespace sharing when the group is unregistered
- `.standard` key set {1-12} and group key set {13-23} are **disjoint literals** — no duplicate name within one container; on watchOS/previews/fresh simulators all 23 land in the same `.standard` container because `AppGroup.defaults` resolves to it (`AppGroup.swift:10-14`).
- Watch **deliberately** pins seven stores to `.standard` even when the group exists: `ShowDateState.swift:20`, `ShowRecurrenceState.swift:20`, `ShowAlarmsState.swift:20`, `ShowListState.swift:20`, `ShowCompletionGlowState.swift:20`, `WatchAppViewModel.swift:155-161` (service), `:30-37` (launch restore). So on a group-registered watch, `showDate`/`showList`/`showRecurrence`/`showAlarms`/`showCompletionGlow`/`showUndatedReminders`/`sortOption`/`completionCount` exist in BOTH containers by different writers.
- `showCompletionGlow` straddles suites: iOS stores in group (`ContentView.swift:132`), the iOS reset seam removes from `.standard` (`AppViewModel.swift:247`).
- `isEntitled` appears in the reset list (`UITestingSeed.swift:74`) but is **never written** to either suite (StoreKit-derived — see Q3); `pendingCompletionIdentifiers` is omitted from the reset list (watch-only).

## Cross-Cutting Observations

- **Namespace-by-registration**: every Core store defaults to `AppGroup.defaults`, which is literally `.standard` whenever the entitlement is absent (`AppGroup.swift:10-14`). The watch pins several to `.standard` explicitly, so "App Group key X" and "standard key X" are the same storage on watchOS but different on iOS — the same logical value exists under one name across two containers depending on process (Q1, Q5).
- **Preference formatting is duplicated per key**: 6 × `Show*Preference` structs + `ShowUndatedRemindersPreference` + `CompletionCounterStore` + `SkippedReminderStore` + `ExcludedListStore` all follow the same `init(defaults: AppGroup.defaults, key:)` + load/save shape, each with hand-written missing-key fallbacks that differ per key (true/true/true/false/false/true/true, Q1/Q4). `SortOptionStore` is the canonical prototype (`ShowUndatedRemindersPreference.swift:2` mirrors it).
- **The entitlement + count gate is the single freemium edge**: `canMutate = isEntitled || count < 100` (strict `<`, no named constant) guards Complete/Undo/Delete/Skip at `ReminderStore.swift:189,238,263,315,346`; iOS bottom bar draws the unresolved-vs-gated-vs-actionable matrix at `ContentView.swift:615-645` (Q3).
- **Write paths are intentionally layered**: sheets → transient `SettingsBindings` bag → `.onChange` → `@AppStorage`; @AppStorage → `.onChange` → `handle…` → store; store → closure hooks → persistence + `pushAll()` + `WidgetCenter.reloadAllTimelines()`. Direct assignments at composition roots and service receive-side writes routinely skip layers (Q6).
- **Test seams reach real production keys**: `--seed`/`--ui-testing` write `enableActionButtons`/`completionCount`/`showCompletionGlow` to the real suites; exactly one seam (`--seed` count) writes a value outside the production counter domain (Q7).
- **Doc/impl drift observed**: `AppGroup.swift:2-4` doc lists only skipped IDs (suite carries 11 keys); `AppViewModel.swift:211` says production glow is 0.25 s, actual default 0.50 (`CompletionGlow.swift:26`).
