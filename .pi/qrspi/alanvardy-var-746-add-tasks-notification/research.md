# Research Findings

## Q1: How are local/OS notifications handled in this app today?

### Findings
- **There is no notification functionality of any kind.** Zero hits for `UNUserNotificationCenter`, `UNUserNotification`, `UNMutableNotificationContent`, trigger types, `addNotificationRequest`, `registerForRemoteNotifications`, or `WKApplicationDelegate` across `SingleThread/`, `SingleThreadWatch/`, `SingleThreadWidget/`, and `SingleThreadCore/` (verified by grep; all absent).
- The only `requestAuthorization` calls are speech recognition: `SingleThread/AuthorizationRequiring.swift:5,11,18,20`, `SingleThread/ReminderDictation.swift:13,41,45`, `SingleThread/DictationViewModel.swift:34`.
- The only `NotificationCenter` usage is `UserDefaults.didChangeNotification` observation in `SingleThread/AppViewModel.swift:221-227` — unrelated to OS notifications.
- `SingleThread/AppDelegate.swift` is the iOS `UIApplicationDelegate` (`:1-75`) but implements only orientation locking and appearance application — no `UNUserNotificationCenter.delegate` conformance, no notification delegate methods.
- **Entitlements**: `SingleThread/AppGroup.entitlements:1-8` (only `com.apple.security.application-groups`) and `SingleThread/SingleThread.entitlements` (macOS: app-sandbox, app group, audio-input, calendars). No `aps-environment` anywhere; grep of `project.pbxproj` for `aps`, `UIBackgroundModes`, `UserNotifications`, `SystemCapabilities` returns zero matches.
- **Framework linkage**: all `PBXFrameworksBuildPhase` blocks (`project.pbxproj:236-290`) link only the local `SingleThreadCore` library; `SingleThreadCore/Package.swift` (1-17) declares no external dependencies. No `UserNotifications.framework`.
- **Per target**: iOS app uses generated Info.plist (`GENERATE_INFOPLIST_FILE = YES`, `project.pbxproj:743`) with only `NSMicrophoneUsageDescription`, `NSRemindersUsageDescription`, `NSSpeechRecognitionUsageDescription` (`:744-746`). Watch (`:941-946, 969-974`) has only display-name + `NSRemindersFullAccessUsageDescription` + `WKCompanionAppBundleIdentifier`; no entitlements file at all. Widget (`project.pbxproj:996-1038`) Info.plist has only the `com.apple.widgetkit-extension` NSExtension dict (`SingleThreadWidget/Info.plist:1-11`).
- No `UIBackgroundModes` anywhere — irrelevant to local notifications but confirms no background capability is registered.

## Q3: What is the established pattern for adding a new user preference/setting?

### Findings
- **`@AppStorage` keys live in `ContentView`**, not `SingleThreadApp` (`SingleThread/ContentView.swift:151-198`). Two storage domains: `.standard` for display/UI prefs (appearanceMode, textSize, allowsLandscape, showMicrophoneButton, backgroundEnabled, backgroundFadePercent, enableActionButtons, showSwipePrompt); `AppGroup.defaults` for cross-target prefs (showUndatedReminders, sortOption, showDate, showList, showRecurrence, showAlarms, showCompletionGlow).
- **`SettingsBindings` snapshot bag**: `@MainActor @Observable final class SettingsBindings` (`SingleThread/SettingsBindings.swift:13-113`) holds all values as plain vars (`:68-99`), init mirrors `ContentView` defaults (`:20-47`). Created fresh per gear-tap via `makeSettingsBag()` (`ContentView.swift:534-571`), held in `@State settingsBag` (`:206-209`), nilled on sheet dismiss (`:101-107`). `excludedLists` deliberately excluded from the bag (store-backed, passed as `Binding<Set<String>>`, `SettingsBindings.swift:8-12`).
- **Write-back**: each bag property has a chained `.onChange(of: bag.X)` writing into the matching `@AppStorage` property (`ContentView.swift:118-138`); three gated `#if os(iOS)` (`allowsLandscape`, `enableActionButtons`, `showSwipePrompt`, `:123-127`). Main-view `.onChange` handlers react to app-facing `@AppStorage` props: `showUndatedReminders` → `viewModel.handleShowUndatedReminders` (`:91-92`), `sortOption` → `handleSortOption` (`:94-95`), `appearanceMode` → `handleAppearanceMode` (`:97-98`).
- **Settings UI**: `SettingsView` (`SingleThread/SettingsView.swift:26-92`) is a modal `NavigationStack { List }` with two Sections: preferences (Interface → `InterfaceSettingsView`, Reminder → `ReminderSettingsView`, Filtering & Sorting → `FilterSortSettingsView`, Background → `BackgroundSettingsView`, Purchase/Unlock → `PurchaseSettingsView`) and informational (Privacy, About). **Yes, there is a distinct interface settings area**: `InterfaceSettingsView.swift:10-63` (Appearance picker `:34-39`, Text Size picker `:40-45`, Allow landscape `:46-53`, Show microphone `:54-56`, Show action buttons `:57-60`, Show swipe prompt `:61-64`). Subviews take only the bindings they need ("rather than the full bag", `InterfaceSettingsView.swift:8-9`).
- **Core preference-store structs** (`SingleThreadCore/Sources/SingleThreadCore/`), both flavors:
  - `isEnabled`/`set(_:)` with absent-defaults via `object(forKey:) as? Bool ?? default`: `ShowDatePreference.swift:8-32` (absent→true), `ShowAlarmsPreference.swift:8-27`, `ShowRecurrencePreference.swift:8-27`, `ShowCompletionGlowPreference.swift:8-27`, `ShowListPreference.swift:9-28` (absent→false).
  - `load()/save(_:)`: `ShowUndatedRemindersPreference.swift:7-29`, `ExcludedListStore.swift:4-24` (`[String]`), `SortOptionStore` (`SortOption.swift:29-51`, key = `SortOption.defaultsKey` at `:18,27`).
  - All take `defaults: UserDefaults = AppGroup.defaults` plus a `key` init override seam for tests (`ShowDatePreference.swift:14-17`; watch constructs with `defaults: .standard`, e.g. `SingleThreadWatch/WatchAppViewModel.swift:145-151`).
  - Other stores: `CompletionCounterStore` (`count`, `increment()`, test-only `resetForTesting()`, `CompletionCounterStore.swift:8-36`); `EntitlementStore` is an in-memory `@MainActor @Observable` class over StoreKit 2 (`EntitlementStore.swift:14-93`, product `app.alanvardy.SingleThread.unlimited`).
- **Side effects**: widget reload via `SettingsViewModel.showPreferenceChanged()` → `WidgetCenter.shared.reloadAllTimelines()` (`SingleThread/SettingsViewModel.swift:19-23`), fired from `.onChange` on `showDate`/`showRecurrence`/`showAlarms` toggles (`ReminderSettingsView.swift:25-27, 35-37, 45-47`); plus `store.onRemindersChanged` hook (`SingleThread/AppViewModel.swift:74-76`). Orientation lock: `allowsLandscape` onChange → `SettingsViewModel.allowsLandscapeChanged` (`SettingsViewModel.swift:10-13`) → `AppDelegate.applyLock` (`AppDelegate.swift:31-45`). Appearance re-applied on active (`AppDelegate.swift:57-59`). Text size applied via `TextSizeModifier` at root (`ContentView.swift:99`) and in settings (`SettingsView.swift:144`).
- **Widget consumption**: `NextThingProvider.makeEntry()` reads the same store structs (`SingleThreadWidget/NextThingWidget.swift:64-72`); `showCompletionGlow` is *not* read by the widget.

## Q4: How does `ReminderStore` determine which reminders are incomplete and due?

### Findings
- **"Incomplete" is delegated to EventKit's predicate** `predicateForIncompleteReminders(withDueDateStarting:ending:calendars:)`, declared on `EventKitStoring` (`SingleThreadCore/Sources/SingleThreadCore/EventKitStoring.swift:16-20`), called in `reload()` at `ReminderStore.swift:301-304` (narrow) and `:315-318` (broad). Production conformance `EventKitStoring.swift:32-51`; test seam `InMemoryEventStore` mirrors `!isCompleted` (`InMemoryEventStore.swift:60`) and stubs the predicate always-true (`:49-54`).
- **Date windows** (`ReminderDateFilter.swift`): `endOfToday()` = startOfToday+1d−1s (`:28-38`); `overdueCutoff(days: 30)` = startOfToday−30d (`:41-49`, doc: "so the EventKit fetch stays bounded" — 30-day default used unconditionally); `isInCurrentWindow(_:)` → `nil` passes, else `overdueCutoff <= date <= endOfToday` (`:54-61`).
- **`reload()` pipeline** (`ReminderStore.swift:287-347`): guard `loadsReminders` (`:288`) → window selection (`:292-300`): `showsUndatedReminders == true` → broad `nil/nil` predicate; else narrow `[overdueCutoff(), endOfToday()]`. Narrow mode: `shown = fetched` unchanged (`:306-308`); the in-memory `isInCurrentWindow` re-filter applies only in broad mode. `hasHidden`: narrow mode issues a **second fully-broad fetch** (`:315-318`) and compares ID sets via `hasHiddenFor(shown:allIncomplete:)` by `calendarItemIdentifier` (`:133-138`); stored in `public private(set) var hasHidden` (`:50`). Skip/exclusion resolution (`:330-341`): `ReminderSkipLogic.resolve(fetched:shownIDs, skipped:skipStore.load())` (`ReminderSkip.swift:11-21`), prunes skip list, saves via `skipStore.save`; `excludedListTitles = Set(excludeStore.load())` (`:338`).
- **Visible list**: `visibleReminders` (`ReminderStore.swift:111-116`) filters `reminders` by `skippedIDs` / `excludedListTitles` and sorts via `ReminderSort.areInIncreasingOrder(...using: sortOption)` `:115`. `ReminderSort.swift:14-37`: `.priority` → priority rank → due date → title; `.dueDate` → due date → title; `.title` → title → due date. Default sort `.priority` (`ReminderStore.swift:58`). `allSkipped` = `!reminders.isEmpty && visibleReminders.isEmpty` (`:120-122`).
- **Consumers**: iOS `ContentView` renders `store.visibleReminders.first` (`SingleThread/ContentView.swift:238-247`); `allSkipped` → "All Done" (`:246-252`); `reminders.isEmpty` → empty state using `hasHidden` (`:253-283`). Watch mirrors this (`SingleThreadWatch/WatchReminderView.swift:67-83, 143-150`). Widget builds a fresh `ReminderStore(loadsReminders: true)` per entry (`SingleThreadWidget/NextThingWidget.swift:58-99`).
- **Data available at an arbitrary point** ("are there reminders the user still needs to complete?"): after `reload()`, `reminders` = all incomplete in-window reminders (≤30d overdue); `visibleReminders` additionally minus skipped/excluded; `hasHidden` = boolean existence of incomplete reminders outside the window. **Reminders outside the window are not retained** — future-dated, >30d overdue, and (when `showsUndatedReminders` is false) undated reminders exist only as the `hasHidden` boolean; their identities/dates are unavailable.
- **Fields read per reminder**: `title`, `notes`, `dueDateComponents?.date`, `isCompleted`, `calendarItemIdentifier`, `calendar?.title`, `priority`, `hasRecurrenceRules`, `hasAlarms` (snapshot projection in `ReminderDisplay.swift:9-20`). **`completionDate` and `flags` are never referenced anywhere** (grep: zero matches). `isCompleted` is written on iOS only in `completeReminder` (`ReminderStore.swift:177-178`). Completed reminders leave the fetched set entirely — historical completion state is not answerable.
- Async bridge: `fetchReminders(matching:)` wraps EventKit's completion handler in `withCheckedContinuation`, resumes on main actor via `resumeOnMainActor` (`ResumptionGate.swift:26-37`; gate `:8-24`).

## Cross-Cutting Observations
- **Two UserDefaults tiers everywhere**: (1) App Group suite for anything shared with the widget/watch (`AppGroup.defaults`), with silent `.standard` fallback; (2) `.standard` for iOS-only presentation prefs. The watch lives entirely on `.standard` — it has no App Group entitlement.
- **`UITestingSeed.persistedKeys` is the de-facto registry** of all persisted keys (17 user keys + `isEntitled`); any new persisted preference becomes an entry there.
- **The preference pattern is uniform**: Core store struct (defaults + key injectable) → `@AppStorage` in `ContentView` → `SettingsBindings` bag → settings subview `.onChange` write-backs → optional side-effect hook (widget reload, orientation lock, WCSession push via `AppViewModel`'s `didChangeNotification` diff).
- **The three targets read reminders independently**: iOS and watch via WCSession sync of skip/excluded/show-* state, widget purely via App Group suite; all three build their own `ReminderStore` and run the same `reload()` pipeline.
- **"Are there reminders to do?" is answered by `visibleReminders` + `hasHidden`** — the codebase has no retained notion of reminders outside the [today−30d, today] window other than the `hasHidden` boolean; completion history (`completionDate`) is entirely absent.
- **No notification infrastructure exists at all** — entitlement, capability, framework, delegate, or permission-request level — and no lifecycle timestamp is stored; both would be greenfield additions.
- Concurrency: `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` on app/watch targets (not Core); Core types annotate `@MainActor` explicitly where needed; UI tests only. `ResumptionGate` is the shared off-main→main resume pattern.

## Open Areas
- **Watch behavior on inactive/background** is entirely undocumented in code — there is no `WKExtensionDelegate`, so what the watch does when covered/completed cannot be traced beyond SwiftUI view lifecycle (`.task`, transitions in `WatchReminderView`).
- `UserDefaults(suiteName:) == nil` redirects App-Group keys into `.standard` with no logging; whether a given run used the group or the fallback is not observable in code.
- The `syncDefaultsObserver` token has no explicit invalidation; removal depends on token deallocation (documented in a comment, `AppViewModel.swift:220-224`).
- Widget-origin skip changes reach the watch only after a subsequent iOS mutation that fires a push hook; there is no cross-process refresh/daemon mechanism (flagged in `SkippedReminderSyncService` report).
- Whether EventKit's `predicateForIncompleteReminders` includes or excludes undated reminders is not documented in `EventKitStoring`; `InMemoryEventStore` stubs the predicate always-true and applies `isInCurrentWindow` filtering separately, so the fake's semantics don't pin down EventKit's.
- No claim is made about iOS lifecycle beyond `applicationDidBecomeActive`; the app relies on SwiftUI `.task` (not `onAppear`) for its launch-time load — a detail relevant if "on re-open" behavior is ever needed.
